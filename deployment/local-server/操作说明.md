# RPGmap V1.4.2 操作说明

本文只面向解压后实际运行 RPGmap 的 GM / Player。项目架构、开发说明和整体路线请看 GitHub 仓库根目录 `README.md`。

## 1. 发布包目录

```text
RPGmap-v1.4.2/
├─ app/                 程序前端，可随版本升级替换
├─ world/               当前这场游戏 / Campaign 的持久运行数据
│  ├─ state.json        运行后生成：World Snapshot / revision
│  ├─ users.json        有正式 User 后生成：身份 / Ownership / 凭证哈希
│  ├─ uploads/          World 上传资源
│  └─ backups/          本地备份
├─ maps/                真正的地图 / Scene 资源库
├─ docs/                补充说明
├─ server.mjs
├─ access-control.mjs
├─ portable-storage.mjs
├─ internet-launcher.mjs
├─ start-rpgmap.bat
├─ start-rpgmap-internet.bat
└─ VERSION.json
```

三条原则：

- `app/` = RPGmap 程序。
- `world/` = 这一场游戏发生了什么。
- `maps/` = 地图 / Scene 本身是什么。

例如，可破坏建筑的模型、碰撞、破坏阶段模板属于 `maps/`；某次跑团里建筑当前 HP、是否燃烧、是否已经坍塌属于 `world/state.json`。

## 2. 本机 / 局域网启动

Windows 双击：

```text
start-rpgmap.bat
```

默认本机地址：

```text
http://127.0.0.1:30000
```

同一 Wi-Fi / LAN 的其他设备使用启动窗口显示的 Network 地址。

Linux / macOS：

```text
./start-rpgmap.sh
```

## 3. Windows 公网联机

双击：

```text
start-rpgmap-internet.bat
```

启动器会：

1. 检测 / 安装 `cloudflared`。
2. 创建 Cloudflare Quick Tunnel。
3. 生成 Join Code 与 GM Secret。
4. 启动 RPGmap Server。
5. 自动打开公网地址。
6. 打开独立 Multiplayer Info 信息窗口。

普通新玩家只需要收到：

```text
Public URL + Join Code
```

GM Secret 只供 GM 使用。

## 4. Player User 创建

推荐流程：

1. Player 选择 `Player`，填写名称和 Join Code。
2. 第一次加入后进入“等待 GM 批准”。
3. GM 点击顶栏“联机 / Users”。
4. GM 在待批准列表中设置正式 User 名称和默认角色。
5. 点击“批准并绑定”。
6. Server 创建持久 User，默认角色获得 OWNER。
7. Player 保存第一次获得的 Player Key。

GM 也可以提前在联机面板“预创建 Player User”，再把 Player Key 私下发给指定玩家。

## 5. Player Key

Quick Tunnel 重启后公网域名通常会变化，浏览器 localStorage 不能跨域共享，所以 RPGmap 同时使用：

- Browser Auth Token：同一网址刷新 / 重连时自动使用。
- Player Key：新的 Quick Tunnel 地址上恢复同一个 User。

已有 User 在新公网地址登录时填写：

```text
当前 Join Code + 自己的 Player Key
```

Server 只保存凭证哈希，不保存明文 Player Key / Token。

GM “重发 Player Key”后，旧 Player Key 与旧浏览器身份都会失效。

## 6. Actor Ownership

权限：

- `NONE`：无控制权。
- `OBSERVER`：观察 / 查看，不允许修改 Actor。
- `OWNER`：可操控 Actor。

每个 Player 可有一个默认角色，也可以同时拥有多个 OWNER / OBSERVER Actor。默认角色必须是 OWNER。

GM 对全部 Actor 隐式拥有完整权限。

## 7. Player 操作权限

战斗外，Player 可以正常操控自己的 OWNER Actor，例如移动 Token、修改角色资源 / 状态、切换 Form、聊天和测距。

Player 不能：

- 创建 / 删除 / 重绑 Actor 或 Token；
- 修改非 OWNER Actor；
- 修改 Combatant、先攻、排序、Round 或 Turn；
- 开始 / 结束战斗；
- 删除或改写已有 Chat / Game Log。

客户端会先做权限预检，Server 再做最终强制校验。

## 8. Combat Turn Lock

Combat active 后，Player 即使拥有多个 OWNER Actor，也只能操控当前 Turn 对应的那个 Actor。

GM 始终可以操作所有 Actor，并负责：

- 加入 / 移出 Combatant；
- Initiative；
- 先攻排序；
- 开始 / 结束 Combat；
- Round / Turn 推进。

Player 可以查看 Combat Tracker，但管理控件为只读。

## 9. world/ 与 maps/ 的区别

### `world/`

保存当前 Campaign 的运行状态：

- User / Ownership；
- Actor / Token；
- Chat / Game Log；
- Combat；
- 当前地图；
- 地图实例的破坏 / 燃烧 / 事件状态；
- 上传资源和备份。

### `maps/`

作为真正的 Map / Scene 资源库，后续可包含：

```text
maps/
├─ lanzhou/
├─ inn-01/
├─ dungeon-01/
└─ battlefield-01/
```

每个地图包以后可继续扩展：背景层、建筑、墙体、可破坏对象、碰撞 / 导航、环境特效、损坏 / 摧毁变体等。

V1.4.2 主要完成目录边界和迁移基础，真正的多地图切换 / 可破坏建筑系统在后续版本继续实现。

## 10. 备份和升级

最重要的备份对象是：

```text
world/
```

地图资源需要一并备份时，再同时备份：

```text
maps/
```

升级 RPGmap 程序时，原则上可以替换 `app/` 和根目录程序文件，不要覆盖自己的 `world/` 和 `maps/`。

RPGmap 默认不会把 World / User 持久数据写入 AppData、用户主目录或其他隐藏目录。

## 11. 旧版本自动迁移

V1.4.2 新文件不存在时，会按优先级自动迁移：

```text
V1.4.1
map/world.json  -> world/state.json
map/users.json  -> world/users.json

更旧版本
data/worlds/default/world.json  -> world/state.json
data/worlds/default/access.json -> world/users.json
```

`uploads/` 和 `backups/` 也会迁移到 `world/`。旧文件不会删除。

## 12. 常用操作

- Token 单选：左键
- 框选：空白地图左拖
- Shift：追加选择
- Alt：移除选择
- Token 移动：直接拖动
- Waypoint：Ctrl/Cmd + 点击或 `F`
- Enter：确认移动
- Esc：取消
- Ruler：`R`
- 从角色测距：`Shift + R`
- 切换 Form：`V`

Player 模式下，与 Actor 有关的操作会受到 Ownership / Combat Turn Lock 约束。
