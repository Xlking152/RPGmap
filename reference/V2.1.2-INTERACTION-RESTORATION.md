# RPGmap v2.1.2 Interaction Restoration

## 目标

v2.1.2 的目标不是回滚到 v1.6.3，而是在保留 V2 World / Scene Token / Ruleset 架构的前提下，恢复 v1.6.3 已经验证过的地图操作体验。

核心原则：**V2 的数据结构和服务器权威逻辑保持不变，只恢复地图交互层。**

## 结构审计结论

本次从 v2.1.1 到交互修复合并提交的变更，没有修改以下 V2 核心边界：

- `src/world/model.js`、`src/world/system.js`、`src/world/operations.js`；
- World schema 2 与 operation schema 1；
- Actor / Token 持久化模型与 Ruleset Contract；
- Local/LAN 服务器权威提交、revision、operation ID 与权限验证；
- SaveV2 迁移边界；
- Scene Token 作为地图角色唯一运行时实体的原则。

因此 v2.1.2 仍然是 V2 架构，不恢复旧 Character Runtime，也不重新引入 `state.characters`、`characterId`、Character pane 或 Character movement API。

## 修改过程

### 1. Token 移动交互

问题：v2.1.1 的 Token-only controller 将 v1.6.3 的持续拖拽规划简化为 pointerup 后一次规划，导致实时路线、拐点规划与滚轮吸附等交互消失。

处理：

- 新增 `src/movement/controller-v3.js` 作为 V2 Token Runtime 的交互控制器；
- 拖动过程中按 70 ms 节流实时计算路径预览；
- 恢复 Ctrl/Cmd 拐点规划、F 添加拐点、Alt+F / 右键移除拐点、滚轮切换吸附；
- 路径受阻继续显示红色失败段与阻挡位置；
- 最终移动不直接修改状态，而是继续调用现有 `api.movement.planTokenMove()` / `commitTokenMove()`；
- 多段路线逐段等待 `token:move` / `token:move-cancelled`，保持服务器权威结果为最终结果。

为了支持任意拐点段的预览，新增 `src/movement/route-inspector.js`，但它只负责只读导航查询，不拥有第二套 World 或 Token 状态。

### 2. 范围攻击拖拽手柄

问题：V2 Scene Area 保存和数值编辑仍存在，但 v1.6.3 的地图拖拽手柄在重构中被遗漏。

处理：

- 新增 `src/scene/area-handle-geometry.js`，纯函数计算圆形、扇形和矩形的手柄位置及拖拽后的几何参数；
- 新增 `src/scene/area-handles.js`，恢复起点、半径、方向、角度、宽度等 Leaflet draggable handles；
- drag 过程中只做本地几何预览；
- dragend 后才通过 `api.commitState(..., { source: 'scene-area:drag' })` 写回 V2 World，避免拖动过程持续产生 World 写入；
- Token / Marker anchor 仍使用现有 V2 anchor 语义，拖动起点时才明确切换为 free anchor。

### 3. Token 名字与血条布局

问题：V2 Token 名称和 HP bar 都位于 Token 下方，尺寸变化后容易发生重叠。

处理：

- Token 名称改为固定显示在 Token 上方；
- 名称偏移根据实时 Token render size 动态计算；
- HP bar 保持 V2 原有的 Token 下方布局；
- 不改变 Health 数据来源、伤势规则或 Actor/Token 状态模型。

最终布局恢复为：名称 → Token → HP bar。

### 4. 地物 / 建筑检查

问题：V2 Core 中仍保留 Feature 检查和详情 UI，但地图点击入口仍依赖旧 `[data-tool].active` DOM 协议；V2 AppShell 已改为 `data-main-tool` 和 Runtime tool state，导致普通点击建筑无法打开建筑详情。

处理：

- 新增 `src/interaction/map-inspector.js`；
- 直接读取 `api.getTool()`，而不是依赖具体 UI DOM；
- `pan` 与 `inspect` 两种模式都允许直接点击 inspectable Feature；
- 点击后继续调用现有 `api.selectFeature()`，由现有 Feature Interaction System 渲染类别、类型、用途、构造、说明、入口、内部 Token 与操作按钮；
- 当前 Feature 增加地图高亮；
- 不改变 Feature State、Capability、Scene featureStates 或操作权限模型。

### 5. 门的直接开关

审计发现 V2 已经存在 `FeatureControlLayer`，openable Feature 会直接在地图上生成开关控件，并调用统一 `api.interaction.execute(open/close)`。

因此本次没有重新实现第二套门状态逻辑，只保留并验证现有直接开关入口。门的 open/close 状态仍由 V2 Feature State / Scene 权威数据维护。

## V2 架构保护

`tests/legacy-runtime-retirement.test.js` 在 v2.1.2 中扩展覆盖以下新交互文件：

- `src/movement/controller-v3.js`
- `src/movement/route-inspector.js`
- `src/interaction/map-inspector.js`
- `src/scene/area-handle-geometry.js`
- `src/scene/area-handles.js`

这些文件现在和其他 V2 Runtime 文件一样，被 CI 明确禁止出现：

- `state.characters`
- `characterId`
- Character create/move/delete/select events
- `selectCharacter` / `placeCharacter` / `repositionCharacter` 等旧 API
- `characterPane`

服务器侧仍继续拒绝任何 Character 字段进入 World V2。

v2.1.2 仅提升应用发行版本。以下兼容边界保持不变：

- World schema: `2`
- operation schema: `1`
