# RPGmap v2.1.3 UI / AoE Fixes

## 目标

v2.1.3 是 v2.1.2 的回归修复版本。它不调整 World V2、Scene Token、Ruleset 或服务器权限架构，只修复三个实际操作问题：

1. Local/LAN 聊天发送后，发送者自己的对话面板没有显示新消息；
2. “选择”已经可以检查地物，但顶部仍保留一个重复的“检查地物”工具；
3. 范围绑定 Scene Token 作为起点后，范围可以显示，但“预览影响 / 应用破坏”无法正常完成。

核心原则仍然是：**保持 V2 权威数据模型不变，在交互和适配边界修复回归。**

## 1. 聊天发送者看不到自己的消息

### 原因

Local/LAN 聊天不是客户端先改本地 World 再提交，而是服务器处理 `chat.append` 后修改共享聊天记录并广播新的 `world.snapshot`。

多人客户端原本有一条重要优化：如果收到的 World snapshot 的 `originSessionId` 等于自己，就认为这是“自己已经在本地应用过的 World 修改”，只推进 revision，不再重复 import 整个 World。这对 Token、Actor、Combat 等客户端先行的普通 World 修改是正确的。

但聊天属于 **server-only write**：发送者在服务器确认前并没有把消息写入本地 World。因此发送者同样跳过自己的 `chat.append` snapshot 时，会出现：

- WebSocket 实际已经发送成功；
- 服务器 World 已经保存消息；
- 其他客户端可以看到；
- 发送者自己的聊天列表却没有更新，看起来像“输入没有反应”。

### 修复

`src/multiplayer/controller.js` 新增一个严格白名单策略：

```js
shouldApplyOwnServerSnapshot(message)
```

只有：

- `chat.append`
- `chat.clear`

这两类服务器独占写入，即使 `originSessionId` 是当前 Session，也重新通过现有 `applyRemoteState()` 导入服务器快照。

普通 `client-state`、World operation、Token/Actor 等自己的 World 修改仍保持原来的“避免重复 import”策略，没有改变网络 operation 模型。

聊天输入框同时增加可见反馈：

- WebSocket 接受发送后才清空输入；
- 清空后立即重新 focus；
- 显示“消息已发送 · 等待服务器同步”；
- 若连接不可用，保留原输入并提示失败。

这不是本地伪造聊天消息；最终聊天列表仍以服务器 World 为权威。

## 2. “选择”与“检查地物”合并

v2.1.2 的 `MapInspector` 已允许在 `pan`（选择/浏览）和 `inspect` 两种 Runtime tool state 下点击 inspectable Feature：

```text
地图点击
  ↓
MapInspector
  ↓
Feature hit test
  ↓
api.selectFeature(featureId, { switchTab: true })
  ↓
现有 Feature Interaction UI
```

因此顶部再保留“检查地物”按钮只是重复入口。

v2.1.3 在 `src/ui/app-shell-v2.js` 中删除可见的“检查地物”按钮，顶部保留：

- 选择
- 范围
- 图层

“选择”模式现在同时承担：

- Token 单选/多选；
- 直接点击建筑、城墙、城门、桥梁等 Feature 打开详情；
- 直接使用地图上的门/Feature 控件。

内部 `inspect` Runtime 状态没有被硬删除，仍保留兼容性；只是默认 AppShell 不再暴露重复 UI。

Feature State、Capability、Feature Interaction、门的 open/close 权限逻辑均未改变。

## 3. Token 起点范围无法预览/应用

### V2 中的正确数据

Scene 中的实时范围可以保存：

```js
anchor: { type: 'token', tokenId: '...' }
```

这是 V2 的 canonical Scene Token anchor。`runtime-state.js` 会通过 `canonicalAttackAreas()` 接受并规范化这种结构，所以**持久化本身没有问题**。

### 实际故障点

`src/scene/areas.js` 在显示范围时会解析 Token 当前坐标：

```text
Token anchor
  ↓
resolvedOrigin()
  ↓
当前 x / y
```

但 v2.1.2 在调用旧的场景破坏几何函数 `createDamagePreview()` 时，只替换了 `origin`，仍把 `anchor: { type: 'token' }` 一起传入。

`src/engine/state.js` 的旧 SaveV2 几何 normalizer 仍只认识历史格式：

- free
- marker
- character（仅旧迁移/兼容）

因此 Token anchor 在“预览影响 / 应用破坏”的几何快照边界被拒绝。

### 修复方式

v2.1.3 不让旧几何模块成为第二个 Scene Token 权威，也不把 Character Runtime 加回来。

`resolvedArea()` 现在明确生成一次性几何快照：

```js
{
  ...liveArea,
  origin: resolvedOrigin(liveArea),
  anchor: { type: 'free', markerId: null },
}
```

含义是：

- **实时 Scene 数据**仍保存 Token anchor；
- **地图显示**使用 Token 当前坐标；
- **预览计算**使用应用这一刻已经解析出的坐标；
- **历史 damage event**保存固定位置，不会在角色之后移动时跟着漂移。

同时修复绑定对象切换时的 fallback origin：以前选择新 Token 后使用旧 anchor 解析 origin；现在使用 `{ ...area, anchor: newAnchor }` 立即解析新绑定对象的位置。

## 4. 为什么不直接扩展旧 `engine/state.js` 为 Token anchor

`engine/state.js` 仍承担 SaveV1/SaveV2 历史几何、damage event 和兼容迁移职责。如果把实时 Scene Token 查询继续向这个层下沉，会让旧兼容模块重新依赖现代 Token Runtime。

v2.1.3 选择在 `Scene Area UI/Runtime Adapter → Geometry Snapshot` 边界完成解析，有三个好处：

1. Scene Token 仍只有一个权威来源；
2. 旧 damage 几何函数继续保持纯数据计算；
3. 历史攻击天然固定在释放瞬间的位置，不跟随 Token。

## 5. 自动化保护

v2.1.3 新增/扩展测试覆盖：

### Multiplayer

`tests/architecture-blockers.test.js` 验证：

- `chat.append` 自己发出的 snapshot 必须回灌；
- `chat.clear` 自己发出的 snapshot 必须回灌；
- `client-state` / `world.operation` 仍不得因此改成重复导入自己的普通 World 修改。

### UI / Chat / AoE

`tests/v2.1.3-regressions.test.js` 验证：

- AppShell 不再创建“检查地物”按钮；
- MapInspector 在 `pan` 下仍能 `selectFeature()`；
- 聊天只在 transport 接受后清空输入，并重新 focus；
- Token anchor 仍存在于 Scene Area 编辑逻辑；
- preview/apply 使用解析后的 free geometry snapshot；
- 绑定新 Token 时使用新 anchor 解析 fallback origin。

原有 Character Runtime retirement、World V2、Token、Feature State、权限、Combat 与服务器操作测试继续运行。

## 6. V2 架构边界

v2.1.3 没有改变：

- World schema：`2`
- operation schema：`1`
- Infinite Horror Ruleset：`1.0.0`
- Lanzhou MapPackage 数据版本：`1.0.5`
- Scene Token 作为地图角色唯一 Runtime 实体
- `actorDelta` / Synthetic Actor 语义
- Local/LAN 服务器 revision、operation ID、权限与写盘权威
- Feature State / Capability 模型
- SaveV2 迁移边界

没有新增 `state.characters`、`characterId` 或 Character movement API。

因此 v2.0 / v2.1.x World 升级到 v2.1.3 不需要新的数据迁移。
