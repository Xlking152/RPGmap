# RPGmap v2.1.4 Movement Visuals

## 1. 目标

v2.1.4 处理两个纯交互/展示层问题：

1. Token 已经拥有 v1.6.3 风格的直接拖动和 waypoint 规划，但确认移动后地图上的 Token 仍会在 World 更新时直接跳到终点，缺少可见移动过程。
2. Token 高度是独立图标标签，和 Token 下方的 Health bar 进入同一视觉区域时容易重叠；高度更适合与名称组成同一顶部标签。

本次修改遵循既有原则：**V2 的数据架构留下，v1.6.3 的地图交互观感拿回来。**

## 2. 架构边界没有改变

v2.1.4 不修改以下持久化/权威边界：

- World schema：`2`
- operation schema：`1`
- Infinite Horror Ruleset：`1.0.0`
- Lanzhou MapPackage：`1.0.5`
- Scene Token 仍是地图角色唯一 Runtime 实体
- Actor / Token / Scene / Feature State 的持久化结构不变
- Local/LAN 的 revision、operation ID、ownership、turn lock 和服务器写盘权威不变
- 不恢复 `state.characters`、`characterId`、Character pane 或 Character movement API

视觉动画不会提交任何中间坐标。

## 3. 问题一：确认移动后像瞬移

### 3.1 根因

v2.1.2 已恢复 `controller-v3.js` 的直接 Token 拖动、实时路线和 waypoint 操作，但 V2 Token Renderer 在状态变化后仍直接执行最终坐标的 `setLatLng()`。

因此逻辑上移动完全正确：

```text
规划路线
→ 权限/碰撞校验
→ 服务器或离线 World 提交最终 Token 坐标
→ Renderer 读到新坐标
→ Marker 直接跳到终点
```

缺少的是**提交后的视觉插值**。

同时，v1.6.3 的 Movement Ghost Renderer 没有进入 V2 Runtime。虽然 V2 路线仍会画线和终点圆点，但拖动时缺少一个明确的“Token 将到这里”的视觉对象。

### 3.2 恢复 V2 Token 终点预览

新增：

- `src/movement/ghost-renderer-v2.js`

它复用现有的 V2 纯描述器：

- `src/movement/ghost.js`
- `createTokenGhostDescriptor()`
- `isMovementEndpointLayer()`

行为：

- 读取 `api.selection` 的 Scene Token；
- 通过 `api.tokens.resolveActor()` 得到当前 V2 Actor 展示；
- 监听 Movement Controller 在 `measurePane` 创建的终点 layer；
- 在终点绘制半透明 Token ghost；
- 正常路线使用蓝绿色虚线光环；
- 受阻路线使用红色预览；
- 路线重新计算时 ghost 跟随新终点；
- 路线取消/提交后自动隐藏。

这个实现没有旧 Character Runtime 依赖，旧 `src/movement/ghost-renderer.js` 仍然保持物理删除状态。

### 3.3 权威提交后的平滑移动

新增：

- `src/render/token-motion.js`

它只提供纯渲染几何：

- 坐标规范化；
- 坐标相等判断；
- 两点线性插值；
- 按移动距离计算可见但有上限的动画时长。

默认时长为：

```text
min 180 ms
35 ms / map meter
max 900 ms
```

`src/render/token-layer.js` 现在把两个概念分开：

```text
canonical point = Scene Token / World 中已经确认的坐标
visual point    = 当前浏览器正在显示的坐标
```

当 canonical point 改变时：

1. World 已经先完成正常提交；
2. Renderer 保留旧 visual point；
3. `requestAnimationFrame` 在旧 visual point 与新 canonical point 之间插值；
4. 动画结束后 visual point 与 canonical point 完全一致。

Renderer 不调用：

- `api.world.commit()`
- `api.commitState()`
- Token movement operation

所以碰撞、权限、战斗回合、多人 revision 均只看已经确认的 V2 World。

### 3.4 多 waypoint 不跳段

多人服务器可能比本地动画更快连续确认多个 waypoint。v2.1.4 不用“重新瞄准最终点”的方式打断当前动画，而是为每个 Token 保存视觉目标队列：

```text
start
→ waypoint A
→ waypoint B
→ final target
```

即使 A/B/final 的权威状态已经快速进入客户端，Renderer 仍按收到的坐标顺序完成各段动画，因此不会视觉上绕过 waypoint。

### 3.5 独立覆盖层

Health bar 和状态徽章拥有独立 Leaflet layer。如果它们继续直接读取 canonical point，会在 Token 动画尚未结束时先跳到终点。

因此 v2.1.4 使用明确的视觉移动事件：

- `token:visual-move-start`
- `token:visual-move-end`

移动期间：

- Token 本体、名称和高度跟随正在动画的 Marker；
- Health bar 暂时隐藏；
- 机械状态徽章暂时隐藏；
- 动画结束后两者在最终权威位置重新渲染。

这避免建立第二套状态坐标或让 Health/Status 系统参与移动权威。

### 3.6 Reduced Motion

如果浏览器/操作系统启用了 `prefers-reduced-motion: reduce`：

- 路线和 Token ghost 仍可用；
- Renderer 不执行位置平滑插值；
- Token 直接显示在权威位置。

这是无障碍行为，不影响 World 数据。

## 4. 问题二：高度与血条重叠

### 4.1 原布局

v2.1.3：

```text
名称
Token + 独立高度标签
Health bar
```

独立高度标签属于 Token icon HTML，而 Health bar 是单独的 Leaflet layer。不同 Token 尺寸/缩放下，两者可能进入同一视觉区域。

### 4.2 v2.1.4 布局

高度不再作为 Token icon 周边的独立标签，而是进入永久名称 tooltip：

```text
[10 ft] 角色名称
      Token
    Health bar
```

代码保证 tooltip DOM 顺序为：

```js
row.append(elevation, name)
```

因此高度固定在名称左侧。

HealthSystem 仍是 Token HP bar 的唯一 owner，血条位置仍保持 Token 下方，Health 数据模型没有任何变化。

## 6. 升级兼容性

v2.1.4 是 UI / Renderer / Movement preview 修复版本，没有数据迁移。

从 v2.0.x、v2.1.0–v2.1.3 升级时仍按普通升级方式：

1. 关闭旧 Server；
2. 备份旧发布目录的整个 `map/`；
3. 解压 v2.1.4；
4. 将旧 `map/` 完整复制到新包；
5. 启动 `start-rpgmap.bat`。
