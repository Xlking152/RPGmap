# RPGmap 开发说明

本文只保留当前仍有效的开发约定，避免与 README 和工作日志重复。

当前应用版本：**1.2.0**

## 1. 技术栈

- JavaScript / ES Modules
- Vite 8
- Leaflet 1.9.4
- EasyStar.js 0.4.4
- polygon-clipping 0.15.7
- Lucide 1.30.0
- Node.js `^20.19.0 || >=22.12.0`
- Node 内置 `node:test`

## 2. 目录职责

```text
src/
├─ app/           持久化与应用辅助
├─ engine/        地图核心、几何、导航、场景状态与兼容层
├─ entities/      Actor / Token / Form / Runtime / Effects / XLSX
├─ maps/          独立 MapPackage
├─ movement/      Token MovementSystem
├─ render/        场景和地图表现
└─ ui/            AppShell UI

tests/            自动化测试
deployment/       本地服务器与发布设施
文档/             工作日志、未来规划、开发说明
```

当前 `src/maps/lanzhou.js` 是第一张地图包和测试地图，不是 RPGmap 本身。新增地图应优先增加独立 MapPackage，而不是复制整套应用逻辑。

## 3. 系统边界

### EntitySystem

`Actor` 负责“这个角色是谁”：

- identity / avatar
- Forms
- resources
- attributes
- checks
- Base / Runtime / Effects

`Token` 负责“这个角色在当前场景中是什么状态”：

- actorId
- map location
- selection
- hidden / locked
- rotation / size 等后续场景属性

### MovementSystem

MovementSystem 只处理 Token 的地图移动行为：

- drag planning
- waypoint
- A*
- snap
- route distance
- Ghost preview

复杂速度、行动点和规则系统暂不写死在 MovementSystem 中。

### AppShell UI

UI 负责组织系统入口，不应复制 Entity / Movement / Scene 的业务状态机。新增 UI 行为优先调用已有系统 API。

## 4. MapPackage 原则

地图内容与通用引擎分离。MapPackage 至少应提供：

```js
{
  id,
  title,
  version,
  width,
  height,
  metersPerUnit,
  initialView,
  features,
  createSvg()
}
```

可按地图需要增加：

- navigation
- roadBuffers
- destructibleCategories
- liquidBodies
- floodRules
- artAssets

地图坐标约定保持：左上角原点，X 向右，Y 向下。

## 5. Actor XLSX 导入

当前 `character-sheet-v1` 只允许读取：

- `角色概览`
- `具体数值表`

不得为了计算结果去读取：

- `购买清单`
- `特性与技能`
- `计算器`

导入器只使用工作簿中已经保存的最终缓存值，不实现 Excel 公式引擎。Excel 单元格地址必须封装在 importer / template 内，不应泄露进 Actor model 或 UI。

## 6. 数据分层

角色基础值与跑团运行状态必须分开：

```text
Imported / Base
      ↓
Current Form
      ↓
Runtime
      ↓
Effects
      ↓
Resolved Value
```

重新导入角色卡时，不应无条件覆盖当前 HP、精力、意志、自定义资源和临时效果。

## 7. 开发流程

```bash
npm ci
npm test
npm run dev
```

生产构建：

```bash
npm run build
```

修改功能时：

1. 优先修改对应子系统，不继续扩大 `src/engine/app.js`。
2. 为可独立验证的底层逻辑补充 `node:test`。
3. 不提交 `node_modules/`、`dist/`、测试缓存或本地运行垃圾。
4. 不提交用户真实角色卡作为测试 fixture；使用最小合成数据。
5. 发布包必须从干净依赖环境重新构建。

## 8. 版本约定

应用版本使用 `MAJOR.MINOR.PATCH`。

- Bug 修复建议 Patch。
- 完整功能 / 子系统建议 Minor。
- 不兼容存档、World 数据或服务器协议建议 Major。

版本号变化不是开发者单方面自动决定：达到新的版本节点时，先提出建议版本及理由，经确认后再修改 `package.json`、页面版本信息和 `文档/工作日志.md`。

GitHub Release 使用 `vX.Y.Z`，例如 `v1.2.0`。

## 9. Server 演进原则

当前 `deployment/local-server/` 只负责本地 / 局域网 HTTP 测试。正式服务器化按 `文档/未来规划.md` 推进：

```text
Static Server
  ↓
World Store
  ↓
REST API
  ↓
WebSocket
  ↓
GM / Player Permissions
  ↓
Multiplayer VTT
```

最终由 Server 成为 authoritative state，Client 负责输入、显示和局部预测。
