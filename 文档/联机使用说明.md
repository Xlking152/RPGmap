# RPGmap 1.4.1 联机使用说明

本文说明 RPGmap V1.4.1 的便携目录、Player User、Actor Ownership、Combat Turn Lock，以及局域网 / 公网联机流程。

> 当前 V1.4.1 在 `feat/v1.4.1-player-identity` Draft PR 中验收；合并前稳定 `main` 仍保持 V1.4.0。

## 1. 便携目录：程序与地图数据分离

V1.4.1 发布包统一为：

```text
RPGmap-v1.4.1/
├─ app/                    前端程序，只读内容
├─ map/                    当前地图 / 跑团全部默认可写数据
│  ├─ world.json
│  ├─ users.json
│  ├─ uploads/
│  ├─ backups/
│  └─ README.txt
├─ docs/
├─ server.mjs
├─ access-control.mjs
├─ portable-storage.mjs
├─ internet-launcher.mjs
├─ start-rpgmap.bat
└─ start-rpgmap-internet.bat
```

核心原则：**World / User / Ownership / 上传资源默认只写在当前 RPGmap 包自己的 `map/` 目录中。**

因此：

- 不需要把 World/User 写到 AppData。
- 不需要在用户主目录创建隐藏数据库。
- 整个程序文件夹可以直接移动到另一个目录、硬盘或电脑。
- 备份跑团时，重点备份整个 `map/`。
- 升级程序时，应保留原 `map/`。

`cloudflared` 本身如果通过 winget 安装，可能属于系统软件；但 RPGmap 的地图、User 和 World 数据不依赖它的系统目录。

## 2. 身份模型

每个 RPGmap World 自己维护 Player User：

```text
Connection Session
        ↓
Persistent Player User
        ↓
Default Actor + Actor Ownership
```

- `Session`：本次 WebSocket 连接，断开后消失。
- `User`：持久 Player 身份，Server 重启后仍存在。
- `Default Actor`：该 User 的主要角色。
- `Ownership`：该 User 对各 Actor 的权限。

GM 不需要持久 User；GM 通过 GM Secret 登录，并隐式拥有全部 Actor 和管理权限。

## 3. User 怎么创建

### 推荐：Player 先申请，GM 再批准

1. Player 打开公网 / LAN 地址。
2. 选择 `Player`，填写名称和 Join Code。
3. 第一次加入进入“等待 GM 批准”，不会立即取得 World 操作权限。
4. GM 打开“联机 / Users”。
5. GM 为该 Player 设置正式 User 名称与默认角色。
6. 点击“批准并绑定”。
7. Server 创建持久 User，默认角色自动获得 OWNER。
8. Player 保存第一次显示的 Player Key。

### 备选：GM 预创建 User

1. GM 打开“联机 / Users”。
2. 在“预创建 Player User”填写 User 名称和默认角色。
3. 点击“创建 User + Player Key”。
4. GM 私下把 Player Key 发给对应玩家。
5. Player 输入 Join Code + Player Key 认领该 User。

## 4. User / World 实际保存在哪里

统一放在当前地图根目录：

```text
map/world.json
map/users.json
map/uploads/
map/backups/
```

### `map/world.json`

保存：

- Actor / Token 状态
- Scene
- Combat
- Chat / Game Log
- revision
- 其他共享 World 状态

### `map/users.json`

保存：

- `userId`
- User 名称
- 默认 Actor
- Actor Ownership
- Browser Token Hash
- Player Key Hash
- disabled 状态
- 创建 / 更新时间

不会保存明文 Player Key 或明文 Browser Token。

`users.json` 不参与 World Snapshot，所以 Player 无法通过 `world.push` 改写自己的 User / Ownership。

### 旧测试包自动迁移

如果新位置不存在对应文件，Server 会检查同一个 RPGmap 目录中的旧结构：

```text
data/worlds/default/world.json
data/worlds/default/access.json
```

然后复制为：

```text
map/world.json
map/users.json
```

旧文件保留，不自动删除。新位置一旦存在，以 `map/` 为准，不会反向覆盖。

## 5. 为什么需要 Player Key

Cloudflare Quick Tunnel 重启后通常会产生新的 `trycloudflare.com` 域名，而浏览器 localStorage 按域名隔离。

因此 V1.4.1 使用：

- **Browser Auth Token**：同一网址刷新 / 重连自动使用。
- **Player Key**：新 Quick Tunnel 地址上恢复原 User。

GM 可以“重发 Player Key”。这会生成新 Key，并使旧 Player Key 和旧 Browser Token 同时失效。

## 6. Actor Ownership

| 权限 | 含义 |
| --- | --- |
| `NONE` | 没有控制权 |
| `OBSERVER` | 观察 / 查看，不允许修改 Actor |
| `OWNER` | 可以操控该 Actor |

一个 Player 可以：

```text
默认角色：张三
OWNER：张三、李四
OBSERVER：王五
```

默认角色必须是 OWNER。GM 对所有 Actor 隐式拥有完整权限。

## 7. Player 能做什么

战斗外，Player 可以操作自己的 OWNER Actor，例如：

- 移动 Token
- 修改角色资源 / 状态
- 切换 Form
- 正常聊天
- 测距和个人 UI

Player 不能：

- 创建 / 删除 / 重绑 Actor 或 Token
- 修改非 OWNER Actor
- 修改 Combatant / Initiative / Round / Turn
- 开始 / 结束战斗
- 删除或改写已有 Chat / Game Log

## 8. Combat Turn Lock

Combat active 后，Player 即使拥有多个 OWNER Actor，也只能修改当前 Turn 对应的 OWNER Actor。

例如：

```text
1. 山贼甲   ← GM
2. 张三     ← Player A
3. 李四     ← Player A
4. 王五     ← Player B
```

当前 Turn 是张三：

- Player A → 张三：可操作
- Player A → 李四：锁定
- Player B → 王五：锁定
- GM → 任意角色：可操作

GM 点击“下一回合”后，控制权自动随当前 Combatant 切换。

Player 可以查看 Combat Tracker，但先攻输入、拖动排序、加入/移出、开始、下一回合、结束等管理控件为 GM-only。

## 9. 两层权限检查

```text
正常玩家操作
   ↓
Client preflight
   ↓
WebSocket world.push
   ↓
Server authoritative validation
   ↓
accept / world.denied
```

客户端检查负责体验；Server 检查才是最终权限边界。

## 10. Windows 远程联机

GM 双击：

```text
start-rpgmap-internet.bat
```

启动器会自动创建 Quick Tunnel、生成 Join Code / GM Secret、启动 Server、打开公网 RPGmap 和连接信息窗口。

首次 Player 通常只需要：

```text
Public URL + Join Code
```

已有 User 在新 Quick Tunnel 地址恢复时：

```text
Public URL + Join Code + 自己的 Player Key
```

GM Secret 仅供 GM 使用。

## 11. Player 后续登录

同一网址下，浏览器会用保存的 `userId + authToken` 自动恢复。

Quick Tunnel 换网址后，在新网址填写当前 Join Code + 原 Player Key，即可恢复原 User、默认角色和 Ownership，无需 GM 再创建一次。

## 12. 局域网联机

同一 LAN：

1. GM 运行 `start-rpgmap.bat`。
2. 使用启动窗口里的 `Network` 地址，例如 `http://192.168.1.4:30000`。
3. Player 打开该地址。
4. Identity / Ownership / Combat Lock 与公网模式相同。

## 13. World Snapshot 与并发

V1.4.1 继续使用完整 World Snapshot + `revision / baseRevision`，同时增加 Server diff 权限校验。

后续如果多人并发编辑频率继续提高，可以进一步升级为 patch / operation 同步。

## 14. 建议的 V1.4.1 实机验收

至少准备 GM + 两个 Player：

1. Player A / B 首次加入并由 GM 批准。
2. A 只能操作 A 的角色，B 只能操作 B 的角色。
3. 测试额外 OWNER 与 OBSERVER。
4. 开始 Combat，验证只有当前 Turn Actor 可由对应 Player 修改。
5. Player 尝试修改先攻 / 排序 / Turn，确认被禁用或拒绝。
6. 重启 Quick Tunnel，用新 URL + Join Code + Player Key 恢复原 User。
7. 重启 Server，确认 `map/world.json` 与 `map/users.json` 恢复。
8. 整个 RPGmap 文件夹复制到另一个路径，直接启动，确认 `map/` 数据跟随程序迁移。
9. GM 重发 Player Key，确认旧身份失效。
10. 如果目录中存在旧 `data/worlds/default/`，确认首次启动能自动迁移且旧文件仍保留。

以上通过后，再把 Draft PR 合并到 `main` 并发布正式 V1.4.1。
