# RPGmap 1.4.2 联机使用说明

本文说明 RPGmap V1.4.2 的便携目录、Player User、Actor Ownership、Combat Turn Lock，以及局域网 / 公网联机流程。

> V1.4.2 当前为 Candidate。稳定 `main` 在正式合并前仍保持 V1.4.0。

## 1. 发布包的数据边界

V1.4.2 统一使用：

```text
RPGmap-v1.4.2/
├─ app/                 程序前端
├─ world/               当前 World / Campaign 的运行数据
│  ├─ state.json
│  ├─ users.json
│  ├─ uploads/
│  └─ backups/
├─ maps/                真正 Map / Scene 资源库
├─ docs/
└─ ...
```

三者职责：

- `app/`：程序。
- `world/`：当前跑团发生的状态。
- `maps/`：地图 / Scene 模板和资源。

World / User 默认不会写入 AppData 或其他隐藏目录。

## 2. 身份模型

```text
Connection Session
        ↓
Persistent Player User
        ↓
Default Actor + Actor Ownership
```

- Session：当前 WebSocket 连接。
- User：持久 Player 身份。
- Default Actor：主要角色。
- Ownership：该 User 对 Actor 的权限。

GM 不需要持久 Player User；GM 使用 GM Secret 登录，并隐式拥有全部 Actor 和管理权限。

## 3. User 创建

### 推荐：Player 先申请，GM 再批准

1. Player 打开 RPGmap 地址。
2. 选择 `Player`，填写名称和 Join Code。
3. 第一次加入进入 pending，不立即获得 World 操作权限。
4. GM 打开“联机 / Users”。
5. GM 设置正式 User 名称与默认角色。
6. 点击“批准并绑定”。
7. Server 创建持久 User，默认角色自动获得 OWNER。
8. Player 保存第一次显示的 Player Key。

### 备选：GM 预创建 User

1. GM 在“联机 / Users”中预创建 Player User。
2. 设置 User 名称与默认角色。
3. RPGmap 生成 Player Key。
4. GM 私下把 Player Key 发给对应玩家。
5. Player 输入 Join Code + Player Key 认领该 User。

## 4. User / World 保存位置

### World

```text
world/state.json
```

保存：

- Actor / Token；
- Scene 实例状态；
- Combat；
- Chat / Game Log；
- revision；
- 当前地图及其运行状态；
- 其他共享 World 数据。

### User / Ownership

```text
world/users.json
```

保存：

- userId；
- User 名称；
- 默认 Actor；
- Actor Ownership；
- Browser Token Hash；
- Player Key Hash；
- disabled；
- 创建 / 更新时间。

不会保存明文 Player Key 或 Browser Token。

`users.json` 不参与 World Snapshot，因此 Player 不能通过 `world.push` 改写自己的 User 或 Ownership。

## 5. maps/ 的定位

`maps/` 从 V1.4.2 起只用于真正的地图 / Scene 资源，例如：

```text
maps/
├─ lanzhou/
├─ inn-01/
├─ dungeon-01/
└─ battlefield-01/
```

未来地图包可以包含：

- manifest / metadata；
- background；
- buildings / walls；
- destructibles；
- collision / navigation；
- environment effects；
- damaged / destroyed variants；
- map-specific assets。

例如“房屋可被破坏、有哪些损坏模型”属于 `maps/`；“这一场跑团里房屋当前 HP=23、正在燃烧”属于 `world/state.json`。

V1.4.2 只先建立这条边界，完整多地图切换 / 可破坏建筑系统后续继续实现。

## 6. 旧版本迁移

如果新位置不存在对应文件，V1.4.2 会按优先级自动迁移。

### V1.4.1 Candidate

```text
map/world.json  -> world/state.json
map/users.json  -> world/users.json
map/uploads/    -> world/uploads/
map/backups/    -> world/backups/
```

### 更旧版本

```text
data/worlds/default/world.json  -> world/state.json
data/worlds/default/access.json -> world/users.json
```

旧文件保留不删除。如果新的 `world/state.json` / `world/users.json` 已存在，则不会被旧数据覆盖。

## 7. Player Key

Quick Tunnel 重启后通常会产生新的 `trycloudflare.com` 域名，而浏览器 localStorage 按域名隔离。

因此 RPGmap 使用：

- **Browser Auth Token**：同一网址刷新 / 重连自动使用。
- **Player Key**：新 Quick Tunnel 地址上恢复原 User。

GM 可以“重发 Player Key”。这样会生成新 Key，并使旧 Player Key 和旧 Browser Token 同时失效。

## 8. Actor Ownership

| 权限 | 含义 |
| --- | --- |
| `NONE` | 没有控制权 |
| `OBSERVER` | 观察 / 查看，不允许修改 Actor |
| `OWNER` | 可以操控 Actor |

一个 Player 可以拥有：

```text
默认角色：张三
OWNER：张三、李四
OBSERVER：王五
```

默认角色必须是 OWNER。GM 对所有 Actor 隐式拥有完整权限。

## 9. Player 能做什么

战斗外，Player 可以操作自己的 OWNER Actor，例如：

- 移动 Token；
- 修改角色资源 / 状态；
- 切换 Form；
- 正常聊天；
- 测距和个人 UI。

Player 不能：

- 创建 / 删除 / 重绑 Actor 或 Token；
- 修改非 OWNER Actor；
- 修改 Combatant / Initiative / Round / Turn；
- 开始 / 结束战斗；
- 删除或改写已有 Chat / Game Log。

## 10. Combat Turn Lock

Combat active 后，Player 即使拥有多个 OWNER Actor，也只能修改当前 Turn 对应的 OWNER Actor。

例如：

```text
1. 山贼甲   ← GM
2. 张三     ← Player A
3. 李四     ← Player A
4. 王五     ← Player B
```

当前 Turn 是张三：

- Player A → 张三：可操作；
- Player A → 李四：锁定；
- Player B → 王五：锁定；
- GM → 任意角色：可操作。

Player 可以查看 Combat Tracker，但先攻输入、拖动排序、加入 / 移出、开始、下一回合、结束等管理控件为 GM-only。

## 11. 两层权限检查

```text
Player UI Action
   ↓
Client preflight
   ↓
WebSocket world.push
   ↓
Server authoritative validation
   ↓
accept / world.denied
```

Client 检查负责体验；Server 检查才是最终权限边界。

## 12. Windows 公网联机

GM 双击：

```text
start-rpgmap-internet.bat
```

启动器会自动创建 Quick Tunnel、生成 Join Code / GM Secret、启动 Server、打开公网 RPGmap 和连接信息窗口。

首次 Player 通常只需要：

```text
Public URL + Join Code
```

已有 User 在新 Quick Tunnel 地址恢复时：

```text
Public URL + Join Code + 自己的 Player Key
```

GM Secret 仅供 GM 使用。

## 13. 局域网联机

同一 LAN：

1. GM 运行 `start-rpgmap.bat`。
2. 使用启动窗口显示的 Network 地址，例如 `http://192.168.1.4:30000`。
3. Player 打开该地址。
4. User / Ownership / Combat Lock 与公网模式相同。

## 14. 备份 / 搬迁

最重要的 Campaign 备份：

```text
world/
```

如果还需要地图模板 / 资源，一并备份：

```text
maps/
```

整个 RPGmap 目录可以直接复制到另一块硬盘或另一台电脑。升级程序时保留自己的 `world/` 与 `maps/`。

## 15. V1.4.2 实机验收建议

1. GM + Player A + Player B 登录。
2. 两个 Player 首次申请，由 GM 分配不同 Actor。
3. A 只能修改 A，B 只能修改 B。
4. 测试额外 OWNER / OBSERVER。
5. 开始 Combat，确认控制权随 Turn 切换。
6. Player 尝试修改 Initiative / 排序 / Turn，确认被禁用或拒绝。
7. 重启 Quick Tunnel，用新 URL + Join Code + Player Key 恢复 User。
8. 重启 Server，确认 `world/state.json` + `world/users.json` 恢复。
9. 用 V1.4.1 Candidate 的 `map/world.json` / `map/users.json` 测试自动迁移。
10. 用更老 `data/worlds/default/` 测试迁移。
11. 将整个 RPGmap 文件夹复制到另一目录启动，确认 World / User 跟随移动。
12. 确认 `maps/` 不会被 Server 当成 User / World 数据目录写入。

以上通过后，再把 V1.4.2 Candidate 合并到 `main`。
