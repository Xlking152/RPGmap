# RPGmap 1.4.3 联机使用说明

本文说明 RPGmap V1.4.3 的 Unified Web Launcher、Persistent Player User、Actor Ownership、Combat Turn Lock，以及局域网 / 公网联机流程。

> V1.4.3 当前为 Candidate；稳定 `main` 在正式合并前仍保持 V1.4.0。

## 1. Windows 启动入口

发布包根目录只保留：

```text
启动 RPGmap.bat
```

BAT 仅负责查找 Node.js 并启动：

```text
launcher/launcher.mjs
```

之后所有 GM 控制都在浏览器 Launcher 页面完成。

当前 Node.js 要求：

```text
^20.19.0 || >=22.12.0
```

BAT 优先使用：

```text
tools/node/node.exe
```

其次使用根目录 `node.exe`，最后使用系统 PATH 中的 Node。

## 2. Launcher 本机端口

Launcher 只绑定：

```text
127.0.0.1
```

首选端口 `29999`。如果被占用，会自动尝试：

```text
29998 → 29997 → 29996 → 29995
```

仍无法使用时，由 Windows 自动分配空闲 loopback 端口。浏览器会自动打开实际地址。

因此：

- 不需要强制关闭占用 29999 的其他程序；
- 不需要手工修改配置；
- 远程 Player 也无法通过 Cloudflare Tunnel 访问 Launcher 管理后台。

Game Server 默认仍使用：

```text
0.0.0.0:30000
```

## 3. 发布包数据边界

```text
RPGmap-v1.4.3/
├─ 启动 RPGmap.bat
├─ 操作说明.md
├─ app/
├─ launcher/
├─ server/
├─ world/
│  ├─ state.json
│  ├─ users.json
│  ├─ uploads/
│  └─ backups/
├─ maps/
├─ tools/
└─ docs/
```

- `app/`：程序。
- `world/`：当前跑团发生的状态。
- `maps/`：地图 / Scene 模板和资源。
- `launcher/`：GM 本机网页控制中心。
- `server/`：Multiplayer Server 内部程序。
- `tools/`：cloudflared、未来 Portable Node 等内部运行工具。

World / User 默认不会写入 AppData 或其他隐藏目录。

## 4. Launcher 的联机模式

### 本机 / LAN

点击：

```text
启动本机 / 局域网
```

Launcher 自动生成 Join Code / GM Secret、启动 Server、建立隐藏 GM Admin Session，并显示 Local / LAN URL。

### Internet

点击：

```text
启动互联网联机
```

Launcher 会：

1. 检测 cloudflared；
2. 优先使用 `tools/cloudflared.exe`；
3. Windows 缺失时下载官方版本到 `tools/`；
4. 建立 Cloudflare Quick Tunnel；
5. 使用 HTTP/2 over TCP；
6. 启动 Server；
7. 显示 Public URL / Join Code / GM Secret。

“玩家邀请”只包含：

```text
Public/LAN URL + Join Code
```

不会包含 GM Secret。

## 5. 身份模型

```text
Connection Session
        ↓
Persistent Player User
        ↓
Default Actor + Actor Ownership
```

- Session：当前 WebSocket 连接。
- User：持久 Player 身份。
- Default Actor：主要角色。
- Ownership：该 User 对 Actor 的权限。

GM 不需要持久 Player User；GM 使用 GM Secret 登录，并隐式拥有全部 Actor 和管理权限。

## 6. User 创建

### 推荐：Player 先申请，GM 再批准

1. Player 打开 RPGmap 地址。
2. 选择 `Player`，填写名称和 Join Code。
3. 第一次加入进入 pending，不立即获得 World 操作权限。
4. GM 在 Launcher 的“待批准玩家”中看到该 Player。
5. GM 设置正式 User 名称与默认角色。
6. 点击批准。
7. Server 创建持久 User，默认角色自动获得 OWNER。
8. Player 保存第一次显示的 Player Key。

也可以继续使用游戏内“联机 / Users”面板完成相同操作。

### 备选：GM 预创建 User

1. GM 在 Launcher 中预创建 Player User。
2. 设置 User 名称与默认角色。
3. RPGmap 生成 Player Key。
4. GM 私下把 Player Key 发给对应玩家。
5. Player 输入 Join Code + Player Key 认领该 User。

## 7. User / World 保存位置

### World

```text
world/state.json
```

保存 Actor / Token、Scene 实例状态、Combat、Chat / Game Log、revision、当前地图及其他共享 World 数据。

### User / Ownership

```text
world/users.json
```

保存：

- userId；
- User 名称；
- 默认 Actor；
- Actor Ownership；
- Browser Token Hash；
- Player Key Hash；
- disabled；
- 创建 / 更新时间。

不会保存明文 Player Key 或 Browser Token。

Launcher 不直接写这个文件，而是通过隐藏 GM WebSocket Session 调用 Server 权限逻辑。

## 8. Player Key

Quick Tunnel 重启后通常会产生新的 `trycloudflare.com` 域名，而浏览器 localStorage 按域名隔离。

因此 RPGmap 使用：

- **Browser Auth Token**：同一网址刷新 / 重连自动使用；
- **Player Key**：新 Quick Tunnel 地址上恢复原 User。

GM 可以在 Launcher 或游戏内 Users 面板“重发 Player Key”。新 Key 会使旧 Player Key 和旧 Browser Token 同时失效。

## 9. Actor Ownership

| 权限 | 含义 |
| --- | --- |
| `NONE` | 没有控制权 |
| `OBSERVER` | 观察 / 查看，不允许修改 Actor |
| `OWNER` | 可以操控 Actor |

一个 Player 可以拥有一个默认角色，以及多个 OWNER / OBSERVER Actor。默认角色必须是 OWNER。GM 对所有 Actor 隐式拥有完整权限。

## 10. Player 能做什么

战斗外，Player 可以操作自己的 OWNER Actor，例如：

- 移动 Token；
- 修改角色资源 / 状态；
- 切换 Form；
- 正常聊天；
- 测距和个人 UI。

Player 不能：

- 创建 / 删除 / 重绑 Actor 或 Token；
- 修改非 OWNER Actor；
- 修改 Combatant / Initiative / Round / Turn；
- 开始 / 结束战斗；
- 删除或改写已有 Chat / Game Log。

## 11. Combat Turn Lock

Combat active 后，Player 即使拥有多个 OWNER Actor，也只能修改当前 Turn 对应的 OWNER Actor。

GM 负责 Combatant、Initiative、排序、开始 / 结束、Round / Turn 推进。

## 12. Client Preflight + Server Authority

权限采用双层模式：

```text
客户端预检
   ↓
world.push
   ↓
Server authoritative validation
```

客户端会主动禁止无权限拖动 / 修改，改善体验；Server 仍是最终安全边界。

## 13. Launcher Admin

Launcher 可以：

- 查看 pending / registered User；
- approve Player；
- create User；
- 设置 Default Actor；
- 设置 NONE / OBSERVER / OWNER；
- rotate Player Key；
- delete User；
- 查看在线状态和 Actor catalog。

Launcher 不直接改 JSON，而是使用隐藏 GM Session 调用 `access.*` 协议。

## 14. Launcher 未来管理模块

Launcher UI 已预留但暂未启用：

- World Manager；
- Scene Manager；
- Backup Center。

## 15. 备份

至少备份：

```text
world/
```

有自定义地图时同时备份：

```text
maps/
```

## 16. Troubleshooting

### BAT 启动后浏览器没有打开

检查根目录：

```text
launcher-startup.log
```

也可以手动执行：

```bat
node launcher\launcher.mjs
```

### 29999 已被占用

无需处理，Launcher 会自动选择其他本机端口。

### Player 能看到不该控制的角色

当前 Ownership 是**控制权限**，不是完整数据隐私。V1.4.3 仍使用完整 World Snapshot。未来如果需要隐藏 NPC Sheet / GM-only 数据，需要实现 per-user filtered snapshot 或 document-level visibility。
