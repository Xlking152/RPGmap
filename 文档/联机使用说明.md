# RPGmap 1.4.3 联机使用说明

本文说明 RPGmap V1.4.3 的 Unified Launcher、Player User、Actor Ownership、Combat Turn Lock，以及局域网 / 公网联机流程。

> V1.4.3 当前为 Candidate。稳定 `main` 在正式合并前仍保持 V1.4.0。

## 1. Windows 启动入口

发布包根目录只保留：

```text
RPGmap Launcher.exe
```

双击后由 Native Launcher 查找 Node.js，并启动本机 Launcher 控制中心：

```text
http://127.0.0.1:29999
```

Launcher 不使用 Electron。当前仍要求 Node.js `^20.19.0 || >=22.12.0`。

Launcher 只绑定 `127.0.0.1`，远程 Player 无法通过 Cloudflare Tunnel 访问 Launcher 管理后台。

## 2. 发布包数据边界

```text
RPGmap-v1.4.3/
├─ RPGmap Launcher.exe
├─ 操作说明.md
├─ app/
├─ launcher/
├─ server/
├─ world/
│  ├─ state.json
│  ├─ users.json
│  ├─ uploads/
│  └─ backups/
├─ maps/
└─ docs/
```

三者职责：

- `app/`：程序。
- `world/`：当前跑团发生的状态。
- `maps/`：地图 / Scene 模板和资源。

World / User 默认不会写入 AppData 或其他隐藏目录。

## 3. Launcher 的联机模式

### 本机 / LAN

点击：

```text
启动本机 / 局域网
```

Launcher 自动生成 Join Code / GM Secret、启动 Server、建立隐藏 GM Admin Session，并显示 Local / LAN URL。

### Internet

点击：

```text
启动互联网联机
```

Launcher 会：

1. 检测 cloudflared；
2. Windows 缺失时下载到 RPGmap 包内 `tools/`；
3. 建立 Cloudflare Quick Tunnel；
4. 使用 HTTP/2 over TCP；
5. 启动 Server；
6. 显示 Public URL / Join Code / GM Secret。

“玩家邀请”只包含：

```text
Public/LAN URL + Join Code
```

不会包含 GM Secret。

## 4. 身份模型

```text
Connection Session
        ↓
Persistent Player User
        ↓
Default Actor + Actor Ownership
```

- Session：当前 WebSocket 连接。
- User：持久 Player 身份。
- Default Actor：主要角色。
- Ownership：该 User 对 Actor 的权限。

GM 不需要持久 Player User；GM 使用 GM Secret 登录，并隐式拥有全部 Actor 和管理权限。

## 5. User 创建

### 推荐：Player 先申请，GM 再批准

1. Player 打开 RPGmap 地址。
2. 选择 `Player`，填写名称和 Join Code。
3. 第一次加入进入 pending，不立即获得 World 操作权限。
4. GM 在 Launcher 的“待批准玩家”中看到该 Player。
5. GM 设置正式 User 名称与默认角色。
6. 点击批准。
7. Server 创建持久 User，默认角色自动获得 OWNER。
8. Player 保存第一次显示的 Player Key。

也可以继续使用游戏内“联机 / Users”面板完成相同操作。

### 备选：GM 预创建 User

1. GM 在 Launcher 中预创建 Player User。
2. 设置 User 名称与默认角色。
3. RPGmap 生成 Player Key。
4. GM 私下把 Player Key 发给对应玩家。
5. Player 输入 Join Code + Player Key 认领该 User。

## 6. User / World 保存位置

### World

```text
world/state.json
```

保存 Actor / Token、Scene 实例状态、Combat、Chat / Game Log、revision、当前地图及其他共享 World 数据。

### User / Ownership

```text
world/users.json
```

保存：

- userId；
- User 名称；
- 默认 Actor；
- Actor Ownership；
- Browser Token Hash；
- Player Key Hash；
- disabled；
- 创建 / 更新时间。

不会保存明文 Player Key 或 Browser Token。

Launcher 不直接写这个文件，而是通过隐藏 GM WebSocket Session 调用 Server 权限逻辑。

## 7. Player Key

Quick Tunnel 重启后通常会产生新的 `trycloudflare.com` 域名，而浏览器 localStorage 按域名隔离。

因此 RPGmap 使用：

- **Browser Auth Token**：同一网址刷新 / 重连自动使用。
- **Player Key**：新 Quick Tunnel 地址上恢复原 User。

GM 可以在 Launcher 或游戏内 Users 面板“重发 Player Key”。这样会生成新 Key，并使旧 Player Key 和旧 Browser Token 同时失效。

## 8. Actor Ownership

| 权限 | 含义 |
| --- | --- |
| `NONE` | 没有控制权 |
| `OBSERVER` | 观察 / 查看，不允许修改 Actor |
| `OWNER` | 可以操控 Actor |

一个 Player 可以拥有一个默认角色，以及多个 OWNER / OBSERVER Actor。默认角色必须是 OWNER。GM 对所有 Actor 隐式拥有完整权限。

## 9. Player 能做什么

战斗外，Player 可以操作自己的 OWNER Actor，例如：

- 移动 Token；
- 修改角色资源 / 状态；
- 切换 Form；
- 正常聊天；
- 测距和个人 UI。

Player 不能：

- 创建 / 删除 / 重绑 Actor 或 Token；
- 修改非 OWNER Actor；
- 修改 Combatant / Initiative / Round / Turn；
- 开始 / 结束战斗；
- 删除或改写已有 Chat / Game Log。

## 10. Combat Turn Lock

Combat active 后，Player 即使拥有多个 OWNER Actor，也只能修改当前 Turn 对应的 OWNER Actor。

Player 可以查看 Combat Tracker，但先攻输入、拖动排序、加入 / 移出、开始、下一回合、结束等管理控件为 GM-only。

## 11. 两层权限检查

```text
Player UI Action
   ↓
Client preflight
   ↓
WebSocket world.push
   ↓
Server authoritative validation
   ↓
accept / world.denied
```

Client 检查负责体验；Server 检查才是最终权限边界。

## 12. Launcher Admin Console

Launcher 可以直接管理：

- pending Player；
- Persistent User；
- 默认 Actor；
- NONE / OBSERVER / OWNER；
- Player Key rotation；
- User 删除；
- 在线 / 离线状态。

安全边界：

```text
Launcher 127.0.0.1:29999
Game Server 0.0.0.0:30000
Cloudflare -> only Game Server
```

## 14. maps/ 的定位

`maps/` 只用于真正的地图 / Scene 资源，例如：

```text
maps/
├─ lanzhou/
├─ inn-01/
├─ dungeon-01/
└─ battlefield-01/
```

未来地图包可以包含 manifest、background、buildings / walls、destructibles、collision / navigation、environment effects 和 damaged / destroyed variants。

## 15. 旧版本迁移

如果新位置不存在对应文件，会按优先级自动迁移：

```text
V1.4.1 Candidate
map/world.json  -> world/state.json
map/users.json  -> world/users.json

更旧版本
data/worlds/default/world.json  -> world/state.json
data/worlds/default/access.json -> world/users.json
```

旧文件保留不删除。

## 16. 备份 / 搬迁

最重要的 Campaign 备份：

```text
world/
```

如果还需要地图模板 / 资源，一并备份：

```text
maps/
```

当前可手动复制；自动快照 / 恢复将由未来 Backup Center 提供。
