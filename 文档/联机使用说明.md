# RPGmap 1.4.3 联机使用说明

本文说明 V1.4.3 的统一 Launcher、Persistent Player User、Actor Ownership、Combat Turn Lock，以及局域网 / 公网联机流程。

> V1.4.3 当前为 Candidate；稳定 `main` 在正式合并前仍保持 V1.4.0。

## 1. 发布包结构

```text
RPGmap-v1.4.3/
├─ 启动 RPGmap.bat
├─ 操作说明.md
├─ app/
├─ launcher/
├─ server/
├─ world/
│  ├─ state.json
│  ├─ users.json
│  ├─ uploads/
│  └─ backups/
├─ maps/
└─ docs/
```

- `app/`：程序。
- `world/`：当前 Campaign 的运行数据。
- `maps/`：Map / Scene 模板和资源。
- `launcher/`：本机 GM Control Center。
- `server/`：Multiplayer Server 内部程序。

## 2. 统一 Launcher

Windows 双击：

```text
启动 RPGmap.bat
```

Launcher 页面默认：

```text
http://127.0.0.1:29999
```

Launcher 可以启动：

- 本机 / LAN；
- Internet Quick Tunnel。

并集中显示 Local / LAN / Public URL、Join Code、GM Secret、Player Invite、Users / Ownership 和日志。

Launcher 只监听本机 loopback，不通过 Cloudflare 暴露。

## 3. 身份模型

```text
Connection Session
        ↓
Persistent Player User
        ↓
Default Actor + Actor Ownership
```

GM 不需要 Persistent Player User；GM 使用 GM Secret 并隐式拥有全部 Actor / 管理权限。

## 4. Player 首次加入

推荐流程：

1. Player 打开 LAN / Public URL。
2. 选择 Player，填写名称和 Join Code。
3. 首次加入进入 pending。
4. GM 在 Launcher 或游戏内“联机 / Users”看到该 Player。
5. GM 设置正式 User 名称和默认 Actor。
6. 批准并绑定。
7. Server 创建 Persistent User，默认 Actor 自动 OWNER。
8. Player 保存 Player Key。

## 5. GM 预创建 User

GM 可以直接在 Launcher 的“预创建 User”建立身份，并选择默认 Actor。

Server 返回 Player Key；GM 私下发给对应玩家。

Player 在新网址输入：

```text
Join Code + Player Key
```

即可恢复 / 认领原 User。

## 6. Launcher Admin 如何修改后台

Launcher 不直接编辑：

```text
world/users.json
```

而是建立隐藏 GM WebSocket Session，发送现有 Server 协议：

```text
access.request
access.user.approve
access.user.create
access.user.update
access.user.reset-claim
access.user.delete
```

因此 Launcher 和游戏内 GM Users 面板共享同一套：

- Server 内存状态；
- Ownership 校验；
- Player Key 逻辑；
- `users.json` 持久化。

## 7. User / World 保存位置

World：

```text
world/state.json
```

User / Ownership：

```text
world/users.json
```

`users.json` 保存 userId、名称、默认 Actor、Ownership、Credential Hash、disabled 和时间戳，不保存明文 Player Key / Browser Token。

`users.json` 不进入 World Snapshot，所以 Player 不能通过 `world.push` 给自己加权限。

## 8. Player Key

Quick Tunnel 重启后域名可能改变，Browser localStorage 无法跨域。

因此：

- Browser Auth Token：同一网址自动重连；
- Player Key：新 URL 恢复同一 Persistent User。

GM 可在 Launcher 或游戏内 Users 面板重发 Player Key。新 Key 会废弃旧 Key 与旧 Browser Token。

## 9. Actor Ownership

| 权限 | 含义 |
| --- | --- |
| `NONE` | 无控制权 |
| `OBSERVER` | 观察 / 查看 |
| `OWNER` | 可操控 Actor |

一个 Player 可以：

```text
默认角色：张三
OWNER：张三、李四
OBSERVER：王五
```

默认角色必须是 OWNER。GM 隐式拥有全部 Actor。

## 10. Player 操作权限

战斗外，Player 可以操作自己的 OWNER Actor，例如：移动 Token、修改角色资源 / 状态、切换 Form、聊天和测距。

Player 不能：

- 创建 / 删除 / 重绑 Actor 或 Token；
- 修改非 OWNER Actor；
- 修改 Combatant / Initiative / Round / Turn；
- 开始 / 结束战斗；
- 删除或改写已有 Chat / Game Log。

## 11. Combat Turn Lock

Combat active 后，即使 Player 有多个 OWNER Actor，也只能操控当前 Turn 对应的那个 Actor。

GM 始终可以操作任意 Actor，并负责 Combatant、Initiative、排序、开始 / 结束、Round / Turn。

Player 可以查看 Combat Tracker，但管理控件只读。

## 12. 两层权限检查

```text
Player UI Action
   ↓
Client preflight
   ↓
WebSocket world.push
   ↓
Server authoritative validation
   ↓
accept / world.denied
```

Client 检查负责体验；Server 才是最终权限边界。

## 13. Internet 联机

Launcher 点击：

```text
启动互联网联机
```

自动创建 Quick Tunnel、生成 Join Code / GM Secret 并显示 Public URL。

首次 Player 收到：

```text
Public URL + Join Code
```

已有 User 在新 Quick Tunnel 地址恢复：

```text
Public URL + Join Code + Player Key
```

GM Secret 只供 GM 使用。

## 14. LAN 联机

Launcher 点击：

```text
启动本机 / 局域网
```

Player 使用 Launcher 显示的 LAN URL + Join Code。

User / Ownership / Combat Lock 与 Internet 模式完全相同。

## 15. maps/ 定位

`maps/` 只用于真正 Map / Scene 资源，例如未来：背景、建筑 / 墙体、destructibles、collision / navigation、environment effects、damaged / destroyed variants。

地图模板属于 `maps/`；本次 Campaign 中地图实例发生的破坏 / 燃烧 / 事件状态属于 `world/state.json`。

## 16. 备份 / 搬迁

最重要的 Campaign 备份：

```text
world/
```

自定义地图资源同时备份：

```text
maps/
```

整个 RPGmap 目录可直接搬迁。默认不会把 World/User 写到 AppData。

## 17. V1.4.3 实机验收建议

1. 双击唯一 `启动 RPGmap.bat`，确认 Launcher 页面自动打开。
2. Local / LAN 模式启动并显示 Local、LAN、Join Code、GM Secret。
3. Internet 模式启动并显示 Public URL。
4. “复制玩家邀请”确认不包含 GM Secret。
5. Player A 首次加入 pending，Launcher 批准并分配 Actor A。
6. Launcher 预创建 Player B，确认显示 Player Key。
7. 在 Launcher 修改 A 的 OWNER / OBSERVER，游戏内权限立即同步。
8. 重发 Player Key，确认旧身份失效。
9. 删除 User，确认在线身份失效。
10. Combat active 时确认控制权随 Turn 切换。
11. Launcher 停止 Server 后确认 Tunnel 同时结束。
12. 确认发布包根目录只有一个 BAT。

通过后再将 V1.4.3 Candidate 合并到 `main`。
