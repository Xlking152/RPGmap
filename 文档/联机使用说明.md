# RPGmap 1.4.3 联机使用说明

本文说明 V1.4.3 的 Unified Web Launcher、Persistent Player User、Actor Ownership、Combat Turn Lock，以及局域网 / 公网联机流程。

> 当前为 Candidate；稳定 `main` 在正式合并前仍保持 V1.4.0。

## 1. Windows 启动

发布包根目录唯一入口：

```text
RPGmap.bat
```

BAT 查找 Node.js 后直接运行：

```text
launcher/launcher.mjs
```

BAT 窗口作为 Runtime 保持运行，可以最小化；实际操作都在浏览器 Launcher 页面中。

当前 Node.js 要求：

```text
^20.19.0 || >=22.12.0
```

## 2. Launcher 本机端口

Launcher 只绑定 `127.0.0.1`。

首选 `29999`，冲突时自动尝试：

```text
29998 → 29997 → 29996 → 29995
```

仍不可用时由 Windows 自动分配空闲 loopback 端口。浏览器会自动打开实际地址。

Game Server 默认：

```text
0.0.0.0:30000
```

## 3. 发布包边界

```text
RPGmap-v1.4.3/
├─ RPGmap.bat
├─ 操作说明.md
├─ app/
├─ launcher/
├─ server/
├─ world/

│  ├─ users.json
│  ├─ uploads/

```

- `app/`：程序；
- `world/`：当前 Campaign 运行数据；
- `maps/`：Map / Scene 模板与资源；
- `tools/`：cloudflared / 未来 Portable Node。

## 4. 本机 / LAN

点击 Launcher 的“启动本机 / 局域网”，Launcher 自动生成 Join Code / GM Secret、启动 Server、建立隐藏 GM Admin Session，并显示 Local / LAN URL。

## 5. Internet

点击“启动互联网联机”后：

1. 检测 cloudflared；
2. 优先使用 `tools/cloudflared.exe`；
3. Windows 缺失时自动下载；
4. 建立 Cloudflare Quick Tunnel；
5. 使用 HTTP/2 over TCP；
6. 启动 Server；
7. 显示 Public URL / Join Code / GM Secret。

Player Invite 只包含 Public/LAN URL + Join Code，不包含 GM Secret。

## 6. 身份模型

```text
Connection Session
        ↓
Persistent Player User
        ↓
Default Actor + Actor Ownership
```

GM 使用 GM Secret，并隐式拥有全部 Actor / 管理权限。

## 7. User 创建

推荐流程：

1. Player 打开 RPGmap 地址；
2. 输入名称 + Join Code；
3. 首次加入成为 pending；
4. GM 在 Launcher 中选择正式 User 名称与 Default Actor；
5. approve；
6. Server 创建 Persistent User；
7. Default Actor 自动获得 OWNER；
8. Player 保存 Player Key。

GM 也可以预创建 User，再私下发送 Player Key。

## 8. 保存位置

World：

```text
world/state.json
```

User / Ownership：

```text
world/users.json
```

Server 只保存 credential hash，不保存明文 Player Key / Browser Token。

Launcher 不直接修改 JSON，而是通过隐藏 GM WebSocket Session 调用 Server 权限逻辑。

## 9. Player Key

- Browser Auth Token：同一网址自动重连；
- Player Key：Quick Tunnel 域名变化后在新网址恢复原 User。

重发 Player Key 会使旧 Key 和旧 Browser Token 失效。

## 10. Actor Ownership

| 权限 | 含义 |
| --- | --- |
| `NONE` | 无控制权 |
| `OBSERVER` | 观察 / 查看 |
| `OWNER` | 可操控 Actor |

一个 Player 可有一个 Default Actor 和多个 OWNER / OBSERVER。Default Actor 必须是 OWNER。

## 11. Combat Turn Lock

Combat active 后，Player 即使拥有多个 OWNER Actor，也只能修改当前 Turn 对应的 OWNER Actor。

GM 负责 Combatant、Initiative、排序、开始 / 结束和 Round / Turn 推进。

## 12. Client Preflight + Server Authority

```text
客户端预检
   ↓
world.push
   ↓
Server authoritative validation
```

客户端负责友好提示，Server 是最终权限边界。

## 13. Launcher Admin

可执行：pending approve、User create/update/delete、Default Actor、NONE / OBSERVER / OWNER、Player Key rotation、在线状态与 Actor catalog。

## 14. 未来模块

Launcher 已预留：

- World Manager；
- Scene Manager；
- Backup Center。

## 15. 当前隐私边界

V1.4.3 的 Ownership 是**控制权限**，不是完整数据隐私。当前仍使用完整 World Snapshot。未来隐藏 NPC Sheet / GM-only 数据需要 per-user filtered snapshot 或 document-level visibility。

## 16. Troubleshooting

### BAT 启动后没有网页

先看 BAT 窗口中的错误，也可以手动执行：

```bat
node launcher\launcher.mjs
```

### 29999 被占用

无需处理，Launcher 会自动换端口。
