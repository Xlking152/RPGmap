# 北宋兰州 RPG 地图：代码配置与二次开发说明

本文面向后续维护者、地图制作者和主持人应用的开发人员，记录当前交付版本的技术配置、数据契约、地图包制作方式、场景破坏算法、构建测试流程与扩展注意事项。

当前基线：

- 项目版本：`1.1.0`
- 地图包 ID：`northern-song-lanzhou-1104`
- 地图包版本：`1.0.5`
- 存档格式：`SaveV2`（兼容迁移 SaveV1）
- 世界尺寸：`6000 × 5000` 米
- 坐标约定：左上角为原点，X 向右，Y 向下，`1 世界单位 = 1 米`
- 生产成品：`dist/index.html`，为不依赖网络的离线单 HTML

> 本项目属于“史料约束下的游戏复原”。测距和攻击范围在游戏坐标内是精确的，但街巷、房址与建筑位置不是考古测绘结论。

## 1. 技术栈与版本

### 1.1 运行与构建

| 组件 | 当前版本 | 用途 |
| --- | --- | --- |
| 原生 JavaScript | ES2020 构建目标 | 应用逻辑、工具和数据模型 |
| SVG | 原生浏览器支持 | 地图、建筑、道路、网格、废墟与破坏遮罩 |
| Leaflet | `1.9.4` | 平移、缩放、坐标视图和交互图层 |
| Lucide | `1.30.0` | 顶部工具栏与品牌区的内联线性图标 |
| polygon-clipping | `0.15.7` | 多边形相交面积与覆盖率计算 |
| EasyStar.js | `0.4.4` | 10 米导航网格的异步 A* 寻路 |
| Vite | `8.2.1` | 开发服务器和生产构建 |
| vite-plugin-singlefile | `2.3.3` | 将 JS、CSS、Leaflet 和地图包内联到单 HTML |
| Node.js `node:test` | Node 内置 | 自动化测试 |

Vite 8 的 Node.js 要求为 `^20.19.0` 或 `>=22.12.0`。本次交付实际使用 Node.js `v24.14.1` 构建和测试。

### 1.2 设计原则

- 地图结构、坐标和交互对象必须保持真正的 SVG；允许使用少量经审查的本地 WebP 作为表面纹理或贴花，但禁止大尺寸 Canvas、栅格底图和外链图片。
- 通用引擎与地图内容分离：交互编排在 `src/engine/`，持久化在 `src/app/`，场景渲染在 `src/render/`，兰州地图包在 `src/maps/lanzhou.js`。
- 地图包只描述地图和可交互对象；标记、测距、范围攻击、存档和破坏历史由通用引擎负责。
- 所有破坏均为运行时派生效果，不永久删除或修改源 SVG。
- 标记、角色、攻击范围、场景事件和用户偏好持久化；两点测距、路线测距、角色移动预览、当前地物选择和记录高亮只保存在当前页面会话中。

## 3. 安装、开发、测试与构建

在 Windows PowerShell 中进入项目根目录后运行：

```powershell
npm.cmd ci
npm.cmd run dev
```

开发服务器默认监听 `http://127.0.0.1:5173/`。若端口已被占用，Vite 会选择其他端口并在终端显示实际地址。

运行自动化测试：

```powershell
npm.cmd test
```

生成离线单页：

```powershell
npm.cmd run build
```

构建成功后应交付：

```text
dist/index.html
```

该文件已内联 JavaScript、CSS、Leaflet、地图 SVG 和生成式美术 WebP，可以直接双击离线打开。`vite.config.js` 中的重要配置如下：

- `base: './'`：使用相对路径，避免本地文件路径失效。
- `viteSingleFile()`：把构建资源内联到一个 HTML。
- `cssCodeSplit: false`：不生成独立 CSS 文件。
- `assetsInlineLimit: 100_000_000`：允许构建资源内联。
- `target: 'es2020'`：浏览器代码目标。
- `stripUnusedLeafletRasterCss()`：清理 Leaflet 默认图标 CSS 中未使用的内联 PNG；项目自有的 29 项生成式 WebP 由入口显式导入，不受该清理器影响。

修改构建设置后，必须再次确认 `dist/` 中只有单个 `index.html`，并在断网环境或浏览器离线模式中测试。

## 4. 应用装配与通用引擎接口

入口文件 `src/main.js` 负责把地图包传给通用应用：

```js
import 'leaflet/dist/leaflet.css';
import './styles.css';
import { createRpgMapApp } from './engine/app.js';
import { lanzhouMapPackage } from './maps/lanzhou.js';

createRpgMapApp({
  container: document.querySelector('#app'),
  mapPackage: lanzhouMapPackage,
});
```

`createRpgMapApp()` 当前接受：

```js
createRpgMapApp({
  container,              // 必填：应用根 DOM 元素
  mapPackage,             // 必填：地图包，至少提供 id/version/尺寸/createSvg
  storageAdapter,         // 可选：自定义存储，默认使用 localStorage
  tools: [],              // 可选：额外工具插件数组
});
```

默认存储适配器契约：

```js
{
  get(key) {},
  set(key, value) {},
  remove(key) {},
}
```

本地图的本地存储键为：

```text
rpg-map:northern-song-lanzhou-1104:v1
```

返回的应用 API 包含：

```js
{
  map,                    // Leaflet map 实例
  mapPackage,
  getState(),             // 返回结构化克隆，不暴露内部可变引用
  setTool(toolName),
  exportState(),
  importState(raw, askConfirmation?),
  on(type, listener),     // 返回取消订阅函数
  emit(type, detail),
  registerTool(tool),     // 调用 tool.register(api)
  previewDamage(),
  applyDamage(),
  restoreFeatures(ids),
  selectFeature(id),
  selectCharacter(id),
  planCharacterMove(characterId, destination, arrival?),
  commitCharacterMove(),
  enterBuilding(characterId, featureId),
  exitBuilding(characterId),
  undoScene(),
  destroy(),              // 保存并释放地图和事件监听
}
```

额外工具的最小接入方式：

```js
const myTool = {
  register(app) {
    const off = app.on('marker:create', event => {
      console.log(event.detail);
    });
    // 插件自身销毁时调用 off()
  },
};
```

当前常用事件包括标记和范围事件，以及 `character:create`、`character:select`、`character:update`、`character:delete`、`character:move-preview`、`character:move`、`character:exit-building`、`character:eject`、`state:import`、`state:migrate`、`scene:preview`、`scene:damage`、`scene:restore`、`scene:reset` 和 `scene:undo`。其中 `scene:reset` 与 `scene:undo` 是应用操作通知，不代表 SaveV2 中会新增同名 SceneEvent：重置会清空 `sceneEvents`，撤销会删除其最后一项。兼容旧版存档导入成功时，会在 `state:import` 前发送 `state:migrate`。

## 5. 坐标系统与几何约定

### 5.1 世界坐标

- 原点：地图左上角 `(0, 0)`。
- X 轴：向右增加。
- Y 轴：向下增加。
- 当前范围：`0 ≤ x ≤ 6000`、`0 ≤ y ≤ 5000`。
- 比例：`metersPerUnit = 1`，即一单位等于一米。
- 普通标记和路线节点必须位于底图范围内。
- 攻击范围的原点可以位于底图外，包括负坐标；只有与底图对象相交的部分会产生破坏。

### 5.2 Leaflet CRS.Simple 转换

Leaflet 的纬度方向与 SVG 的 Y 方向相反，因此必须用地图高度翻转：

```js
worldToLatLng({ x, y }, height)
// => { lat: height - y, lng: x }

latLngToWorld({ lat, lng }, height)
// => { x: lng, y: height - lat }
```

当前地图高度为 5000，因此：

```text
世界坐标 (100, 100)     → Leaflet (lat: 4900, lng: 100)
世界坐标 (6000, 5000)   → Leaflet (lat: 0, lng: 6000)
```

地图 SVG 的 `viewBox` 固定为：

```html
<svg viewBox="0 0 6000 5000">...</svg>
```

不要在新地图包里省略高度参数或直接把 `y` 当作 Leaflet `lat`，否则点击位置、缩放、范围方向和测距会发生上下镜像。

### 5.3 距离、朝向与矩形原点

- 距离使用欧氏距离：`hypot(dx, dy) × metersPerUnit`。
- 朝向 `0°` 指地图上方。
- 朝向顺时针增加：`90°` 向右，`180°` 向下，`270°` 向左。
- 圆形原点是圆心。
- 扇形原点是扇形尖端，`headingDeg` 是扇形中线。
- 矩形原点是近端边的中点，`length` 沿朝向向前延伸，`width` 向两侧各延伸一半。
- 吸附支持 `1/5/10/20` 米；`null`、`'free'` 或 `0` 表示自由位置。默认值为 5 米。

## 6. 核心数据契约

以下字段是当前代码实际读取、校验和导出的稳定契约。建议新增字段时保持向后兼容，避免重命名现有字段。

### 6.1 MapPackage

```js
const mapPackage = {
  id: 'unique-map-id',
  title: '地图界面标题',
  name: '地图名称',
  version: '1.0.0',
  period: '时代说明',

  width: 6000,
  height: 5000,
  metersPerUnit: 1,
  viewBox: '0 0 6000 5000',
  initialView: [minX, minY, maxX, maxY],

  defaultPreferences: {
    snapMeters: 5,
    gridVisible: true,
  },

  layers: [
    'base', 'liquid', 'destructible', 'damage', 'flood', 'labels',
  ],

  features: [],
  liquidBodies: [{ id: 'river', name: '黄河', polygon: [[x, y], ...] }],
  destructibleCategories: ['building', 'wall', 'vegetation', 'bridge', 'terrain'],
  roadRules: {},
  roadBuffers: [],
  navigation: {
    cellSizeMeters: 10,
    roads: [{ id: 'road-1', kind: 'major', points: [[x1, y1], [x2, y2]] }],
    gateways: [{ id: 'gate-1', polygon: [[x, y], ...] }],
    bridgeFeatureIds: ['bridge-1'],
  },
  floodRules: {
    maxInflowGapMeters: 12,
    inletWidthMeters: 6,
    propagationGapMeters: 1,
  },

  createSvg() {
    return '<svg viewBox="0 0 6000 5000">...</svg>';
  },
};
```

必需项是稳定的 `id`、`version`、正数 `width/height` 和 `createSvg()`。若 `features` 为空或未提供，普通标记、测距与攻击范围显示仍可使用，但场景破坏没有目标，界面应视为不可用。

兼容别名：状态模块也能从 `mapId`/`mapVersion` 或 `manifest` 中读取元数据，但新地图包应统一使用顶层 `id` 与 `version`，减少维护分支。

### 6.2 Marker

标准化后的标记结构：

```js
{
  id: 'marker-001',
  name: '北门集合点',
  x: 3365,
  y: 1545,
  color: '#3498db',
  visible: true,
}
```

规则：

- ID 必须唯一、非空，不能使用 `__proto__`、`prototype` 或 `constructor`。
- 名称最长保留 80 个字符，显示时必须继续使用 `textContent` 或安全文本节点。
- 颜色只接受六位十六进制格式，例如 `#3498db`。
- 坐标必须是有限数字，并且位于地图范围内。
- 删除标记时要同步解除或处理攻击范围对该标记的绑定。

批量框选与删除由两个可复用纯函数支撑：

```js
const ids = markerIdsInBounds(markers, dragStart, dragEnd);
const result = removeMarkers(state, ids);
```

- `markerIdsInBounds()` 位于 `geometry.js`，接受任意拖动方向，矩形边界按包含处理。
- `removeMarkers()` 位于 `state.js`，一次性返回新状态、被删标记及原索引、被解除绑定的范围快照。
- 被删标记所绑定的范围会冻结在标记删除瞬间的位置并改为 `anchor.type = 'free'`；单个或框选批量删除的 UI 撤销可按原索引和原绑定恢复。
- 此状态操作明确复用原 `sceneEvents` 引用，不修改、不筛选也不生成场景事件。清空全部同样必须走这条隔离路径，不能把“删除玩家标记”实现成清空整个 SaveV2。
- 互斥工具名为 `marker-select`。进入后关闭地图拖动，在 Leaflet `selectionPane` 绘制选框；只有 `Delete` 会执行批量删除，`Esc` 退出。名称/颜色输入框和确认弹窗打开时，地图快捷键不处理按键。

### 6.2.1 Character

```js
{
  id: 'character-001',
  name: '韩守忠',
  color: '#3d9b63',
  avatarDataUrl: null,
  visible: true,
  location: { type: 'map', x: 2795, y: 1755 },
  // 或 { type: 'building', featureId: 'barracks-03' }
}
```

- 头像源文件只接受 PNG、JPEG 或 WebP，源文件不超过 5 MB；运行时居中裁为 `128×128` WebP，单张不超过 96 KB、总量不超过 3 MB。
- 无头像时使用姓名首字和角色颜色。地图头像固定 34px，选中时固定 42px。
- 建筑内角色不绘制地图头像，列入建筑详情的内部角色名单；建筑整毁时移动到入口外最近安全格。
- 角色不会被攻击自动删除、受伤或击杀，本版本只维护位置、移动和疏散。

### 6.3 AttackArea

标准化后的攻击范围：

```js
{
  id: 'area-001',
  name: '火攻范围',
  shape: 'circle',              // circle | sector | rectangle
  origin: { x: 3100, y: 2200 },
  anchor: {
    type: 'free',               // free | marker | character
    markerId: null,             // type=marker 时必填
    characterId: null,          // type=character 时必填
  },

  radius: 100,                  // 圆形使用
  range: 200,                   // 扇形使用
  angleDeg: 60,                 // 扇形使用，必须 >0 且 ≤359
  length: 300,                  // 矩形使用
  width: 80,                    // 矩形使用
  headingDeg: 0,                // 规范化到 0..359

  color: '#c00000',
  opacity: 0.18,                // 0..1
  visible: true,

  destructionEnabled: false,
  severeDamage: false,
  craterEnabled: false,
  destructionTargets: ['building', 'wall'],
}
```

规则：

- 所有尺寸必须是正的有限数字。
- 当前存档校验的单个尺寸上限是 `max(width, height) × 4`；兰州地图为 24000 米。
- 攻击范围原点不限制在底图内。
- 绑定标记或角色时，范围显示使用锚点实时坐标；建筑内角色以建筑中心作为锚点。提交破坏时会把已解析坐标写入快照并解除快照中的绑定。
- “严重破坏”会自动启用弹坑，但随后可以单独关闭；只有 `craterEnabled` 为真时事件才冻结 `craterPolygon`。
- 修改、移动、删除原攻击范围，不会改变已经提交的破坏事件。
- 支持的输入别名仅用于兼容：`fan/cone → sector`，`rect/box → rectangle`。新代码应写标准名称。

### 6.4 SceneFeature

地图包中每个可破坏对象都需要稳定 ID、类别、命中几何和对应 SVG 图组：

```js
{
  id: 'granary-01',
  name: '仓廪 1',
  category: 'building',
  subtype: 'granary',
  importance: 'secondary',      // primary | secondary | detail
  mode: 'object',                // object | clip
  geometry: {
    type: 'polygon',
    points: [
      [x1, y1],
      [x2, y2],
      [x3, y3],
    ],
  },
  center: [cx, cy],
  details: {
    use: '历史用途或游戏用途说明',
    structure: '建筑结构与材料说明',
    description: '复原依据或主持信息',
  },
  enterable: true,
  entrance: [x, y],
  minCoverage: 0.95,      // object 类整毁阈值：足迹覆盖 ≥95% 才整毁，否则局部破坏
  ruinStyle: 'timber-earth',
  roadOverlapAllowed: false,
  severeOnly: false,      // true 时仅“严重破坏”攻击参与命中（如基础地表）
}
```

对应 SVG：

```html
<g
  id="feature-granary-01"
  data-feature-id="granary-01"
  data-category="building"
  data-subtype="granary"
  data-mode="object"
  class="destructible"
>
  ...对象的矢量图形...
</g>
```

若有固定地图标签，可增加：

```html
<g data-label-for="granary-01">...</g>
```

对象被整毁时，引擎会隐藏完整状态和关联固定标签，并生成通用废墟。玩家标记是独立图层，不会跟随隐藏。

`name` 是地物检查面板使用的公开名称。检查工具不绑定 SVG 事件，而是把点击位置转换为地图坐标，再用 Feature 几何执行点中多边形测试；重叠对象先按 `importance` 降序，再按足迹面积升序选择。当前只允许直接检查建筑、墙体、植被和桥梁，基础地表不会拦截点击。

建筑 `details` 为主持人详情面板的公开资料；`entrance` 位于足迹外最近可行走位置。完整或局部破坏建筑只要入口可达即可进入，整毁建筑不可进入。选中轮廓、场景记录高亮和预览目标高亮绘制在运行时 `#layer-inspection` 中，位于标签层下方。它们在缩放、拖动、撤销、恢复和导入后重新派生，不加入 SaveV2，也不能直接摧毁对象。精确恢复必须调用既有 `commitRestoreEvent()`，因此保持线性撤销语义。

当前规范类别：

- `building`：建筑、院落核心屋体、官署、仓廪等。
- `wall`：城墙、城门、关墙等；这类对象永远只局部破坏（即使 `mode` 为 `object` 也会被归为局部裁切）。
- `vegetation`：作为独立对象的树木。
- `bridge`：桥体。
- `terrain`：允许局部破坏的地表对象，通常使用 `clip`；`severeOnly: true` 的地表仅在“严重破坏”开启时命中。

道路、水体、地图文字和坐标基础层默认受保护，不应进入 `destructibleCategories`。若未来确实允许破坏，必须先定义明确的 SceneFeature、视觉恢复方案和测试，而不能只把类别名称加到列表里。

兰州地图中的 `chenghuang-temple-compound` 是一个独立 `building/temple` 对象，中心约为 `(3080, 2060)`。它替换了原地的 `market-shop-04`，而不是叠加在店铺上；SVG 包含南向庙门、前院、香炉、侧廊、正殿和后部小房，固定标签通过 `data-label-for` 随建筑破坏状态显隐。

地图包已移除史料考据内容（A/B/C 圆标、图例、`sources`、`evidenceScale`、`confidence` 元数据）。历史资料只保留在工程留痕目录，作为制作参考；新地图包也不需要提供这些字段。

### 6.5 SceneEvent

`sceneEvents` 是当前有效场景操作的有序记录栈。持久化的 SceneEvent 只有 `damage` 和 `restore` 两种结构；破坏与指定恢复会追加到栈尾，撤销与重置则直接改变这个数组。

破坏事件：

```js
{
  id: 'scene-000001',
  type: 'damage',
  createdAt: '2026-08-07T12:00:00.000Z',
  areaSnapshot: { /* 标准化且解除标记绑定的 AttackArea */ },
  objectIds: ['building-01'],
  clipHits: [
    {
      featureId: 'city-wall-north',
      polygon: [{ x, y }, { x, y }, { x, y }],
    },
  ],
  craterPolygon: [{ x, y }, { x, y }, { x, y }], // 仅显式弹坑
}
```

指定恢复事件：

```js
{
  id: 'scene-000002',
  type: 'restore',
  createdAt: '...',
  featureIds: ['building-01', 'city-wall-north'],
}
```

操作规则：

- “撤销最近事件”删除 `sceneEvents` 的最后一项，并从剩余记录重新派生场景；一次只删除一项，不生成 `type: 'undo'` 记录。
- 如果最后一项是 `restore`，撤销会删除该恢复记录，被它恢复且仍有较早破坏来源的对象会再次显示为被毁。
- “重置场景”把 `sceneEvents` 直接替换为空数组，同时清除全部破坏结果；不生成 `type: 'reset'` 记录，也不保留可供场景撤销恢复的旧历史。
- 重置属于不可撤销的场景格式化操作。若要保留重置前状态，调用方应先导出 SaveV2 或建立应用外备份。
- 事件 ID 在单个存档当前保留的 `sceneEvents` 中必须唯一。

### 6.6 SaveV2

持久化结构：

```js
{
  saveVersion: 2,
  mapId: 'northern-song-lanzhou-1104',
  mapVersion: '1.0.5',
  markers: [/* Marker[] */],
  characters: [/* Character[] */],
  attackAreas: [/* AttackArea[] */],
  sceneEvents: [/* SceneEvent[] */],
  preferences: {
    snapMeters: 5,
    gridVisible: true,
  },
}
```

导入会严格校验：

- `saveVersion` 必须为 2；SaveV1 先迁移为 SaveV2，角色数组默认为空，旧地表命中会转换为稳定弹坑几何。
- `mapId` 必须与当前地图包一致；`mapVersion` 可以是当前版本或 `compatibleMapVersions` 声明的兼容旧版本，旧版本会先迁移再校验。
- 标记、角色和范围 ID 必须分别唯一。
- 绑定范围引用的标记必须存在。
- 场景事件引用的 Feature ID 必须存在。
- 建筑内角色引用必须指向可进入建筑；角色锚点引用的角色必须存在。
- 数值必须有限，尺寸、角度、透明度和标记边界必须合法。
- 对象不能包含危险原型键或非 JSON 安全值。
- 名称被当作普通文本，颜色只能是六位十六进制。
- 导入文件不超过 5 MB；标记、范围、事件、引用和多边形点数都有明确上限。
- 浏览器自动存档迁移前先写入版本化备份；备份或正式写入失败时暂停自动保存。

因此，哪怕只是地图包内容调整，只要会让旧存档中的对象 ID 失效，就应提高 `mapPackage.version`，并按需要编写显式迁移器；不要静默复用已改变语义的 ID。

## 7. 兰州地图的道路宽度与禁建缓冲

配置位于 `src/maps/lanzhou.js`：

```js
export const ROAD_RULES = {
  widthsMeters: {
    major: 12,
    secondary: 7,
    alley: 3,
    country: 8,
  },
  setbacksMeters: {
    building: 3,
    streetShop: 1.5,
  },
};
```

当前普通建筑道路缓冲总宽度按“道路宽度 + 两侧各 3 米退界”生成：

| 道路类型 | 路面宽度 | 普通建筑缓冲总宽 | 代码中的 `bufferWidth` |
| --- | ---: | ---: | ---: |
| 主街 | 12 m | 18 m | 18 |
| 次街 | 7 m | 13 m | 13 |
| 巷道 | 3 m | 9 m | 9 |
| 城外道路 | 8 m | 14 m | 14 |

道路中心线采用三次贝塞尔曲线描述。`createRoadBufferFeatures()` 会对每段曲线采样，并为相邻采样点生成旋转矩形缓冲片段，最终导出到 `roadBuffers` 供测试使用。

建筑布置的验收规则：

- 所有普通 `building` 多边形与任一道路缓冲多边形的正面积交集必须为 0。
- 建筑之间的正面积交集必须为 0。
- 允许跨街的城门、桥梁或门楼必须显式设置 `roadOverlapAllowed: true`。
- 当前唯一许可对象是 `yamen-gate`，且 SVG 中必须有可见的 `gate-opening` 通行孔。
- 不要通过降低浮点阈值或删除测试来“解决”占道；应修改建筑足迹、道路曲线、缓冲宽度或明确许可结构。

临街商铺的 1.5 米退界已经作为规则元数据保留。若后续要让测试按建筑 subtype 分别应用 1.5/3 米退界，应为道路缓冲生成器增加不同 setback 版本，并在测试中按 `subtype` 选择，而不是修改现有普通建筑缓冲的含义。

## 8. 如何制作一张新地图包

### 步骤 1：建立独立地图模块

复制结构，不要复制通用工具逻辑。例如新建：

```text
src/maps/new-city.js
```

导出：

```js
export const newCityMapPackage = { ... };
```

### 步骤 2：确定坐标与尺寸

- 选择世界宽、高和 `metersPerUnit`。
- 推荐继续使用左上原点、Y 向下，与 SVG 原生坐标一致。
- SVG `viewBox`、MapPackage `width/height` 与所有 Feature 坐标必须一致。
- 初始视图写成 `[minX, minY, maxX, maxY]`。

### 步骤 3：按层生成 SVG

推荐维持以下图层 ID（自上而下）：

```text
layer-base          // 基底地图：纸张、山体、城基、遗迹、道路、地块、静态植被
layer-liquid        // 液体：黄河等静态水体
layer-destructible  // 全部可破坏对象图组
layer-damage        // 破坏痕迹（引擎运行时填充）
layer-flood         // 漫灌水体（引擎运行时填充）
layer-labels
```

图层可以按新地图需求增减，但每个 `layers` 条目都应与 SVG 中的 `id="layer-{name}"` 对应；`#layer-damage` 与 `#layer-flood` 必须位于 `#layer-destructible` 之后、`#layer-labels` 之前，破坏与漫灌才能盖住破口。纹理优先使用轻量 SVG `pattern`、渐变和滤镜；确需栅格质感时，只允许低体积本地 WebP，并通过地图包 `artAssets` 注入。

1.0.12 的普通建筑素材通过冻结的 `artAssets.buildingSprites` 注入，九组键为 `yamenGate`、`yamenSideHall`、`barracks`、`granary`、`stable`、`workshop`、`marketShop`、`residenceHouse` 和 `residenceCourtyard`，值均为 URL 数组。地图渲染按 `category + renderType` 选择组，并用 Feature ID 的 FNV-1a 哈希稳定选择数组下标。默认 `lanzhouMapPackage` 的九组数组均为空，因此仍不含 `<image>`、Data URL 或外部资源。

### 步骤 4：建立道路中心线、宽度和缓冲

- 把道路视觉路径和碰撞中心线放在同一数据源或由同一参数生成，避免二者漂移。
- 按路面宽度和建筑退界生成 `roadBuffers`。
- 在测试中验证建筑零占道。
- 城门、桥梁等许可对象必须有真实通道，并显式标记例外。

### 步骤 5：定义可破坏对象

- 每栋建筑、独立树木、桥梁和墙段都要有唯一且长期稳定的 ID。
- 碰撞几何应是对象真实足迹，不是标签包围盒或装饰阴影。
- 普通建筑用 `mode: 'object'`。
- 连续城墙、可裁切地表用 `mode: 'clip'`。
- SVG 图组 ID 必须与 Feature ID 对上：`feature-${id}`。
- 固定标签用 `data-label-for` 关联。

### 步骤 6：设置破坏白名单

只把确实定义了 Feature 和恢复视觉的类别加入：

```js
destructibleCategories: ['building', 'wall', 'vegetation', 'bridge', 'terrain']
```

如果地图不需要破坏，提供空 `features` 即可，其他通用工具仍可工作。

### 步骤 7：切换入口并验证

在 `src/main.js` 中改为导入新地图包，然后运行：

```powershell
npm.cmd test
npm.cmd run build
```

建议把兰州地图包测试抽象为可复用的“地图包契约测试工厂”，让每张新地图自动检查图层、ID、SVG 自包含、对象重叠和道路碰撞。

## 9. 破坏命中规则与事件派生

### 9.1 范围多边形

`attackAreaToPolygon()` 把圆、扇形和旋转矩形离散成闭合多边形：

- 圆形默认使用 72 段。
- 扇形根据夹角分配弧段，尖端包含在多边形中。
- 矩形按近端边中点、长度、宽度和朝向计算四角。

这些多边形在任意 Leaflet 缩放下仍使用世界坐标，因此显示尺寸、测距和命中结果不会随屏幕缩放改变。

### 9.2 object 命中

普通对象（建筑、树木、桥梁）的规则为：

```text
攻击范围与对象足迹有正面积交集 → 命中
且
攻击范围与对象足迹的交集面积 / 对象足迹面积 ≥ 0.95 → 整对象被毁（objectIds）
否则（0 < 覆盖 < 0.95）→ 只局部破坏被覆盖部分（clipHits）
```

当前公开地图对象的 `object` 整毁阈值统一为 `0.95`，不再使用中心命中判定。因此：

- 任意正面积相交都会命中并产生局部破坏（烧蚀、缺口或局部坍塌）。
- 覆盖达到 95% 及以上才整对象倒塌。
- 对象中心命中但覆盖不足时，只局部破坏，不会整毁。

整毁对象不会从源 SVG 删除。场景渲染会给源图组增加 `scene-destroyed`，隐藏关联固定标签，并根据足迹生成瓦砾、断木或桥体残骸。

`wall`/`gate`/`pass-wall`/`pass-gate`/`terrain` 类别即使 `mode` 为 `object`，也一律归为局部裁切，不会整毁。

### 9.3 clip 命中

`clip` 对象只要存在正面积交集就会命中。破坏事件保存“应用瞬间的攻击多边形”，渲染时：

- 用 SVG `mask` 从完整墙体或地表中裁掉覆盖部分。
- 用 Feature 足迹 `clipPath` 限制破损材质。
- 城墙显示瓦砾缺口；地表显示深色烧蚀、碎石或弹坑区域。
- 多次攻击保留多个 clip hit，由事件派生结果共同渲染。

### 9.4 预览和提交

`createDamagePreview(area, features, categories)` 的返回值包括：

```js
{
  areaId,
  areaSnapshot,
  categories,
  objectIds,
  clipHits,
  featureIds,
  counts,          // 分类数量
  hits,            // coverage/centerHit/intersectionArea 等诊断信息
}
```

预览只高亮命中对象，不修改场景事件。`commitDamageEvent()` 仅在确认应用时追加事件；如果 `objectIds` 与 `clipHits` 都为空，则返回原 state，不生成空事件。

`AttackArea.severeDamage` 为 true 时，`severeOnly: true` 的 `ground-terrain` 等特征也会进入 `clipHits`，渲染层会在地面叠加弹坑（`#layer-damage`），不会改动基底图层。

### 9.5 事件派生

`deriveSceneState(sceneEvents)` 每次从当前仍保留的场景记录栈重放，输出：

```js
{
  destroyedObjectIds,
  clipHits,
  damagedFeatureIds,
  activeSceneEventIds,
}
```

重放语义：

1. `damage` 增加整毁对象来源或裁切命中。
2. 重叠的 `damage` 可以同时作用于同一对象；整毁对象只显示一份废墟。
3. `restore` 清除指定对象当前累积的整毁和裁切来源。
4. 撤销不参与重放：它在调用 `deriveSceneState()` 之前就已删除数组最后一项；如果删掉的是 `restore`，更早的破坏来源会重新生效。
5. 重置也不参与重放：它直接令输入数组变为 `[]`，因此派生结果为空，并且不存在“撤销 reset 后恢复旧破坏”的路径。

不要在 UI 中直接改 `destroyedObjectIds` 或 SVG class 来保存结果；权威数据始终是 `sceneEvents`，DOM 只是派生视图。

### 9.6 液体倒灌派生

`deriveFloodRegions(scene, liquidBodies, features, floodRules)` 返回 `{ sourceBodyId, kind, eventId, polygon, flowLine? }`；`deriveFloodPolygons()` 保留为只返回多边形的兼容包装。

判定规则：

1. 旧式 `clipHits` 与整毁对象足迹仍按“与液体重合面积占候选面积 >1%”直接进水。
2. 显式 `craterPolygon` 与水体相交时直接进水；未相交但最近距离不超过 12 米时，尝试生成约 6 米宽的入水沟。
3. 连接沟不得穿过当前仍完整的建筑或墙体；最短连接被挡后尝试其他边界点，无有效连接则不进水。
4. 已进水弹坑可向相交或 1 米容差内接触的弹坑传播，但不会再次跨越 12 米跳跃。
5. 新事件先播放约 550ms 入水沟，再显示约 450ms 坑内积水；导入、刷新和缩放只渲染静态终态。

弹坑随对应 damage 事件撤销或场景重置移除；恢复建筑不会填平弹坑。`#layer-flood` 完全由场景事件重放派生，不增加单独存档字段。

### 9.7 角色导航

`createNavigationGrid()` 以 10 米网格缓存道路和静态地形，再叠加建筑、完整城墙、河流、积水、弹坑及桥梁破坏。城门通道和完整浮桥可通行；墙体整毁或局部缺口会开放对应格。

`findNavigationPath()` 使用 EasyStar A*，道路代价 1.0、普通地面 1.7，允许对角移动但禁止穿角。点击障碍时先在 30 米内寻找最近可行走格；每帧分批计算，找不到路线时保持角色原位。攻击、恢复、撤销、重置和导入后会使动态网格缓存失效。

## 11. 常见扩展点

### 11.1 增加新的地图

新增 `MapPackage` 并在 `src/main.js` 切换即可。若主持人应用需要多地图选择，可建立地图注册表：

```js
const mapPackages = new Map([
  [lanzhouMapPackage.id, lanzhouMapPackage],
  [newCityMapPackage.id, newCityMapPackage],
]);
```

切图前调用旧应用实例的 `destroy()`，再用新容器或清空后的容器创建实例。存储键包含地图 ID，因此不同地图不会混用自动存档。

### 11.2 自定义存储

主持人应用可把 `storageAdapter` 替换为 IndexedDB、桌面应用文件接口或服务器同步层。适配器内部仍应保存 `exportSave()` 返回的完整 SaveV2 JSON，并处理写入失败、配额和冲突。当前 localStorage 键继续保留 `:v1` 后缀，以便原位读取并迁移既有 SaveV1，而不是另开键导致旧存档失联。

### 11.3 添加工具插件

通过 `tools` 或 `registerTool()` 订阅应用事件。若需要真正加入新的互斥地图操作模式，应扩展 `app.js` 的工具状态机和 UI；不要只监听地图 click，否则可能与标记、测距或攻击放置同时触发。

### 11.4 新攻击形状

需要同步修改：

1. `state.js` 的 `normalizeAttackArea()` 形状白名单和字段校验。
2. `geometry.js` 的 `attackAreaToPolygon()`。
3. `app.js` 的编辑器、放置流程和拖动手柄。
4. SaveV2 测试、SaveV1 迁移、旋转/边界命中测试和导入导出测试。

只要最终稳定转换为世界坐标多边形，现有 object/clip 命中和场景事件逻辑可以复用。

### 11.5 伤害、材质与生命值

当前一次确认即按规则破坏，没有生命值、材质抗性、距离衰减或物理坍塌。后续增加时建议：

- 给 SceneFeature 增加可选 `material`、`maxHp`、`resistance`。
- 给 damage event 增加版本化、不可变的伤害参数快照。
- 仍通过事件重放派生当前 HP 和外观。
- 不要把动态 HP 写回 MapPackage 或源 SVG。
- 继续维护 SaveV1 到 SaveV2 的显式迁移，不要让旧事件语义随代码更新改变。

### 11.6 路径规划和碰撞

当前道路缓冲只用于制图验收，不是运行时寻路网格。若增加角色移动：

- 单独定义通行图、门洞连接和动态障碍层。
- 场景破坏的墙体缺口应投影到导航数据。
- 不要直接从 SVG 视觉线条猜测可通行性。

### 11.7 专用废墟变体

当前运行时能根据足迹生成通用瓦砾。要实现专用废墟，可在 MapPackage 中增加可复用模板或 `renderRuin(feature, eventState)` 回调，并保留通用废墟作为缺省路径。模板 ID 必须与 Feature ID 解耦，避免多个对象引用同一 SVG ID。

## 12. 修改注意事项与发布纪律

### 12.1 稳定 ID 与存档兼容

- Feature、Marker、AttackArea 和 SceneEvent 的 ID 均参与引用。
- 已发布地图不要随意重命名或复用 Feature ID。
- 删除 Feature 会让包含该引用的旧存档导入失败。
- 地图语义或几何发生不兼容变化时，提高 `mapPackage.version`。
- 若要继续支持旧存档，先编写显式迁移，再调用 `validateAndNormalizeSave()`。

### 12.2 安全输出

- 用户名称只用 `textContent`，不要拼入 `innerHTML`。
- 不要放宽颜色为任意 CSS 字符串；当前仅接受 `#[0-9a-fA-F]{6}`。
- JSON 导入必须通过 `validateAndNormalizeSave()`，不能直接赋给内部 state。
- 保留对非有限数、危险键、重复 ID、未知引用和嵌套过深的拒绝。

### 12.3 几何一致性

- SVG 视觉足迹、SceneFeature 碰撞足迹和道路缓冲应来源一致。
- 对象阴影、屋檐装饰和文字不应扩大命中几何。
- 多边形点序可顺时针或逆时针，但不能自交，至少要有三个有效点。
- 浮点误差判断由几何模块统一处理；不要在各 UI 分支重复实现命中算法。

### 12.4 性能

- 避免把数万个纹理点写进 SVG。
- 使用 `pattern`、渐变和少量滤镜表达材质。
- 大量 Feature 时，应先加空间索引或包围盒粗筛，再进行 polygon-clipping 精确相交。
- 圆形分段数影响平滑度与计算量；默认 72 段适合当前地图，不要无依据放大到数百或数千段。

### 12.5 离线约束

- 不使用 CDN、在线字体、远程图片、在线瓦片或运行时 fetch。
- 新增字体、图标或素材时必须可内联且确认授权和体积。
- 每次构建后检查地图 SVG 中无 `<canvas>`、外部资源引用或栅格底图；允许的 `<image>` 仅限 `artAssets` 注入并由生产入口显式导入的本地 WebP。确认成品没有外链脚本、外链样式或网络素材请求。

### 12.6 源文件与构建产物

- 修改 `src/`，不要手工编辑 `dist/index.html`。
- 保留 `package-lock.json`，确保后续构建版本一致。
- 原始 `北宋兰州城_v2 (1).html` 是参考记录，除非明确决定淘汰，不应覆盖。
- 发布包应同时保留使用说明、本文、源代码、测试和最终离线 HTML，便于主持人直接使用并支持后续维护。
