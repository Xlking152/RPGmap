# RPGmap v3.0.0 实施与验收任务书

本文是可独立交给开发者或编码代理执行的任务说明。用户已于 2026-10-13 授权实施；实施进度、验证结果与未执行项另行记录，不把计划内容视为已完成的能力。

## 1. 目标、版本与不可回退约束

最终应用版本为 **v3.0.0**，候选版本依次使用 `3.0.0-rc.1`、`3.0.0-rc.2`。应用、地图、规则及存档格式分别管理版本。

基线为 `v2.5.5`，提交 `9fdcbc09e0ae1bd992ce02e0aad1b79dbd544dd5`；World schema 4；无限规则 `infinite-horror@1.1.0`；兰州地图 `northern-song-lanzhou-1104@1.1.0`。兰州内容和行为保持，归档格式单独使用版本 1。

最终目标：

1. 代码按整体、运行、规则、地图四个主层组织。
2. Windows 安装版自带运行环境，用户无需安装 Node.js。
3. 启动器与兰州地图独立打包，放在同一个交付目录。
4. 兰州是可导入、可卸载的推荐地图，启动器不依赖它才能启动。
5. 通过正式导入流程实现与 v2.5.5 对等的兰州游玩能力。
6. 同一 World 可拥有使用不同地图包的多个 Scene，正确切换、保存、恢复。
7. 更新保留存档和内容包，只清理旧程序文件。
8. 提供范围明确、具有恢复点的环境恢复及场景清空。

保留米制坐标、World 权威模型、Actor/Token 实例隔离、Document 操作、权限裁剪、WAL、幂等和断线恢复。兼容旧存档，不要求 2.5.5 与 3.0.0 网络客户端混用。不得通过放宽权限、跳过碰撞、移除行为测试或静默重置存档取得验收通过。

完整 DND/COC、插件市场、在线自动更新、完整制图软件和玩家各自独立活动场景不属于本轮。

## 2. 四层架构与内容接口

| 层级 | 职责 |
| --- | --- |
| 整体层 | 桌面启动、管理首页、游戏 UI、包管理、设置和系统装配 |
| 运行层 | 场景状态、交互、移动、导航、视野、破坏几何和渲染调度 |
| 规则层 | 角色私有数据、伤害恢复、状态、行动能力、消耗和展示描述 |
| 地图层 | 画面、地物几何、物理属性、初始声明和资源绑定 |

规则与地图是运行层接入的并列模块。共享契约、存储及网络适配作为支撑，不另增业务层。核心不依赖 DOM、UI 或具体地图；整体层使用创建/销毁、命令、只读查询及订阅接口。规则实例按 World 上下文注入，逐步消除全局当前规则依赖。UI 不直接改写 World。

### 地图格式

`.rpgmap` 本质为 ZIP，包内根目录包含：

```text
manifest.json    身份、版本、兼容要求、文件清单与校验
map.json         地物、几何、物理属性及初始状态
map.svg          分层画面，通过地物 ID 对应数据
assets/          实际引用的图片等资源
preview.webp     可选预览
README.md        可选说明
```

一个包是一张地图模板，可创建多个 Scene。包不包含角色、Token、探索、战斗或进度，不执行制图脚本。使用统一米制坐标；保留稳定 feature ID、整体/局部破坏方式、navigation 阻挡/高度/破坏后通行、vision 遮挡/高度、门初始状态及宿主、ruinStyle 和素材绑定。

外观、移动阻挡与视线轮廓可以不同。宿主建筑必须留出门洞。原物体、破坏遮罩和废墟使用同一 ID，不创建第二个实体。可破坏画面需独立建筑图层或地面修补素材；不能靠给扁平 PNG 加属性自动还原拆除后的地面。

### 数据归属

| 数据 | 保存位置 |
| --- | --- |
| 原始建筑、默认门状态、物理属性及素材绑定 | 只读地图包 |
| 当前门状态、GM 临时地物及遮挡覆盖 | Scene |
| 破坏、恢复、撤销 | Scene 事件 |
| Token、实例状态、历史探索 | Scene 存档 |
| 导航索引、剩余几何和当前可见性 | 可重建缓存 |

制图修改导出地图版本；游玩状态不写回地图包。规则专属伤害、生命或抗性公式由规则层负责。

### 安装及版本

导入顺序固定为读取清单、展示信息、完整校验、暂存、原子安装、注册。检查资源、重复 ID、有效几何、门宿主、废墟绑定、路径和 SVG，禁止地图脚本。

按 ID＋版本索引：同版本同内容复用，同版本不同内容拒绝；多版本并存；World 固定规则版本，Scene 固定地图版本；安装不自动迁移引用。卸载检查 World/Scene/系统恢复点，显示引用清单并阻止删除被使用版本，不自动删除存档。卸载兰州后程序更新不复装。

规则包扩展名 `.rpgrules`，包含清单、契约信息、入口、资源及迁移声明；用于受信任的本项目契约扩展，不保证任意第三方代码的沙箱安全或 FVTT 格式兼容。迁移无限并提供最小第二规则验证解耦。

## 3. 桌面、更新、多地图与重置

使用 Electron 与 electron-builder/NSIS 生成 Windows x64 安装器，锁定依赖和构建环境。GM 从桌面进入管理首页，再启动 World；玩家浏览器加入。预加载只暴露限定桌面功能。单实例；退出停止新写入、完成持久化并关闭服务。

无地图也能进入管理首页，导入后创建可运行场景。安装器不得包含用于运行的兰州几何、SVG、贴图或备用副本。预设通过同目录独立 `.rpgmap` 提供，走通用导入流程。

用户数据默认 `%LOCALAPPDATA%/RPGmap/UserData`：World、权限、WAL、包、上传、备份、配置及日志。安装目录仅程序文件。旧 map/ 导入复制校验，成功前保留原目录；浏览器离线存档显式导入。

新版安装校验、停服、暂存、替换、检查及清理；只删除安装清单管理的旧文件。迁移先备份，在副本校验完成后切换；失败保留原数据；回退检查数据兼容。首版使用本地新版安装器覆盖更新。

### 多地图

一个 World 绑定规则、拥有多个 Scene，每个 Scene 绑定地图版本。支持创建、切换、返回及恢复，GM 切换后玩家同步。共享 Actor，各 Scene Token/破坏/门/Fog 独立。首版只有一个共同活动 Scene，允许重建 Runtime，不自动搬运 Token。

服务端从已安装包读取完整地图；禁止仅尺寸降级代替物理地图。客户端和服务器必须同版本及指纹。切换和缓存区分 ID、版本、World/Scene 和计算版本；同 ID 不同版本重建；缺图明确拒绝；切换取消旧输入及任务，目标未就绪不能操作。

### 重置

| 内容 | 恢复地图环境 | 清空当前场景 |
| --- | --- | --- |
| 破坏、门、地物及遮挡覆盖 | 恢复固定地图初始声明 | 同左 |
| 历史探索 | 清除并重算现有 Token 当前视野 | 清除 |
| Token/实例状态 | 保留 | 清除 |
| 标记/范围 | 保留 | 清除 |
| 关联战斗 | 保留并更新空间派生结果 | 清除 |
| Scene 设置 | 保留 | 恢复默认 |

两者保留 Scene ID、名称、版本和 World 角色、模板、资料、聊天、其他 Scene。仅 GM 执行；确认范围并先建立可验证恢复点，失败不执行；原子提交后废弃旧任务/预览并同步。冲突 Token 标记供 GM 调整，不自动挪动。新增明确意图，旧 scene.reset 保留旧语义并退出正式 UI。

## 4. 实施顺序与仓库组织

1. 固定 2.5.5 行为、存档及性能基线。
2. 抽取运行核心、规则上下文、UI/环境适配，保持程序可运行。
3. 地图/规则包导出、校验、安装、版本注册，服务器外部地图加载。
4. 多地图及两种重置与恢复点。
5. 按真实依赖增量更新开门、破坏、恢复、撤销，减少重复扫描与全场景序列化。
6. 桌面管理、安装、旧数据导入及覆盖升级。
7. 用实际产物验收并整理交付证据。

代码按 app/runtime/contracts/adapters/具体规则组织。地图制作项目 maps/，公共素材 素材库/，现行规范与历史说明 文档/ 分开。素材索引记录稳定 ID、尺寸、用途、来源和废墟绑定，只导出依赖。兼容入口可转发，不能长期维护两份权威状态。

继续使用 Document changes 从提交前后推导影响范围。无关聊天/名称不重算空间；视野包括门后远处的影响，未知变化完整重建。Worker 校验 Scene 与计算版本。

## 5. 交付与验收

```text
RPGmap-v3.0.0-rc.1-验收/
  RPGmap-Setup-3.0.0-rc.1.exe
  北宋兰州城-1.1.0.rpgmap
  SHA256SUMS.txt
  使用说明.md
  验收报告.md
  验收附件/最小测试地图、最小测试规则、测试与性能证据
```

测试地图/规则使用其真实内容版本，不强行和应用同版。外层 ZIP 只用于传递，地图仍独立导入。正式交付不夹带开发日志、源码和测试；所有产物记录提交和 SHA-256，验收后不能换成未验证重建产物。

### 必须执行的场景

- 无系统 Node、源码及浏览器缓存环境：只安装启动器地图为空；正式导入兰州；建 World；重启恢复；移走原导入文件仍可用；无引用地图卸载，更新不复装。
- 与 2.5.5 对照：画面/标签/资源/坐标，放置/拖动/分段/群组移动，门/碰撞/高度 LOS，局部/完整破坏/废墟/恢复/撤销，灯光/Fog/运动，角色/生命/状态/战斗/聊天/资料，GM/Player/WAL/幂等/重连/重启。服务端判定必须实测。
- 同 World 兰州 A/B 与测试地图 C：A 改动不影响 B；切 C 再回 A 状态正确；玩家同步；重连/重启恢复活动 Scene；同 ID 两版本并存切换；跨地图相同地物 ID 不串状态。
- 真实旧存档副本导入、覆盖升级/中断/卸载重装、程序残留清理、内容及数据保留、缺包/不兼容/损坏/版本冲突、两种重置与恢复、重置后立刻移动/破坏/切图/重启、过期 Worker、重复启动和服务退出。
- 保留既有自动测试与性能门槛，应用 JS/CSS 与桌面运行库分开统计，原 ZIP 小体积门槛不套用到 Electron，但不能取消应用性能门槛。
- 记录启动/导入/加载/切换、更新范围/计算次数/p50/p95、内存、多人确认/广播/浏览器表现，以及版本/硬件/提交/产物哈希。

报告逐项列通过、失败、未执行。回环 LAN 不冒充 VPN 多机。候选完成后正式 3.0.0 产物需重新验证，不能只给 RC 改名。本任务不自动授权仓库合并或线上发布。
