# RPGmap 未来规划

当前开发基线：**v2.3.1**。

RPGmap 已完成 World-first、Ruleset/Actor Contract、Scene Feature State、通用多人 operation 与发布链收敛。后续开发必须保持以下边界：Core 提供能力，Ruleset 解释规则，MapPackage 描述地图内容，World 保存 Campaign 权威数据，Scene 保存地图实例与 Token。

## 一、v2.3.1 已具备的基础

- World schema 3、operation schema 2、Status schema 4、Access schema 4、Infinite Horror Ruleset `1.0.0`。
- 启动顺序为 World → Ruleset → Active Scene → MapPackage → Runtime。
- Actor 属于 World 并作为模板；Token 属于 Scene。怪物/NPC/召唤物强制为 Unlinked，生命、伤势、状态、资源和当前形态只保存在各自 `actorDelta`。
- `Scene.featureStates` 独立保存每个 Scene 的门、机关、阻挡高度和扩展状态。
- Actor、Token、Scene、Status、Effect、Chat、Health、Combat、Feature 与 Fog 的普通联机写入使用服务器权威 Operation V2 patch/changeSet，不发送整份 World。
- Local/LAN 逐会话生成 AudienceProjection；隐藏 Token 不会进入玩家快照、补丁、Combat、Chat、Effect、Status、Access 目录或查询结果。
- 每个 Player 会话使用一个受控 Token 的圆形实时视野；圆心跟随 Token 最新权威坐标，精确/模糊范围的 5 米网格探索历史按 Scene 和队伍持久化共享，GM 可重置或局部重新隐藏。
- Infinite Horror 提供精确/模糊侦测范围、感官能力、亮度降级和实例覆盖；模糊敌影使用 Session opaque ID，只投影匿名轮廓和量化位置。
- Actor 权限区分 NONE/LIMITED/OBSERVER/OWNER，并与 Token visibility、实例控制和视野授权分离。
- Actor Sheet V3 使用显式权限上下文、Play/Edit 边界和多窗口；GM 公共档案与按 Token 实例裁剪的 LIMITED 状态摘要已成为正式运行链路。
- Token 普通拖放、Ctrl/Cmd 分段路径、WASD 与群组移动共用同一权限、状态、逐段碰撞与 Combat Turn Lock 语义。
- Status V4 支持 Buff/Debuff/Neutral、快捷 HUD、白名单自定义定义和服务器权威 turns/rounds 持续时间。
- 兰州城通过 Built-in Registry 延迟加载；World Manager 首屏不静态加载 Leaflet、地图 CSS、地图逻辑、SVG 或数据资源。
- Windows 包使用严格白名单，只包含编译后的 `app/`、Local/LAN Server、空数据目录和操作指南。
- Candidate/Release 自动验证 audit、测试、tracked syntax、bundle budget、package manifest、ZIP 校验和、BAT、World Manager、逐用户权限投影、Fog Canvas、动态 Runtime、兰州 JSON/SVG 与 29 个 WebP。

## 二、下一优先级

### 1. External MapPackage 生命周期

- 定义可安装 manifest、资产目录、签名/校验和与安全限制。
- 支持 Registry discovery、安装、禁用、卸载和离线校验。
- 为 Scene pinning 建立 MapPackage 版本兼容、升级预览、迁移与回滚策略。
- 保持单一 Source of Truth；不得同时维护编译包与服务器 raw 地图的双写版本。

### 2. Server Multi-World Manager

- 服务器端 World catalog、创建、切换、归档和备份恢复。
- `/setup` 管理界面与权限隔离。
- 切换 World 时重新执行 World-first bootstrap，不在已加载 Runtime 中强行覆盖另一份 World。
- 明确数据根、上传资源和备份保留策略。

### 3. Asset Manager

- Actor/Token 图片、地图素材和用户上传文件使用稳定资产 ID，不继续扩大 data URL。
- 内容类型、大小、文件名、路径穿越和配额由服务器校验。
- World 只保存资产引用，删除资产前检查反向引用。

### 4. External Ruleset Package

- Ruleset manifest、版本依赖、安装/升级/隔离和兼容检查。
- 用不包含 Health、Forms 或 Infinite Horror 字段的第二 Ruleset 持续验证 Contract。
- 未知或不兼容 Ruleset 继续明确失败，不允许静默回退到 Infinite Horror。

## 三、Feature 与权限

当前 Feature State 修改保持 GM-only。Player 交互必须在服务器 operation 层增加权限，不得只隐藏前端按钮。

计划能力：

- `permissions.interactFeatures`，并细分 open、close、activate、use。
- locked、secret、GM-only 与探索状态。
- Server 按身份过滤秘密 Feature 数据，复用现有 AudienceProjection，禁止用 CSS 假隐藏。
- toggle、button、activate/deactivate/use 等通用控件。
- MapPackage 可声明 anchor、图标和展示策略，但不能注入自己的状态机或权限判断。

## 四、Elevation 与空间模型

当前只实现 Token 离地高度与 Feature 阻挡顶部高度。后续需要统一设计：

- ground elevation 与 absolute elevation。
- 建筑楼层、地下层、屋顶层和层间连接。
- 桥上/桥下多层 Navigation Surface。
- walk、fly、climb、swim 等 Movement Mode 与垂直移动成本。
- Token physical height、门洞净高和大型生物体积。
- 坠落、水深、弹坑深度、洪水水位。
- Vision、LOS、投射物与高度区间。

这些能力应扩展显式 `NavigationQuery`/mover context，不复制另一套路网或把规则写死进地图。

## 五、VTT 功能

在 Server、权限和资产边界稳定后逐步实现：

- 基于墙体、门、地形高度和光源的精确 LOS；扩展现有 Vision/Fog，不建立第二套探索存储。
- Secret Door、Trap 与 Exploration State。
- 更完整的 Initiative/Combat workflow。
- Dice、Check、Target 与聊天卡片。
- 更完整的规则包 Hook 与回合触发；不得把 Status V4 已有持续时间重新实现为平行系统。
- Scene Notes、Journal、手册与分享权限。
- 环境声音、地图动画与交互反馈。

Combat API 扩展、精确 LOS/Light、Asset Manager、通用 Hook 和第二 Ruleset 必须分别进入独立检查点，不与小型修复捆绑。

## 六、质量与发布

- 保留固定 fixture 性能基准；时间结果用于 PR 对比，不设置易抖动的 CI 毫秒阈值。
- World Manager 首屏与总 bundle 继续使用确定性 gzip budget。
- 每个发布包必须从 tag commit 干净构建，`VERSION.json.commit` 与 tag 目标一致。
- Release 只包含 ZIP 与 SHA-256；raw `reference/` 继续留在源码仓库。
- 增加第二 MapPackage/Ruleset 后扩展浏览器 smoke，覆盖版本不兼容、跨包 Scene 与安装失败。
- 长期关注损坏存档恢复、未知扩展字段保留、幂等重放、断线重连和多个同源 Token 隔离。
- 增加大规模 Fog 网格压缩、历史裁剪和跨 Scene 性能基准；不得用客户端上报探索格换取性能。

## 七、不可回退约束

- 不恢复浏览器全局默认 Ruleset 覆盖已有 World。
- 不把 `preferences.entitySystem` 或 UI 投影变回持久化写入权威。
- 不让 Unlinked Token 修改 Base Actor。
- 不让 NPC/召唤物通过 `actorId` 运行操作或切回 Linked 模式。
- 不把 AudienceProjection、当前视野来源或 UI 选择写回权威 World。
- 不接受客户端提交的视野坐标或探索网格。
- 不在普通交互中恢复整份 `world.push`。
- 不把 `featureStates` 放回全局 preferences。
- 不让 Core 依赖兰州 Feature ID、分类或 Infinite Horror 私有字段。
- 不为地图、服务器模式或安装流程增加平行 Launcher/Runtime。
- 不删除、跳过或弱化迁移、权限、并发与发布测试来获得全绿。
