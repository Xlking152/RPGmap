# RPGmap 未来规划

当前开发版本：**V1.4.3 Candidate**  
当前稳定 `main`：**V1.4.0**

目标：把 RPGmap 逐步发展为类似 Foundry VTT 的自托管、可携带、可扩展 VTT 平台，并保持地图资源、World 运行状态和程序本身相互分离。

状态标记：

- ✅ **已实现**：当前 Candidate 已具备并进入自动测试。
- 🟨 **部分实现**：核心基础已经存在，但完整管理能力尚未完成。
- ⬜ **计划中**：尚未开始正式实现。
- 🧭 **Launcher 已预留入口**：Launcher UI 已保留位置，后续可直接扩展。

## 二、当前总体架构

V1.4.3 Candidate 已经从早期“浏览器本地工具”演进为：

```text
RPGmap Launcher
├─ Native Windows EXE
├─ Local Control Center :29999
├─ Server / Tunnel Lifecycle
├─ GM Admin Session
└─ Future Managers
    ├─ World Manager
    ├─ Scene Manager
    └─ Backup Center

RPGmap Game Server :30000
├─ HTTP / Static Client
├─ World Store
├─ WebSocket
├─ Player Identity
├─ Actor Ownership
└─ Combat Turn Authority

Portable Package
├─ app/        程序前端
├─ world/      当前 Campaign 运行状态
└─ maps/       Map / Scene 资源库
```

长期原则：

1. Server 是共享 World 的最终数据与权限裁决者。
2. Client 负责输入、显示和友好预检。
3. `app/` 可以升级替换，但不能破坏 `world/` / `maps/`。
4. `maps/` 只描述地图 / Scene **是什么**。
5. `world/` 描述当前游戏里**发生了什么**。
6. Launcher 逐渐成为本机 GM 的 World / Scene / Backup / Server 管理中心。
7. 不为 Launcher 引入 Electron；Windows 原生 EXE 只作为轻量入口，核心仍使用 Node + Web UI。

## Phase 2：正式 Server V1 — ✅ 已实现

原规划建议 Fastify，但当前使用零额外运行依赖的 Node 原生 HTTP / WebSocket 实现，已经满足 V1 所需目标：

- HOST / PORT。
- 静态 Web Client。
- `/api/health`。
- `/api/version`。
- `/api/multiplayer`。
- World / Build / User 信息输出。
- WebSocket `/ws`。
- 错误处理和运行日志。

因此不为了“符合旧规划中的 Fastify 名称”而进行无价值重写。

## Phase 3：World Store — 🟨 核心已实现

## Phase 8：Portable World / Map Boundary — ✅ 已实现

V1.4.2 已完成：

```text

```


这条边界作为后续多地图与可破坏场景的长期基础，不再把 `/map` 当整个 Campaign 数据目录。

需要实现：

1. Map manifest schema。
2. Map Registry。

4. World 当前 Scene。
5. Scene 切换。
6. Token 在不同 Scene 间的位置归属。

8. MapPackage import / validation。

北宋兰州最终应成为普通 MapPackage，而不是应用核心代码默认绑定的一张地图。

# 六、持久化与数据库 — ⬜ 暂缓

JSON World Store 当前仍足够。

只有出现以下明显瓶颈后，再考虑 SQLite：

- World 数据量明显增大。
- operation / audit log 很长。
- 多 World 管理需要高效索引。
- JSON 全量写入成为性能瓶颈。

未来适合进入数据库：

- Actors。
- Tokens。
- Users。
- Permissions。
- Combat state。
- Audit log。

地图、图片和大型附件继续使用文件系统。

# 九、推荐开发顺序

当前建议顺序已经从早期路线调整为：

1. ✅ V1.4.3 Launcher / User / Ownership / Combat / Portable Storage 实机验证。
2. ⬜ **World Manager 基础**：从“单 default World”演进为可选择 World。
3. ⬜ **Map Registry + Scene Manager**：真正支持多地图切换。
4. ⬜ **Scene Instance / 可破坏地图对象**。
5. ⬜ **Backup Center + World export/import**。
6. ⬜ Snapshot → operation / patch 同步优化。
7. ⬜ Dice / Target / Fog / Vision 等游戏系统。
8. ⬜ Named Tunnel / Docker / 固定公网服务。
9. ⬜ JSON 确实成为瓶颈后再评估 SQLite。

不要因为未来功能很多而同时引入数据库、Electron、微服务或复杂账号体系。优先保持 RPGmap 的便携、自托管和可理解性。
