# RPGmap 未来规划

当前开发版本：**V1.4.3 Candidate**  
当前稳定 `main`：**V1.4.0**

目标：把 RPGmap 逐步发展为类似 Foundry VTT 的自托管、可携带、可扩展 VTT 平台，并保持程序、地图资源和 World 运行状态相互分离。

状态标记：

- ✅ **已实现**：当前 Candidate 已具备并进入自动测试。
- 🟨 **部分实现**：核心基础已经存在，但完整管理能力尚未完成。

- 🧭 **Launcher 已预留入口**：Launcher UI 已保留位置，后续可直接扩展。
- ↩️ **已撤回方案**：曾实现/测试，但不再作为当前推荐架构。

## 当前总体架构

```text
RPGmap.bat
   ↓
Node.js
   ↓
Web Launcher / GM Control Center
├─ Dynamic Loopback Port
├─ Local / LAN / Internet Lifecycle
├─ GM Admin Session
├─ Connection Dashboard
└─ Future Managers
   ├─ World Manager
   ├─ Scene Manager
   └─ Backup Center

Game Server :30000
├─ Web App
├─ World Store
├─ WebSocket
├─ Player Identity
├─ Actor Ownership
└─ Combat Turn Authority

Portable Package
├─ app/
├─ world/
├─ maps/
└─ tools/
```

长期原则：

1. Server 是共享 World 的最终数据与权限裁决者。
2. Client 负责输入、显示和友好预检。
3. Launcher 负责本机 GM 的启动、网络、User 与未来 World/Scene/Backup 管理。
4. `app/` 可升级替换，但不能破坏 `world/` / `maps/`。
5. `maps/` 描述地图 / Scene **是什么**。
6. `world/` 描述当前游戏里**发生了什么**。
7. 当前不为了桌面外观增加额外 EXE 启动层。

### Phase 2：Server V1 — ✅

原生 Node HTTP / WebSocket、静态 Client、`/api/health`、`/api/version`、`/api/multiplayer`、`/ws`、日志与状态输出已完成。

### Phase 3：World Store — 🟨 核心完成

```text

├─ state.json
├─ users.json
├─ uploads/
└─ backups/
```

已完成 Snapshot、revision、原子写入、Persistent User / Ownership、旧目录迁移与便携移动。多 World / 自动备份 / 恢复进入未来 Manager。

### Phase 4：Realtime / WebSocket — ✅ V1

World Snapshot、Presence、Conflict、Actor/Token/HP/Form/Combat/Chat 同步和 Server 权限验证已完成。后续演进到 operation / patch。

### Phase 5：Player Identity / Ownership — ✅

pending、approve、预创建 User、Browser Auth Token、Player Key、NONE/OBSERVER/OWNER、Default Actor、多角色、Combat Turn Lock 和 Launcher Admin 已完成。

### Phase 6：Combat / 游戏系统 — 🟨

Combat、Initiative、Round/Turn、Health/Damage/Healing、Chat/Game Log 已完成。Dice、Target、Fog、Vision 等仍计划中。

### Phase 7：Portable World / Map Boundary — ✅


这条边界作为后续 Multi-Map / Destructible Scene 的长期基础。

推荐顺序：

```text
World Manager
   ↓
Map Registry
   ↓
Scene Manager
   ↓
Scene Instance
   ↓
Destructible Object / Environment
```

需要实现：Map manifest、Registry、Scene ID、当前 Scene、切换、Token Scene 归属、reset/clone、MapPackage import/validation。

北宋兰州最终应成为普通 MapPackage，而不是应用核心绑定的一张地图。

## 可破坏地图 / 环境 — ⬜

正式 Scene System 后实现：Building / Wall / Door、HP / Durability、Collision、Damage stages、Destroyed Variant、Fire / Smoke / Explosion。模板留在 `maps/`，当前损坏状态留在 `world/`。

## 数据库 — ⬜ 暂缓

JSON World Store 当前仍足够。只有 World 数据量、operation log、查询复杂度或原子 JSON 重写真正成为瓶颈后，再评估 SQLite。

## 推荐开发顺序

```text
1. V1.4.3 RPGmap.bat + Web Launcher 实机验收
2. World Manager
3. Map Registry + Scene Manager
4. Scene Instance
5. Backup Center
6. 可破坏建筑 / 环境状态
7. Snapshot → operation / patch
8. Dice / Target / Fog / Vision
9. Named Tunnel / 固定公网部署
10. 需要时再评估 SQLite
```

这份路线以当前真实完成度为准，不再把已经完成的 Multiplayer / Identity / Ownership / Portable Storage / Launcher 重复列为未来工作。
