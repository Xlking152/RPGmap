## 下一优先级

### 1. External MapPackage 生命周期

- 定义可安装 manifest、资源目录、签名、校验和与安全限制。
- 支持 Registry discovery、安装、禁用、卸载和离线校验。
- 为 Scene pinning 建立 MapPackage 版本兼容、升级预览、迁移和回滚策略。
- 保持单一来源，不同时维护编译包与服务器 raw 地图的双写版本。

### 2. Server Multi-World Manager

- 增加服务端 World catalog、创建、切换、归档和备份恢复。
- 建立 `/setup` 管理界面与权限隔离。
- 切换 World 时重新执行 World-first bootstrap，不在已加载 Runtime 中覆盖另一份 World。
- 明确数据根、上传内容和备份保留策略。

### 3. 完整 Asset Manager

- 当前 v2.4.0 已有鉴权内容存储、去重、引用统计和模板/Journal 依赖，但仍不是面向所有地图素材的完整资产管理器。
- 后续统一 Actor、Token、Journal、地图素材和用户文件的稳定资产 ID、目录、配额、反向引用和生命周期 UI。
- 删除资产前继续由服务器检查全部 World、备份和内容依赖，不能仅依赖客户端展示状态。

### 4. External Ruleset Package

- 定义 Ruleset manifest、版本依赖、安装、升级、隔离和兼容检查。
- 使用不包含 Health、Forms 或 Infinite Horror 字段的第二 Ruleset 持续验证 Contract。
- 未知或不兼容 Ruleset 必须明确失败，不得静默回退到 Infinite Horror。

### 5. 高级空间与感知

- 多层 Navigation Surface、建筑楼层、地下层、屋顶层和桥上/桥下通行。
- Token 三维身体体积、门洞净高、大型生物占位、攀爬、坠落、水深和弹坑深度。
- 窗、秘密门和更完整的 `visionOccluders`，以及 Vision Mode、Detection Mode 与投射物高度区间。
- 保持现有米制纯空间内核和 Ruleset capability 边界，不建立第二套导航或 Fog 存储。

### 6. 后续 VTT 能力

- 更完整的 Initiative/Combat 工作流、Dice、Check、Target 和聊天卡片。
- Journal 交叉链接、场景笔记、手册目录和更细的共享权限。
- Secret Door、Trap、Exploration State、环境音效、地图动画和交互反馈。
- Combat API、Hook、第二 Ruleset 和高级 Fog 工具分别进入独立检查点，不与小型修复捆绑。

## 质量与发布

- 固定 2 Scene、100 Actor、500 Token、1000 Feature State 的 CPU fixture，并保留 GM + 6 Player 的 500 Token LAN 回环基准。
- 正式性能记录使用规定的 Node 22.12.0、Edge/Chrome 版本、硬件信息和 1080p 前台窗口；其他 Node 版本结果只能作为补充。
- World Manager 首屏和总 bundle 继续使用确定性 gzip 预算，不因新增功能擅自放宽。
- 每个正式包从唯一 main release commit 干净构建，`VERSION.json.commit` 必须与 Tag 目标一致；Release 只包含 ZIP 与 SHA-256。
- 长期回归覆盖损坏存档、升级中断、未知安全字段、WAL 重放、断线重连、多人幂等、Audience 零泄漏和多个同源 Token 隔离。

## 不可回退约束

- 不让全局默认 Ruleset 覆盖已有 World，也不让 Core 依赖兰州 Feature ID 或 Infinite Horror 私有字段。
- 不把 UI 投影、AudienceProjection、当前视野来源或选择状态写回权威 World。
- 不让 Unlinked Token 修改 Base Actor，不让 NPC/召唤物绕过实例目标或切换为 Linked。
- 不接受客户端提交的视野坐标、探索网格、任意 Document 路径或伪造 capability。
- 不在普通交互中恢复整份 `world.push`，不把 `featureStates` 放回全局 preferences。
- 不用前端遮挡代替服务端投影裁剪，不在错误响应中泄露 canonical World 或隐藏实体 ID。
- 不删除、跳过或弱化迁移、权限、并发、性能和发布测试来获得全绿。
