## 当前架构

```text
RPGmap.bat
   ↓
PowerShell Runtime
   ├─ Node.js Host
   ├─ app/maps -> ../maps Runtime Junction
   ├─ Launcher / Server / Tunnel 输出
   └─ Local / LAN / Public / JoinCode / GMSecret
   ↓
Web Launcher / GM Control Center
   ├─ Server / Tunnel Lifecycle
   ├─ User / Ownership
   └─ Future Managers
      ├─ World Manager
      ├─ Scene Manager
      └─ Backup Center

Game Server :30000
├─ Web App / Engine
├─ Runtime MapPackage
├─ World Store
├─ WebSocket
├─ Player Identity
├─ Actor Ownership
└─ Combat Turn Authority

Portable Package
├─ app/     引擎 / UI
├─ maps/    Map Registry / MapPackage / assets
└─ world/   Campaign 运行状态
```

长期原则：Server 是共享 World 最终裁决者；Web Launcher 负责交互管理；PowerShell 只做稳定 Runtime 和信息窗口；`app/`、`maps/`、`world/` 职责继续严格分离。

## 已完成阶段

### Movement / Entity / UI — ✅

Token Movement、Waypoint、A*、Selection、Ruler、Actor / Token / Form、XLSX 导入、AppShell 等基础能力已完成。

### Server / Realtime V1 — ✅

Node HTTP / WebSocket、静态 Client、World Snapshot、revision、Presence、冲突保护与 Server 权限验证已完成。

### Player Identity / Ownership — ✅

pending、approve、预创建 User、Player Key、NONE/OBSERVER/OWNER、Default Actor、多角色、Combat Turn Lock 与 Launcher Admin 已完成。

### Portable World / Map Boundary — ✅

```text
app/   = 程序
maps/  = 地图模板 / 资源
world/ = Campaign 实例状态
```

### External Runtime MapPackage — ✅ V1.4.3

早期 Candidate 的 `maps/` 只有边界定义，默认兰州地图仍然被 Vite 编译进 `app/`。当前已经真正完成外置：

```text
maps/
├─ index.json
└─ northern-song-lanzhou-1104/
   ├─ map.json
   └─ assets/
```

已经完成：

- Runtime Map Registry `maps/index.json`；
- 默认 MapPackage JSON 导出；
- 地图 WebP 与 app 前端 bundle 分离；
- Production 运行时从 `/maps/...` 读取；
- Windows `app/maps -> ../maps` Junction；
- Vite dev 源码地图 fallback；
- CI 验证地图定义不再重新烘焙进 `app/`。

这意味着未来 Scene Manager 不需要再先解决“地图如何脱离前端 bundle”的基础问题。

### Unified Launcher — ✅ V1.4.3

已经完成：
