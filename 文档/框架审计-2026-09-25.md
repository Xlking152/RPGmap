## 当前结构

```text
main → World Manager → runtime/map-runtime
                         ├─ World / Scene / Actor / Token
                         ├─ Document intent → World reducer
                         ├─ Ruleset（当前内置 infinite-horror）
                         ├─ MapPackage → spatial / movement / vision
                         └─ UI / renderer / content / journal
LAN client → operation queue → server authority → WAL → audience changes
```

优点：启动与地图运行时分离；World 是持久化权威，Token 支持独立 Actor delta；规则与地图通过契约接入；本地和服务端复用操作归约器；多人权限、广播裁剪、幂等、WAL 和断线恢复有行为测试。

主要证据：`src/main.js`、`src/runtime/map-runtime.js`、`src/world/system.js`、`src/world/operations.js`、`src/documents/`、`src/server/world-operations-entry.js`、`src/multiplayer/`、`deployment/local-server/`。

## 与 FVTT 的差距

结论：具备 FVTT 式战术地图和文档架构的主要骨架，但不是完整 FVTT 平台，也没有证据支持与其系统/模块兼容。

| 领域 | RPGmap 当前实现 | 判断 |
| --- | --- | --- |
| World / Scene | 多 World、Scene、地图包选择与场景状态 | 已具备核心能力 |
| Actor / Token | 模板、Linked/Unlinked、实例 delta、角色卡 | 已具备核心能力 |
| 多人权限 | GM/Player、控制权、Audience 投影、权威写入与重连 | 已具备核心能力 |
| 战术地图 | 移动路径、测距、高度、碰撞、门、光源和迷雾 | 已具备主要能力，仍需持续真实联机场景验证 |
| 战斗与聊天 | 回合、先攻、状态、生命、共享聊天 | 已具备；未发现完整通用骰子表达式引擎 |
| Journal / 资料库 | Markdown、图片、模板、依赖 ZIP | 部分对应，不等同 FVTT 多页日志/文档链接/完整 Compendium |
| 多规则系统 | Ruleset 契约与注册机制 | 当前只内置一个系统，安装/升级生态尚不完整 |
| 平台扩展 | 启动时注册内部 tools | 未发现面向用户的模块安装、依赖管理和稳定插件 API |
| 其他文档能力 | 未发现独立完整实现 | Item 文档、RollTable、Cards、Playlist、宏等仍有差距 |

以上结合仓库入口、注册列表、模型和搜索得出，不能按关键词缺失推断所有能力绝对不存在。FVTT 对照来源：

## 已修复的问题

- 并发后台探索：原代码以整份 Fog 未变化为提交条件，先完成的探索导致后完成的合法区域被丢弃。现在验证计算输入与 epoch 后，将区域合并到最新 Fog；hide/reset 仍使旧任务失效。
- 默认场景：操作协议允许省略 sceneId，但后台结果校验与 undefined 比较并丢弃结果。现在提交前解析并固定当前场景。
- 完整 World 替换：通过 World commit 替换存档后，旧后台结果可能重新填入探索。完整替换现在递增探索 epoch；退出应用也使旧任务失效。
- Worker 生命周期：构造失败原来同步抛错，绕过调用方 Promise catch；messageerror 没有收尾；dispose 后仍可重新启动；postMessage 失败留下 pending 项。现分别通过异步拒绝、错误清理、终止标记和删除 pending 修复。
- LOS 与照明组合：关闭 LOS 但仍需要照明网格时，原分支仍使用遮挡体。共享计算现在显式尊重 `lineOfSightEnabled === false`，保留灯光自身的遮挡输入。

新增测试先复现并发探索和 Worker 异常，再确认修复；默认场景也记录了修复前失败。新增测试还覆盖完整 World 替换、Worker/同步结果一致性和关闭 LOS 的照明分支。
