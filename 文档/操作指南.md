# RPGmap v2.3.0 操作指南（Windows Local / LAN）

本版本只支持 Windows 本机与局域网联机；不要将服务直接暴露到公网。主机需要安装 Node.js `20.19+` 或 `22.12+`，Player 只需要现代浏览器。

## 1. 启动与加入

1. 解压 ZIP 到一个有写入权限的普通目录；不要放在只读压缩包、U 盘根目录或受同步软件占用的目录。
2. 双击 `start-rpgmap.bat`。启动器会先检查 Node.js；首次出现 Windows 防火墙提示时，若要让局域网玩家加入，请允许专用网络访问。
3. 启动窗口会显示：
   - `Local URL`：GM 主机使用；
   - `LAN URL`：发给同一局域网的 Player；
   - `Join Code`：发给 Player；
   - `GM Secret`：仅 GM 保留，绝不能发送给 Player。
4. 启动器会用系统默认浏览器打开 GM 页面。若自动登录没有完成，点顶部“联机”，选择 **GM** 并输入 `GM Secret`。
5. Player 在另一台设备的浏览器打开 `LAN URL`，选择 **Player**，输入显示名称与 `Join Code`。第一次加入需要等待 GM 批准。

Player 与 GM 必须访问同一个地址：例如 Player 从 `http://192.168.x.x:30000` 打开，而不能从书签中的旧地址或其他网页跨站连接。

首次使用或服务器尚无 World 时会先显示 World Manager。选择 Ruleset 与“北宋兰州城”，创建 World 后才会载入地图；已有 World 会按自身 Ruleset 和 Active Scene 打开，不使用浏览器里的旧默认值覆盖。

## 2. GM 审批 Player 与分配角色

1. GM 点击顶部“联机”打开 Users 面板。
2. 在“待批准 Player”中选择该玩家的默认角色并批准；默认角色会自动获得 OWNER。
3. 在 Player User 卡片中可以分别设置每个 Actor：

| 权限 | 能做什么 |
| --- | --- |
| GM | 管理 World、角色/Token 结构、先攻、导入、清空聊天与 Token 尺寸。 |
| OWNER | 查看和编辑 Actor；是否能移动具体 Token 仍按实例控制权与战斗回合判断。 |
| OBSERVER | 查看完整只读角色卡，不能编辑 Actor 或控制 Token。 |
| LIMITED | 只看名称、头像、类型和公开简介，不读取生命、状态、属性或 Ruleset 私有数据。 |
| NONE | 目录和角色卡均不可见。 |

如需让 Player 在新浏览器或新设备继续使用同一身份，请在 Users 面板生成并妥善保存该 Player 的 `Player Key`。

Actor 权限与地图实例控制权彼此独立：PC 的 OWNER 可以控制其 Linked Token；怪物、NPC 和召唤物只接受 Token 上的显式控制者。GM 还可以在 Access 面板按 Actor 类型、具体模板或 Marker 类型授予“允许放置”，玩家放置实例后自动成为该 Token 的控制者。玩家不能自行修改控制者、可见性或服务器授权。

## 3. 角色、Token 与地图操作

### 创建与放置

- GM 在“角色库”新建角色或导入角色卡，然后在角色卡的 Token 页点击“放置 Token”。
- Actor 是模板。PC 可以使用共享角色 Token；怪物、NPC 与召唤物始终创建为“独立实例”，每个实例分别保存当前生命、伤势、状态、资源和当前形态。伤害地图上的一个怪物不会改变同模板的另一个怪物，也不会扣除模板生命。
- “Actor 模板卡”用于编辑模板名称、头像、属性、技能、形态定义和生命上限；从地图 Token 打开的“Token 实例卡”用于修改该实例的运行状态。怪物/NPC/召唤物不能从模板卡直接扣血。
- GM 可将旧的共享 NPC/召唤物 Token 批量转换为独立实例。转换会逐 Token 复制当时的运行状态，并保留位置、外观、战斗引用和自定义字段。
- 角色卡会关闭并显示顶部放置提示；点击地图中的可通行 1m 格子完成放置。
- 取消方式：点击 HUD 的“取消”、按 `Esc`、断线或权限变化。Token 放置成功后角色卡不会自动重新打开。
- GM 可以在 Token 页修改 Token 直径为 `1 / 5 / 10 / 20 m`，并可重新放置被旧存档保留在阻挡格中的 Token。
- 同一 MapPackage 的多个 Scene 分别保存门、机关与阻挡高度状态；切换 Scene 后不会串用另一 Scene 的 Feature State。
- GM 可通过地图上的通用 Feature 控件直接打开/关闭门；不需要先切换到单独的检查工具。普通 Player 当前不能修改 Feature State。

### 控制权、可见性与隐身

- GM 在 Token 属性中可设置控制者、视野覆盖用户，以及“公开 / 队伍 / 仅 GM / 指定用户”可见性。“仅 GM”优先级最高，不会因探索、控制或其他授权向 Player 投影。
- 可见但未授权的 NPC 只向 Player 显示名称和头像；其角色卡、生命、状态、Effect、控制者、队伍和其他隐藏字段不会下发。队友 PC/召唤物角色卡可查看但保持只读。
- Infinite Horror 的“隐身”状态会让 Token 对 GM、控制者、同队成员和明确授权用户呈半透明；其他 Player 的快照、战斗列表、聊天结果和查询中完全没有该 Token。
- 选中 Token 后，右下角显示允许公开的大头像与摘要，地图 Token 只做视觉放大，实际占位、碰撞尺寸和导航均不改变。

### Token 实例配置

- 从地图 Token 打开配置时只编辑该实例；从 Actor 模板进入时先从实例列表选择目标。标题显示头像、名称、Linked/Unlinked、Scene、坐标和高度，UUID 只在高级调试信息中显示。
- “基础”设置实例名称、直径、旋转和高度；“视野”分别设置精确/模糊范围并可恢复 Ruleset 继承；“权限”按显示名选择控制者、指定可见用户和视野授权；“高级”提供重新放置、实例覆盖和二次确认删除。
- 每个字段单独提交。显示 pending 时不要重复操作；confirmed 表示服务器已接受，error 会恢复服务器 canonical 值。模糊范围不能小于精确范围，两个字段留空表示继承 Ruleset，显式范围可以超过 120 米。

### 其他指示物、视野与迷雾

- 右侧“指示物”页可放置陷阱、目标点、区域和注释。模板分为“怪物”“NPC”“其他模板”三块；怪物与 NPC 各有 XLSX 导入按钮，召唤物与 `other` 保留在其他模板。同一模板只显示一个紧凑条目；点击“实例”可在抽屉中改名、编辑当前/最大 HP，查看状态，并对勾选实例原子批量添加或移除状态。
- 怪物默认按“模板名1、模板名2…”编号，并优先复用当前 Scene 中的最小空缺正整数。每个 Token 的名称、HP、伤势、状态和侦测覆盖互不污染。
- 陷阱默认仅 GM；其他 Marker 可在创建时选择公开或队伍可见。GM 还可在此页设置当前 Scene 为正常、昏暗或黑暗环境。
- 普通 Player 直接点击自己控制的 Token 后，它成为本会话唯一实时视野来源。多选时以最后直接点击的可控 Token 为准；点击未授权 Token 不会切换视野。
- 当前可见区域明亮；本队走过但当前看不到的区域暗化；从未探索区域完全遮挡。视野圆心始终读取视野源 Token 的最新服务器确认坐标；移动路径会按模糊侦测范围连续揭示，精确范围外但实际能感知的格子也会永久记录。探索记录按当前 Scene 与 Actor 队伍持久化，同队共享历史，但不会共享其他成员的实时视野。
- GM 默认使用全图视角，可选择任意 Token 预览玩家视角，也可在“指示物”页恢复全图。GM 可按队伍重置当前 Scene 的全部探索，或选择半径后在地图上重新隐藏局部区域。
- 首期视野是 5 米网格上的圆形范围，不计算墙体、门、地形高度或精确视线。地图底图仍作为客户端资源下载，迷雾只保护动态 Token、角色卡、Marker、Combat、Chat、Effect、Status 和查询数据，不是地图资产 DRM。

### 侦测与环境光照

- Infinite Horror 角色卡“概览”页的“侦测”区域可编辑精确范围、模糊范围，以及真实视觉、透视、灵视、昏暗视觉和黑暗视觉。从角色表导入的值属于 Form 基础数据；独立 Token 的运行时覆盖只影响该实例。
- 精确范围内显示完整可见 Token；仅在模糊范围内时显示匿名轮廓和粗略方位，不提供名称、图片、角色卡或权威 ID。模糊范围小于精确范围时，导入诊断保留原值，运行时会将其提高到精确范围。
- 昏暗环境中，没有昏暗视觉时精确目标降为模糊；黑暗环境中，只有黑暗视觉按正常精度工作。真实视觉、透视和灵视在 v2.2.1 只保存与展示，不穿墙、不提供特殊目标识别。

### 选择与检查地物

v2.1.3 起，原先重复的“检查地物”入口已经合并进“选择”模式，顶部不再单独显示“检查地物”按钮。

- 保持顶部“选择”处于激活状态时，可以直接点击 Token 进行角色选择，也可以用框选一次选择多个 Token。
- 同一个“选择”模式下，也可以直接点击可检查的建筑、城墙、城门、桥梁等 Feature。
- 点击 Feature 后，右侧会自动切换到其详情，显示类别、类型、用途、构造、说明、入口、内部 Token 和可用操作；当前 Feature 会在地图上高亮。
- 门等可交互 Feature 的地图快捷控件仍可直接使用，不需要先打开详情。
- “范围”仍是独立工具；v2.2.1 已删除“图层”按钮和面板，地图网格始终显示。旧 World 中的网格关闭值仍可安全读取，但 Runtime 会忽略它。

### 移动与高度

- 单个 Token：点击选择后直接拖动即可规划移动。
- 键盘移动：直接选中一个可控 Token，使用 `W/A/S/D` 每次移动一个当前步长。焦点在输入框、下拉框、文本区或角色卡内时不会触发；局域网下每次移动仍等待服务器权威确认。
- 群组 Token：先框选或多选多个地图 Token，再拖动**已经在该选区中的任意一个 Token**。被拖动的 Token 会成为 leader，其余成员保持与 leader 的原始 `dx/dy` 相对位置一起平移。拖动未选中的 Token 会回到普通单 Token 移动。
- 群组只是本次选择/移动的临时上下文，不会创建可保存的 TokenGroup 或 Formation。
- 规划群移时只绘制 leader 的一条路线，避免多条重合路线遮住地图；终点会显示整组 Token 的半透明预览，因此可以直接检查最终队形。
- 每个成员都会按自己的 Token 直径、高度和当前状态独立检查 leader 路线平移后的每一段。只要一个成员受阻，整组路线就视为受阻，终点预览统一变红；不会出现“能走的先走、被挡的留在原地”。
- 拖动或移动鼠标规划路线时，终点预览只表示当前计划位置，不会修改 World。
- 移动只有严格直线，不会自动绕路。受阻时首个阻挡格、受阻段以及终点预览会显示为红色。
- 普通左键拖动并释放提交一条直线路线。要规划分段路线，在拖动期间按住 `Ctrl`（macOS 为 `Cmd`）并释放；该释放点只是预览，不会自动成为第一个路径点。
- 保持 `Ctrl`/`Cmd` 时左键点击或按 `F` 添加路径点；右键或 `Alt+F` 移除最后一个路径点，没有路径点时右键取消。释放修饰键后的下一次左键点击设置终点并提交，也可按 `Enter` 确认当前终点；`Esc` 取消整次移动。
- 路线显示每段距离、累计距离、合法/非法与 LAN pending。服务器会逐段复验控制权、锁定、当前战斗回合、场景边界和碰撞；群移时同一组 waypoint 按固定相对位移映射给所有成员，任一成员失败则整批不移动。
- 单 Token 确认移动后，服务器/World 先提交权威位置，Renderer 再平滑显示已确认路径。群组确认移动时，会先重新验证整组路线，然后把全部最终坐标放进**同一次 World commit**；要么全部成功，要么全部不动。
- 群组的 canonical state 只原子提交一次，但 Renderer 会使用每个成员的只读视觉 waypoint 队列同步播放路径，因此不会因为原子提交而直接瞬移到最终位置。
- 平滑移动只是视觉插值，不产生任何中间 Token 坐标写入，不改变碰撞、距离、回合锁、OWNER 或服务器 revision 语义。
- 为避免独立覆盖层先跳到终点，Token 移动动画期间血条和机械状态徽章会暂时隐藏，动画结束后在最终权威位置恢复。
- 群移只修改 x/y；每个 Token 保留自己的 `elevationFt`。因此不同高度成员仍分别按自己的高度检查障碍，但只要任一成员不能通过，整组就不能提交。
- Token 顶部标签按 **高度 → 名称** 排列，例如 `10 ft  张三`；高度位于名称左侧。生命条仍固定在 Token 下方。
- 右键 Token 打开高度 HUD。只有 Token 高度**严格高于**障碍高度时，直线才可越过该障碍；`0 ft` 与等高均按受阻处理。
- 非战斗时，Player 只能移动自己拥有 OWNER 权限的 Token；群组中只要包含一个未拥有 Token，服务器就会拒绝整次提交。
- 战斗中，普通 Player 仍只能移动当前回合的**一个** Token，即使多个 Token 都绑定同一个当前 Actor，也不能用群移绕过 Combat Turn Lock。GM 可在战斗中群移多个 Token 以调整敌军/NPC。

## 4. 范围与场景破坏

1. 点击顶部“范围”，选择圆形、扇形或矩形，然后点击地图放置起点。
2. 选中已保存范围后，可修改名称、尺寸、角度、透明度以及场景破坏选项，也可以直接拖动地图上的起点、半径、方向、角度或宽度手柄。
3. “绑定对象”支持三种起点：
   - **自由放置**：使用范围自身坐标；
   - **Marker**：范围起点跟随 Marker；
   - **Token**：范围起点跟随 Scene Token，也就是角色在地图中的当前实例位置。
4. Token 作为起点时，范围会按 Token 当前坐标显示和计算。角色移动后，已绑定但尚未应用的范围会跟随新的位置。
5. 若要造成场景破坏，先勾选“启用场景破坏”，再点击“预览影响”。预览会计算当前范围实际覆盖的 Feature；确认后再点“应用破坏”。
6. “应用破坏”记录的是**应用瞬间已经解析出的范围位置**。以后角色继续移动，不会把历史破坏区域一起拖走。
7. 若在预览之后又移动了绑定 Token、修改范围参数或切换破坏目标，应重新点击“预览影响”后再应用，避免使用过期预览。
8. 拖动范围起点会明确解除原有 Token/Marker 绑定并切换为自由起点；这是为了避免手动位置和绑定对象同时成为两个权威来源。

## 5. 生命、伤害与恢复

- 在右侧“聊天”面板选择“伤害”或“恢复”，先选中目标 Token，再输入已经完成规则结算后的数值与 B / L / A 类型。
- 普通 HP 模式按当前/最大生命值变化；伤势生命槽模式使用：**B** 冲击、**L** 严重、**A** 恶性。
- 简单 HP 未配置时的 `0/0` 显示为“未配置”，不会自动判定耗尽、昏迷或死亡。
- 角色卡概览中的 B/L/A 数字可直接编辑，适合修正或录入既有伤势；系统会自动限制总数不超过生命槽上限。
- 恢复只能恢复所选类型的现有伤势。没有相应 B/L/A 伤势、已满血，或目标已死亡时，界面会给出明确提示；普通恢复不代替复活。
- 在局域网中，生命、伤势和资源变更会立即提交至服务器。Player 仍仅能编辑自己的当前回合角色。

## 6. 角色状态 / Buff

- 角色卡的“状态”页分为 Actor 状态、各 Token 状态和生命系统自动派生状态。Actor 状态影响该角色的全部形态与 Token；Token 状态只影响一个地图实例。
- 普通右键 Token 或点击其状态徽章会打开快捷 HUD。状态按 Buff、Debuff 和折叠的中性/派生状态分区；单击按“施加 → 停用 → 重新启用”循环，详情可编辑层数、备注、turns/rounds 持续时间或彻底移除。
- 多选 Token 时快捷操作作为一个原子 batch 提交。Linked Token 修改 Actor Effect；Unlinked Token 只修改自己的 `actorDelta.effects`，不会污染模板或同源实例。
- 只有 GM 可以管理状态定义；实例状态修改仍需对应 Token 控制权限。按钮显示“等待服务器确认”期间不要重复点击，服务端拒绝后会恢复 canonical 值。
- 内置状态包括隐身、灵体、定身、失能、强化、虚弱、中毒、燃烧、流血和目盲。目盲只通过安全 capability 将精确感知降为模糊，不执行任意脚本。自定义 JSON 固定为 `{ "statusSchemaVersion": 4, "definitions": [...] }`，导入时整体校验；任一 ID 冲突会拒绝整批并列出冲突项。
- 回合持续时间由服务器权威战斗推进扣减：turns 每次推进扣减，rounds 仅在回合数增加时扣减；到期状态自动停用，手动停用期间暂停计时。
- 内置“灵体”只穿透建筑、城墙及关闭的门/城门，不会穿越水域、弹坑或地图边界；“定身”禁止移动；“失能”禁止移动、Feature 交互和战斗行动。
- 昏迷、死亡以及 B/L/A 不良状态徽章由角色数据自动计算，不能手动移除。生命恢复后，相应限制和 Token 徽章会立即刷新。
- Token 上方最多直接显示 4 个高优先级状态，其余合并为 `+N`。在地图中多选 Token 后，GM 可在状态页按 Token 批量施加，也可按所选 Token 对应的多个 Actor 批量施加同一状态。
- 局域网中状态以服务器 World 为准。断线、权限下降、写盘失败或并发冲突会取消待提交操作及移动预览，不会先在本地显示成功后再回滚。

## 7. 战斗与聊天

1. GM 选中一个或多个 Token，点击顶部“进入战斗”。
2. 在先攻表填写先攻值；需要时可拖动调整顺序；点击“开始战斗”。开始战斗时，系统会把第一名当前 Scene Token 的位置与高度记录为本回合起点。
3. 当前战斗者第一次离开本回合起点后，原位置会显示一个淡化、不可交互的 Token 幻影，并标记 `起点 · X ft`。它只用于观察本回合从哪里开始，不是第二个 Token，不参与选择、碰撞、范围、伤害或其他地图规则。
4. 起点保存在共享 Combat State。GM 或 Player 刷新页面、断线重连后，只要仍处在同一回合且 Token 已离开起点，幻影会从服务器同步状态恢复。
5. GM 点击“下一回合”推进回合。旧起点立即失效，并记录新当前战斗者此刻的位置和高度；因此每个回合最多只有当前战斗者的一个起点幻影。
6. 如果当前 Token 回到完全相同的起点位置，幻影会暂时隐藏，避免与真人 Token 重叠；之后再次离开时仍使用同一个本回合起点。
7. 只有当前回合 Actor 的 OWNER 可以移动或编辑该角色的生命/资源。战斗中普通 Player 只能移动一个当前回合 Token；群移为 GM 管理权限。若 GM 直接移除或删除当前战斗者，系统会为被动切换后的新当前战斗者重新记录起点。
8. GM 点击“结束战斗”并确认，清空先攻表与本回合起点。战斗状态会先保存，再记录日志，避免局域网 revision 冲突。
9. “聊天”面板底部默认只显示“消息、伤害、恢复”三个模式按钮。点击某模式展开表单，再次点击当前模式或按 `Esc` 收起；切换模式不会重建聊天记录。聊天页未激活时，新消息只增加未读角标，不会自动展开表单。
10. Local/LAN 中聊天由服务器写入共享 World。发送成功后清空输入但保持当前模式；服务器拒绝或断线时保留输入。普通 Player 只能提交文本，消息 ID、时间、发送者与受保护事件类型由服务器生成。
11. 若 WebSocket 已断开或服务器不可用，发送会保留输入内容并提示发送失败，方便重新连接后再次发送。
12. GM 的“清空共享聊天记录”只删除日志，不会清除先攻、Token、伤势、生命或场景状态；清空结果同样以服务器快照同步给包括 GM 自己在内的全部客户端。

## 8. 存档、备份与升级

所有共享数据都在发布目录的 `map/` 内：

```text
map/world.json     当前 World（角色、Token、场景、先攻、聊天等）
map/users.json     Player User 与权限记录
map/backups/       自动滚动备份和损坏文件隔离副本
map/uploads/       上传文件
```

- 导入存档会覆盖共享 World。GM 应先阅读确认内容，并复制整个 `map/` 作为人工备份。
- 每次 World/User 写入前，服务器会保留最近的滚动备份。若 JSON 损坏，服务器会隔离原文件并停止启动，不会用空数据覆盖。
- 升级到新版本时：关闭服务 → 复制旧包的整个 `map/` 到新包 → 启动新包。不要只复制 `world.json` 而遗漏 `users.json` 或备份。
- v2.3.0 保持 World schema `3`，将 operation schema 升至 `2`、Status schema 升至 `4`、Access schema 升至 `4`。首次写回旧状态/权限结构前会先备份并幂等迁移，保留定义 ID、Effect ID、未知扩展字段和 Unlinked 实例隔离。Protocol V2 不与旧客户端降级互通；主机与 Player 必须使用同一版本。

## 9. 常见问题

- **Player 打不开 LAN URL**：确认两台设备处于同一局域网、主机防火墙允许专用网络、使用启动窗口最新的 LAN URL，并避免访客 Wi-Fi 的客户端隔离。
- **Player 只能看不能改**：GM 需要授予 OWNER；若战斗已开始，还必须轮到该 Actor。
- **为什么两个同模板怪物不会一起扣血**：NPC/召唤物是独立 Token 实例。请从地图打开实例卡或选中具体 Token 结算；只提供 Actor 模板的含糊运行操作会被服务器拒绝。
- **为什么 Player 看不到某个怪物或战斗项**：检查 Token 可见性、隐身状态和当前实时视野。服务器会删除无权看到的实体，而不是只用前端样式遮住。
- **刷新后探索区域会不会消失**：不会。探索按 Scene 与队伍保存在权威 World；切换 Token、重连或服务器重启都保留，只有 GM 重置或重新隐藏才会减少。
- **为什么队友看得到探索暗区，却没有我的实时亮区**：这是设计行为。队伍只共享探索历史，每个会话始终只使用自己最后选择的一个可控 Token 作为实时来源。
- **怎么让多个角色一起移动**：先框选/多选多个 Token，再拖动其中一个已选 Token。被拖动者是 leader，其他 Token 保持原相对位置；确认前可以从整组终点幻影检查最终队形。
- **为什么群移路线是红色**：至少一个成员的平移路线被自己的直径、高度、状态或地图障碍阻挡。群移不会拆散队伍；需要改终点、添加整组都能通过的 waypoint，或先调整队形。
- **为什么战斗中 Player 不能群移自己几个 Token**：这是 Combat Turn Lock 的设计。普通 Player 每次只允许移动当前回合的一个 Scene Token；GM 才能在战斗中批量调整 Token。
- **群移失败会不会有几个人已经移动了**：不会。正式提交前会重新检查整组，全部通过后只做一次 canonical World commit；失败时整组保持原权威位置。
- **为什么回合刚开始看不到“起点”幻影**：这是设计行为。起点已记录，但真人 Token 还与起点完全重合；只有 Token 离开后才显示幻影，避免两个相同 Token 叠在一起。
- **起点幻影能不能点击/攻击/选中**：不能。它只是 Renderer 视觉层，不是 Scene Token，也不进入碰撞、范围、伤害、治疗或选择系统。
- **刷新后起点幻影不见了**：确认仍是同一个战斗回合，且当前 Token 的权威位置确实已离开起点。v2.1.5 起点存在共享 Combat State，正常重连会自动恢复。
- **Token 看起来仍然瞬移**：确认使用的是 v2.1.4 或更新版本，并检查浏览器/系统是否启用了“减少动态效果（prefers-reduced-motion）”；该无障碍设置会按设计关闭平滑插值，但路线和终点预览仍可使用。
- **移动时血条暂时消失**：这是 v2.1.4 起的设计。血条是独立覆盖层，为避免它比 Token 提前跳到服务器终点，动画期间暂时隐藏，结束后自动恢复。
- **高度在哪里**：v2.1.4 起已把高度移到 Token 上方名称的左侧；血条仍在 Token 下方。右键 Token 仍可编辑高度。
- **消息按发送后没有出现**：先看顶部状态。v2.1.3 起会在发送请求被 WebSocket 接受后清空输入框，并等待服务器快照；若提示连接不可用，重新连接后再发送。若服务器确认同步完成仍看不到消息，应检查是否打开了同一个 World。
- **Token 绑定范围无法预览/应用**：v2.1.3 已修复。确认绑定对象仍显示正确 Token；角色移动后重新预览，再应用破坏。
- **找不到“检查地物”按钮**：v2.1.3 已将它合并进“选择”。保持“选择”模式，直接点击建筑、城墙、城门等可检查 Feature 即可。
- **操作后又恢复原状**：等待顶部状态显示联机同步完成；不要同时在多个设备修改同一份 World。发生冲突时客户端会重新加载服务器版本。
- **启动报告存档损坏**：不要继续覆盖文件；在 `map/backups/` 找最近备份，恢复后再启动。
- **浏览器没有自动打开**：复制启动窗口的 Local URL 到系统默认浏览器。服务关闭可直接关闭启动窗口，或按 `Ctrl+C`。
