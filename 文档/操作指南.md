# RPGmap v2.1.5 操作指南（Windows Local / LAN）

本版本只支持 Windows 本机与局域网联机；不要将服务直接暴露到公网。主机需要安装 Node.js `20.19+` 或 `22.12+`，Player 只需要现代浏览器。

## 1. 启动与加入

1. 解压 ZIP 到一个有写入权限的普通目录；不要放在只读压缩包、U 盘根目录或受同步软件占用的目录。
2. 双击 `start-rpgmap.bat`。启动器会先检查 Node.js；首次出现 Windows 防火墙提示时，若要让局域网玩家加入，请允许专用网络访问。
3. 启动窗口会显示：
   - `Local URL`：GM 主机使用；
   - `LAN URL`：发给同一局域网的 Player；
   - `Join Code`：发给 Player；
   - `GM Secret`：仅 GM 保留，绝不能发送给 Player。
4. 启动器会用系统默认浏览器打开 GM 页面。若自动登录没有完成，点顶部“联机”，选择 **GM** 并输入 `GM Secret`。
5. Player 在另一台设备的浏览器打开 `LAN URL`，选择 **Player**，输入显示名称与 `Join Code`。第一次加入需要等待 GM 批准。

Player 与 GM 必须访问同一个地址：例如 Player 从 `http://192.168.x.x:30000` 打开，而不能从书签中的旧地址或其他网页跨站连接。

首次使用或服务器尚无 World 时会先显示 World Manager。选择 Ruleset 与“北宋兰州城”，创建 World 后才会载入地图；已有 World 会按自身 Ruleset 和 Active Scene 打开，不使用浏览器里的旧默认值覆盖。

## 2. GM 审批 Player 与分配角色

1. GM 点击顶部“联机”打开 Users 面板。
2. 在“待批准 Player”中选择该玩家的默认角色并批准；默认角色会自动获得 OWNER。
3. 在 Player User 卡片中可以分别设置每个 Actor：

| 权限 | 能做什么 |
| --- | --- |
| GM | 管理 World、角色/Token 结构、先攻、导入、清空聊天与 Token 尺寸。 |
| OWNER | 查看自己的角色；非战斗时可编辑/移动；战斗中只能操作当前回合的自己。 |
| OBSERVER / NONE | 只读，不能修改角色、Token、生命或战斗。 |

如需让 Player 在新浏览器或新设备继续使用同一身份，请在 Users 面板生成并妥善保存该 Player 的 `Player Key`。

## 3. 角色、Token 与地图操作

### 创建与放置

- GM 在“角色库”新建角色或导入角色卡，然后在角色卡的 Token 页点击“放置 Token”。
- 角色卡会关闭并显示顶部放置提示；点击地图中的可通行 1m 格子完成放置。
- 取消方式：点击 HUD 的“取消”、按 `Esc`、断线或权限变化。Token 放置成功后角色卡不会自动重新打开。
- GM 可以在 Token 页修改 Token 直径为 `1 / 5 / 10 / 20 m`，并可重新放置被旧存档保留在阻挡格中的 Token。
- 同一 MapPackage 的多个 Scene 分别保存门、机关与阻挡高度状态；切换 Scene 后不会串用另一 Scene 的 Feature State。
- GM 可通过地图上的通用 Feature 控件直接打开/关闭门；不需要先切换到单独的检查工具。普通 Player 当前不能修改 Feature State。

### 选择与检查地物

v2.1.3 起，原先重复的“检查地物”入口已经合并进“选择”模式，顶部不再单独显示“检查地物”按钮。

- 保持顶部“选择”处于激活状态时，可以直接点击 Token 进行角色选择。
- 同一个“选择”模式下，也可以直接点击可检查的建筑、城墙、城门、桥梁等 Feature。
- 点击 Feature 后，右侧会自动切换到其详情，显示类别、类型、用途、构造、说明、入口、内部 Token 和可用操作；当前 Feature 会在地图上高亮。
- 门等可交互 Feature 的地图快捷控件仍可直接使用，不需要先打开详情。
- “范围”和“图层”仍是独立工具；使用这些工具时不会把普通地图点击误当成地物检查。

### 移动与高度

- 点击 Token 选择；也可以直接拖动 Token 规划移动。
- 拖动或移动鼠标规划路线时，终点会显示一个半透明 Token 预览。它只表示当前计划位置，不会修改 World。
- 移动只有严格直线，不会自动绕路。受阻时首个阻挡格、受阻段以及终点预览会显示为红色。
- `Ctrl` / `Cmd` + 左键可添加必须直达的拐点；右键撤销最近拐点；`Esc` 取消整次移动。
- 确认移动后，服务器/World 仍先提交最终权威位置；地图 Renderer 再让 Token 在旧位置和已确认位置之间平滑移动。多拐点会按各段顺序显示，不再看起来像直接瞬移到终点。
- 平滑移动只是视觉插值，不产生任何中间 Token 坐标写入，不改变碰撞、距离、回合锁、OWNER 或服务器 revision 语义。
- 为避免独立覆盖层先跳到终点，Token 移动动画期间血条和机械状态徽章会暂时隐藏，动画结束后在最终权威位置恢复。
- Token 顶部标签现在按 **高度 → 名称** 排列，例如 `10 ft  张三`；高度位于名称左侧。生命条仍固定在 Token 下方，因此不会再与高度文字重叠。
- 右键 Token 打开高度 HUD。只有 Token 高度**严格高于**障碍高度时，直线才可越过该障碍；`0 ft` 与等高均按受阻处理。
- Player 只能移动自己的当前回合 Token。不能移动时先检查 OWNER 分配、是否轮到该角色、Token 是否被锁定及直线路径是否受阻。

## 4. 范围与场景破坏

1. 点击顶部“范围”，选择圆形、扇形或矩形，然后点击地图放置起点。
2. 选中已保存范围后，可修改名称、尺寸、角度、透明度以及场景破坏选项，也可以直接拖动地图上的起点、半径、方向、角度或宽度手柄。
3. “绑定对象”支持三种起点：
   - **自由放置**：使用范围自身坐标；
   - **Marker**：范围起点跟随 Marker；
   - **Token**：范围起点跟随 Scene Token，也就是角色在地图中的当前实例位置。
4. Token 作为起点时，范围会按 Token 当前坐标显示和计算。角色移动后，已绑定但尚未应用的范围会跟随新的位置。
5. 若要造成场景破坏，先勾选“启用场景破坏”，再点击“预览影响”。预览会计算当前范围实际覆盖的 Feature；确认后再点“应用破坏”。
6. “应用破坏”记录的是**应用瞬间已经解析出的范围位置**。以后角色继续移动，不会把历史破坏区域一起拖走。
7. 若在预览之后又移动了绑定 Token、修改范围参数或切换破坏目标，应重新点击“预览影响”后再应用，避免使用过期预览。
8. 拖动范围起点会明确解除原有 Token/Marker 绑定并切换为自由起点；这是为了避免手动位置和绑定对象同时成为两个权威来源。

## 5. 生命、伤害与恢复

- 在右侧“聊天”面板选择“伤害”或“恢复”，先选中目标 Token，再输入已经完成规则结算后的数值与 B / L / A 类型。
- 普通 HP 模式按当前/最大生命值变化；伤势生命槽模式使用：**B** 冲击、**L** 严重、**A** 恶性。
- 角色卡概览中的 B/L/A 数字可直接编辑，适合修正或录入既有伤势；系统会自动限制总数不超过生命槽上限。
- 恢复只能恢复所选类型的现有伤势。没有相应 B/L/A 伤势、已满血，或目标已死亡时，界面会给出明确提示；普通恢复不代替复活。
- 在局域网中，生命、伤势和资源变更会立即提交至服务器。Player 仍仅能编辑自己的当前回合角色。

## 6. 角色状态 / Buff

- 角色卡的“状态”页分为 Actor 状态、各 Token 状态和生命系统自动派生状态。Actor 状态影响该角色的全部形态与 Token；Token 状态只影响一个地图实例。
- 只有 GM 可以创建状态定义、施加/移除状态、调整层数、启用状态与备注。OWNER 和 OBSERVER 始终只读；按钮显示“等待服务器确认”期间不要重复点击。
- 内置“灵体”只穿透建筑、城墙及关闭的门/城门，不会穿越水域、弹坑或地图边界；“定身”禁止移动；“失能”禁止移动、Feature 交互和战斗行动。
- 昏迷、死亡以及 B/L/A 不良状态徽章由角色数据自动计算，不能手动移除。生命恢复后，相应限制和 Token 徽章会立即刷新。
- Token 上方最多直接显示 4 个高优先级状态，其余合并为 `+N`。在地图中多选 Token 后，GM 可在状态页按 Token 批量施加，也可按所选 Token 对应的多个 Actor 批量施加同一状态。
- 局域网中状态以服务器 World 为准。断线、权限下降、写盘失败或并发冲突会取消待提交操作及移动预览，不会先在本地显示成功后再回滚。

## 7. 战斗与聊天

1. GM 选中一个或多个 Token，点击顶部“进入战斗”。
2. 在先攻表填写先攻值；需要时可拖动调整顺序；点击“开始战斗”。开始战斗时，系统会把第一名当前 Scene Token 的位置与高度记录为本回合起点。
3. 当前战斗者第一次离开本回合起点后，原位置会显示一个淡化、不可交互的 Token 幻影，并标记 `起点 · X ft`。它只用于观察本回合从哪里开始，不是第二个 Token，不参与选择、碰撞、范围、伤害或其他地图规则。
4. 起点保存在共享 Combat State。GM 或 Player 刷新页面、断线重连后，只要仍处在同一回合且 Token 已离开起点，幻影会从服务器同步状态恢复。
5. GM 点击“下一回合”推进回合。旧起点立即失效，并记录新当前战斗者此刻的位置和高度；因此每个回合最多只有当前战斗者的一个起点幻影。
6. 如果当前 Token 回到完全相同的起点位置，幻影会暂时隐藏，避免与真人 Token 重叠；之后再次离开时仍使用同一个本回合起点。
7. 只有当前回合 Actor 的 OWNER 可以移动或编辑该角色的生命/资源。战斗中若 GM 直接移除或删除当前战斗者，系统会为被动切换后的新当前战斗者重新记录起点。
8. GM 点击“结束战斗”并确认，清空先攻表与本回合起点。战斗状态会先保存，再记录日志，避免局域网 revision 冲突。
9. “聊天”面板用于普通消息、战斗、伤害与恢复记录。输入普通消息后按 Enter 或点击“发送”。
10. Local/LAN 中聊天由服务器写入共享 World。发送成功后输入框会立即清空并重新取得焦点，同时提示“等待服务器同步”；服务器确认后，发送者自己的聊天面板也会载入这条权威消息，而不再出现“别人能看到、自己没有反应”的情况。
11. 若 WebSocket 已断开或服务器不可用，发送会保留输入内容并提示发送失败，方便重新连接后再次发送。
12. GM 的“清空共享聊天记录”只删除日志，不会清除先攻、Token、伤势、生命或场景状态；清空结果同样以服务器快照同步给包括 GM 自己在内的全部客户端。

## 8. 存档、备份与升级

所有共享数据都在发布目录的 `map/` 内：

```text
map/world.json     当前 World（角色、Token、场景、先攻、聊天等）
map/users.json     Player User 与权限记录
map/backups/       自动滚动备份和损坏文件隔离副本
map/uploads/       上传文件
```

- 导入存档会覆盖共享 World。GM 应先阅读确认内容，并复制整个 `map/` 作为人工备份。
- 每次 World/User 写入前，服务器会保留最近的滚动备份。若 JSON 损坏，服务器会隔离原文件并停止启动，不会用空数据覆盖。
- 升级到新版本时：关闭服务 → 复制旧包的整个 `map/` 到新包 → 启动新包。不要只复制 `world.json` 而遗漏 `users.json` 或备份。
- v2.1.5 没有提升 World schema、operation schema、Ruleset 或 MapPackage 数据版本；Combat 子系统的 preference schema 从 1 自动归一化到 2，旧 v2.0/v2.1.x World 不需要手工迁移。

## 9. 常见问题

- **Player 打不开 LAN URL**：确认两台设备处于同一局域网、主机防火墙允许专用网络、使用启动窗口最新的 LAN URL，并避免访客 Wi-Fi 的客户端隔离。
- **Player 只能看不能改**：GM 需要授予 OWNER；若战斗已开始，还必须轮到该 Actor。
- **为什么回合刚开始看不到“起点”幻影**：这是设计行为。起点已记录，但真人 Token 还与起点完全重合；只有 Token 离开后才显示幻影，避免两个相同 Token 叠在一起。
- **起点幻影能不能点击/攻击/选中**：不能。它只是 Renderer 视觉层，不是 Scene Token，也不进入碰撞、范围、伤害、治疗或选择系统。
- **刷新后起点幻影不见了**：确认仍是同一个战斗回合，且当前 Token 的权威位置确实已离开起点。v2.1.5 的起点存在共享 Combat State，正常重连会自动恢复。
- **Token 看起来仍然瞬移**：确认使用的是 v2.1.4 或更新版本，并检查浏览器/系统是否启用了“减少动态效果（prefers-reduced-motion）”；该无障碍设置会按设计关闭平滑插值，但路线和终点预览仍可使用。
- **移动时血条暂时消失**：这是 v2.1.4 起的设计。血条是独立覆盖层，为避免它比 Token 提前跳到服务器终点，动画期间暂时隐藏，结束后自动恢复。
- **高度在哪里**：v2.1.4 起已把高度移到 Token 上方名称的左侧；血条仍在 Token 下方。右键 Token 仍可编辑高度。
- **消息按发送后没有出现**：先看顶部状态。v2.1.3 起会在发送请求被 WebSocket 接受后清空输入框，并等待服务器快照；若提示连接不可用，重新连接后再发送。若服务器确认同步完成仍看不到消息，应检查是否打开了同一个 World。
- **Token 绑定范围无法预览/应用**：v2.1.3 已修复。确认绑定对象仍显示正确 Token；角色移动后重新预览，再应用破坏。
- **找不到“检查地物”按钮**：v2.1.3 已将它合并进“选择”。保持“选择”模式，直接点击建筑、城墙、城门等可检查 Feature 即可。
- **操作后又恢复原状**：等待顶部状态显示联机同步完成；不要同时在多个设备修改同一份 World。发生冲突时客户端会重新加载服务器版本。
- **启动报告存档损坏**：不要继续覆盖文件；在 `map/backups/` 找最近备份，恢复后再启动。
- **浏览器没有自动打开**：复制启动窗口的 Local URL 到系统默认浏览器。服务关闭可直接关闭启动窗口，或按 `Ctrl+C`。
