> 将本文件交给 Codex 后，请让它直接执行全部任务，不要只重新生成计划。实施过程中应保留现有用户修改、先同步代码并检测实际实现，再修改、测试、合并和发布。

## 一、目标与交付物

基于远端最新 `main`（当前为 v2.2.0）完成以下功能，合并为 v2.2.1，并按仓库既有流程生成正式 Windows Local/LAN Release。

最终必须交付：

- 合并到 `main` 的 v2.2.1 release commit；
- `v2.2.1` Tag 与正式 GitHub Release；
- `RPGmap-v2.2.1.zip`；
- `RPGmap-v2.2.1.zip.sha256`；
- 更新后的 README、CHANGELOG、操作指南和必要开发文档；
- 全量测试、构建、包校验和 Windows smoke 结果。

## 二、同步代码与保护本地修改

1. 开始前检查 `git status`、当前分支、远端 `main` 和现有 Tag。
2. 如果工作区存在未提交修改，先创建独立备份分支并提交，禁止直接覆盖、丢弃或 `reset --hard`。
3. 执行 `git fetch --prune --tags origin`，使用 fast-forward 方式同步最新 `origin/main`。
4. 从同步后的 `main` 创建 `codex/v2.2.1` 功能分支。
5. 不得整体合并旧 v2.2.0 原型；应以远端正式 v2.2.0 架构为基线，只移植仍有价值且兼容的实现。
6. 同步后先运行全量测试和构建，记录基线结果，再开始修改。

## 三、功能任务

### 1. 移动修复与 WASD

- 保留目前已经可用的 Token 拖动移动，不重写正常主链路。
- 修复不可移动 Token 的预览/提交不一致：死亡、昏迷、定身等状态下，当前可能先提示“路线已就绪”，确认时才误报“路径不可通行”。
- 路线预览和正式提交必须调用同一套移动能力、碰撞、权限和回合校验，并返回结构化失败原因及准确中文提示。
- 简单生命模式下，`0/0` 代表生命值尚未配置，不应自动派生死亡或昏迷；只有 `max > 0 && current <= 0` 才判定生命耗尽。
- 增加 WASD：移动当前主选 Token，每次移动一个现有网格吸附步长。
- WASD 必须复用拖动移动的碰撞、状态、权限、回合、服务端权威和迷雾探索逻辑，不能直接修改坐标。
- 输入框、文本域、下拉框、角色卡或带 Ctrl/Alt/Meta 的组合键获得焦点时，不得触发地图移动。
- 联机环境中，Token 移动与由移动产生的视野/迷雾更新必须有序或原子提交，避免 World revision 冲突。

### 2. 角色“侦测”数据与界面

为无限跑团 Actor 形态增加：

```js
form.detection = {
  preciseRangeMeters,
  vagueRangeMeters,
  senses: {
    trueSight,
    xrayVision,
    spiritSight,
    lowLightVision,
    darkvision
  }
}
```

- 在角色卡“概览”中加入独立的“侦测”区域。
- 显示并允许编辑精确范围、模糊范围，以及五个感知勾选项：真实视觉、透视、灵视、昏暗视觉、黑暗视觉。
- 导入值属于形态基础数据；运行时勾选/覆盖应走 Actor Runtime。独立怪物 Token 的修改写入该 Token 的 `actorDelta`，不能影响同模板的其他实例。
- 重新导入形态时更新基础值，但不得无提示清空已有运行时状态。

侦测显示规则：

- 精确范围内：显示目标完整 Token、名称和位置；
- 精确范围外、模糊范围内：只显示匿名轮廓/方位提示，不泄露名称和完整资料，并按半揭示处理迷雾；
- 模糊范围外：按现有不可见规则处理。

光照规则：

- 正常光照：按精确/模糊距离正常工作；
- 昏暗环境：没有昏暗视觉时，精确目标降为模糊；具有昏暗视觉时按正常光照处理；
- 黑暗环境：只有具有黑暗视觉的角色继续按正常精度工作；
- v2.2.1 中真实视觉、透视、灵视只完成导入、保存、实例覆盖、勾选和展示，不实现穿墙或特殊目标识别，保留为后续机械扩展标志。

### 3. Excel 读取规则

读取工作表“具体数值表”中 `S:AD`、第 `60:68` 行的侦测数据：

- `X62`：精确范围，单位米；
- `X63`：模糊范围，单位米；
- 真实视觉、透视、灵视、昏暗视觉、黑暗视觉应按规范化后的中文标签定位，不能只依赖单一固定列。

解析要求：

- 支持数字、数字字符串、带 `m/米` 后缀和公式缓存值；
- 空值按 `0/未启用` 处理；
- 标签比较前去除空格、换行、全角符号差异；
- 识别常见勾选表达，例如布尔值、勾号、是、启用、1；
- 对工作表缺失、标签重复、格式错误、无法解析值产生明确警告；
- 如果模糊范围小于精确范围，保留导入警告，运行时将模糊范围提高到精确范围，但不得静默修改原始诊断数据。

### 4. Excel 真实读取测试

用户会额外提供一份真实 Excel。该文件只用于本地验收，不得提交仓库、复制进发布包或留下临时解压内容。

新增可复用命令，例如：

```text
npm run test:xlsx -- --file "角色卡.xlsx"
```

该命令必须调用正式 XLSX importer，而不是另写一套测试解析器，并输出：

- 实际识别到的工作表名称；
- `X62/X63` 的原始值、单元格地址和归一化米数；
- 五种视觉能力的原始标签、地址、原始值和布尔结果；
- 已有身份、属性、资源等导入摘要；
- 所有缺失、重复、格式和范围冲突警告。

真实文件验收流程：

1. 人工打开 Excel，独立记录 `X62/X63` 和五种视觉的期望结果；
2. 运行正式读取命令逐项对照；
3. 任何关键字段不一致时命令退出非零；
4. 测试完成后逐项清理临时文件，不保留用户角色资料。

仓库自动化测试不保存真实 Excel，应使用合成 sheet/cell 数据覆盖：

- 标准 `S60:AD68` 布局；
- 精确和模糊范围；
- 五种视觉的启用、未启用和不同文本形式；
- 空单元格、字符串数字、单位后缀、公式缓存值；
- 标签空格、换行和全角符号；
- 模糊范围小于精确范围；
- 工作表缺失或名称轻微差异。

正式验收必须同时通过合成自动化测试和用户真实 Excel 本地读取测试。

### 5. 非公开、隐身与 GM 检查

- 非公开使用 Token 实例属性 `visibility: "gm"`，不能只绑定 User 或 Actor。
- 隐身状态必须同时支持 Actor scope 和 Token scope。
- 玩家 Audience 投影继续完全移除无权查看的非公开/隐身 Token。
- GM 始终能看到、选中和编辑这些 Token，并以半透明方式显示。
- GM 视图增加“GM 专属”“隐身”角标；两个条件同时存在时显示两个角标。
- GM 的角色卡、状态管理、当前 Token 检查和批量管理必须读取原始 Token，不能因为玩家投影而失去目标。

### 6. 指示物库与怪物实例管理

- PC 主要由角色库管理；NPC、召唤物及怪物模板集中到指示物库。
- 同一 Actor 模板在指示物库中只显示一个紧凑条目。
- 怪物采用“一个模板 Actor + 多个独立 Token/actorDelta”：
  - 模板属性修改可传播；
  - 每只怪物的名称、HP、伤势、状态、感知覆盖独立保存；
  - 修改一只怪物不得污染同模板其他实例。
- 放置怪物时默认命名为 `模板名1`、`模板名2`……，使用当前场景中最小可用正整数，并允许自定义改名。
- PC/角色放置时提供“共享角色数据”选项，默认共享；取消时创建独立 Token 实例。
- 点击怪物模板条目打开侧边抽屉，列出该模板在当前场景中的全部 Token。
- 抽屉中优先显示并直接编辑每只 Token 的名称、当前 HP、最大 HP和状态。
- 支持多选、全选、批量添加状态和批量移除状态；批量修改应使用一次原子 World operation 提交。
- “聊天、角色库、当前、指示物”四个侧边栏标签必须在桌面宽度下单行等宽显示，不能换行。

### 7. 地图界面整理

- 删除顶部“图层”按钮、对应面板以及 Runtime 面板注册。
- 地图网格始终开启，不再提供显隐开关。
- 旧 World 中已有的网格关闭设置允许兼容读取，但 Runtime 必须忽略并强制显示网格，避免破坏旧数据加载。
- 选中角色的大图和摘要固定在地图右下角，避开顶部工具栏、右侧栏、移动确认栏和移动端安全区。

## 四、测试与验收标准

### 移动

- 健康角色拖动和 WASD 均能移动；
- 死亡、昏迷、定身角色在预览阶段即被正确拒绝；
- 空白 `0/0` 角色不会自动死亡；
- 碰撞、权限、回合限制和联机服务端校验无法被 WASD 绕过；
- 连续移动和迷雾更新不产生 revision 冲突。

### 侦测与可见性

- 精确、模糊范围边界正确；
- 正常、昏暗、黑暗环境符合规定；
- 五种视觉能够导入、保存、勾选并在独立 Token 中覆盖；
- 玩家无法看到无权 Token；GM 可半透明查看、选择和管理，并看到正确角标。

### 怪物管理与 UI

- 同模板怪物的 HP、状态、名称互不污染；
- 模板修改不覆盖实例运行状态；
- 默认编号、改名、批量状态操作正确；
- 图层入口消失、网格始终显示；
- 四个侧栏标签单行显示；
- 大图位于右下角且不遮挡主要操作。
