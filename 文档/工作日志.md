# RPGmap 工作日志

本文件记录应用版本级别的重要开发过程。精炼摘要见根目录 `CHANGELOG.md`；具体提交历史通过 Git 查看。

当前开发版本：**1.4.2 Candidate**  
当前稳定 `main`：**1.4.0**

## 版本规则

RPGmap 使用 `MAJOR.MINOR.PATCH`：

- `PATCH`：Bug 修复、权限增强、小型架构整理、兼容性修正，例如 `1.4.2`。
- `MINOR`：新增较完整功能或子系统，例如未来完整 Multi-Map / SceneSystem。
- `MAJOR`：明显不兼容的存档、服务器协议、World 数据或核心架构变化。

## 1.4.2 Candidate — 2026-08-22

V1.4.2 继续继承 V1.4.1 Candidate 的 Player Identity、Actor Ownership 与 Combat Turn Lock，同时重新整理发布包和持久数据边界。目标是避免 `/map` 同时承担“地图资源”和“整个跑团数据根目录”两种含义。

### 一、确立 app / world / maps 三层结构

最终发布包约定：

```text
RPGmap-v1.4.2/
├─ app/                 程序前端
├─ world/               当前 World / Campaign 的持久运行状态
├─ maps/                真正的 Map / Scene 资源库
├─ docs/
├─ server.mjs
├─ access-control.mjs
├─ portable-storage.mjs
├─ internet-launcher.mjs
└─ start scripts
```

语义固定为：

- `app/`：程序是什么。
- `maps/`：地图 / Scene 本身是什么。
- `world/`：这一场游戏里发生了什么。

### 二、World 数据根目录

V1.4.2 新的持久数据：

```text
world/state.json
world/users.json
world/uploads/
world/backups/
```

其中：

- `state.json`：World Snapshot、revision、Actor / Token、Combat、Chat、Scene 实例状态等。
- `users.json`：Persistent Player User、默认 Actor、Ownership、Browser Token Hash、Player Key Hash。
- `uploads/`：当前 World 上传资源。
- `backups/`：本地备份。

RPGmap 默认不将这些数据写入 AppData、用户主目录或其他隐藏目录。

### 三、maps/ 正式留给真正的地图系统

新增 `maps/` 根目录，并明确它不用于 User / World 持久化。

后续一个地图包可以包含：

- manifest / metadata；
- 背景层；
- 建筑 / 墙体；
- 可破坏对象；
- Collision / Navigation；
- 环境特效；
- Damage / Destroyed Variant；
- 地图专属 Assets。

数据边界示例：

```text
maps/lanzhou/buildings/house-17
    = 房屋模板、碰撞、破坏阶段、资源

world/state.json
    = 本次跑团中 house-17 当前 HP、燃烧、坍塌状态
```

V1.4.2 只建立边界，不在 Patch 版本中强行加入完整 Multi-Map / Destructible Building System。

### 四、兼容迁移

`portable-storage.mjs` 现在兼容两代旧目录。

V1.4.1 Candidate：

```text
map/world.json  -> world/state.json
map/users.json  -> world/users.json
map/uploads/    -> world/uploads/
map/backups/    -> world/backups/
```

更旧结构：

```text
data/worlds/default/world.json  -> world/state.json
data/worlds/default/access.json -> world/users.json
```

迁移规则：

- 只有新文件不存在时才迁移。
- 优先读取 V1.4.1 Candidate 的 `map/`。
- 如果不存在再读取更老 `data/`。
- 旧文件不自动删除。
- 已存在的新 `world/` 数据永远优先。

### 五、启动脚本

Windows / Unix 启动脚本统一使用：

```text
RPGMAP_PUBLIC_DIR=<package>/app
RPGMAP_WORLD_DIR=<package>/world
RPGMAP_MAPS_DIR=<package>/maps
```

本机、LAN、公网 Quick Tunnel 使用完全相同的 World / Maps 数据目录。

## 1.4.1 Candidate — 2026-08-21

V1.4.1 Candidate 在 Multiplayer V1 上建立了完整权限层。

### Player Identity

- Player 首次 Join Code 加入时进入 pending。
- GM 批准后创建 Persistent User。
- GM 可预创建 User。
- Player Key 用于 Quick Tunnel 新域名恢复身份。
- Server 只保存凭证哈希。

### Actor Ownership

- NONE / OBSERVER / OWNER。
- 一个 User 可有默认 Actor 和多个 OWNER / OBSERVER。
- GM 隐式拥有全部 Actor。
- Player 只能修改 OWNER Actor。

### Combat Turn Lock

- Initiative、Combatant、排序、Round、Turn、开始 / 结束由 GM 管理。
- Combat active 时 Player 只能修改当前 Turn 对应的 OWNER Actor。
- Client Preflight + Server Validation 双层执行。

### 初版 Portable Storage

曾采用：

```text
app/
map/world.json
map/users.json
```

该方案因为 `/map` 同时承担跑团数据和地图资源语义，在 V1.4.2 中被重新拆分为 `world/ + maps/`。
