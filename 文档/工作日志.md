# RPGmap 工作日志

本文件记录应用版本级别的重要开发过程。精炼摘要见根目录 `CHANGELOG.md`；具体提交历史通过 Git 查看。

当前开发版本：**1.4.3 Candidate**  
当前稳定 `main`：**1.4.0**

## 版本规则

RPGmap 使用 `MAJOR.MINOR.PATCH`：

- `PATCH`：Bug 修复、权限增强、Launcher、兼容性和小型架构整理，例如 `1.4.3`。
- `MINOR`：新增完整功能或子系统，例如未来真正的 Multi-Map / SceneSystem。
- `MAJOR`：明显不兼容的存档、服务器协议、World 数据或核心架构变化。

## 1.4.3 Candidate — 2026-08-22

V1.4.3 的目标是把 V1.4.2 已经整理好的 `app / world / maps` 结构继续向“真正软件产品”的使用方式推进：不再让 GM 面对多个 BAT、多个 CMD 窗口和分散的连接信息，而是提供一个统一 Launcher / GM Control Center，并最终把 Windows 根入口收口成原生 EXE。

### 一、Native Windows Launcher

Windows 发布包唯一启动入口改为：

```text
RPGmap Launcher.exe
```

实现方式不是 Electron，而是新增：

```text
deployment/launcher/windows-launcher.c
```

CI 使用 MinGW 编译为 Windows x64 PE。

Native EXE 只负责：

1. 找到自身所在的 RPGmap 包根目录；
2. 检查 `launcher/launcher.mjs`；
3. 优先查找 `tools/node/node.exe`；
4. 其次查找根目录 `node.exe`；
5. 最后查找系统 PATH 中的 Node；
6. 启动 Launcher Node 后台；
7. 自身退出，不占用额外桌面窗口。

当前 Node.js 仍是 RPGmap 的运行要求：

```text
^20.19.0 || >=22.12.0
```

如果没有 Node，Native EXE 通过 Windows MessageBox 提示，并可打开 Node.js 官网。

这样既得到正常 `.exe` 软件入口，又不引入 Electron 带来的巨大运行时和包体积。

### 二、Launcher 统一联机信息

Launcher 后台进程通过 Node.js 启动，并打开本机控制页：

```text
http://127.0.0.1:29999
```

一个界面集中显示：

- Server 状态；
- 本机 URL；
- LAN URL；
- Cloudflare Public URL；
- Join Code；
- GM Secret；
- Player Invite；
- World / Maps 路径；
- Server / Tunnel 日志。

玩家邀请文本只包含：

```text
地址 + 房间号
```

GM Secret 被单独放在 GM 安全区，默认隐藏。

### 三、本机 / LAN / Internet 生命周期统一

Launcher 负责：

```text
Local / LAN
Launcher -> Generate Credentials -> Server

Internet
Launcher -> cloudflared -> Public URL -> Server
```

Internet 模式继续强制 Cloudflare HTTP/2 over TCP。

Windows 未检测到 cloudflared 时，由 Launcher 下载官方 Windows amd64 可执行文件到 RPGmap 包内 `tools/`，不再要求用户单独运行 setup BAT。

### 四、Launcher Admin Console

Launcher 增加 Users / Actor Ownership 管理：

- pending Player；
- 批准首次加入；
- 预创建 User；
- 默认 Actor；
- NONE / OBSERVER / OWNER；
- 重发 Player Key；
- 删除 User；
- 在线状态；
- Actor catalog。

关键设计决定：**Launcher 不直接写 `world/users.json`。**

Launcher 使用隐藏的本机 GM WebSocket Session，复用 Multiplayer Server 已经存在的：

```text
access.request
access.user.approve
access.user.create
access.user.update
access.user.reset-claim
access.user.delete
```

因此：

```text
Launcher Admin
      ↓
GM WebSocket Session
      ↓
Multiplayer Server
      ↓
Access / Ownership Logic
      ↓
world/users.json
```

这避免了 Launcher 直接改文件后 Server 内存状态不同步的问题。

### 五、Launcher 安全边界

Launcher HTTP Server 只监听：

```text
127.0.0.1:29999
```

Cloudflare Quick Tunnel 仍然只指向 RPGmap Game Server：

```text
127.0.0.1:30000
```

因此公网玩家不会经过 Launcher Port。

Launcher 本机 API 还使用随机 Browser Token，浏览器页面通过 Header 调用管理 API。

### 六、预留 World / Scene / Backup 管理入口

Launcher 首页新增“未来管理中心”，预留三个模块卡片，当前按钮保持禁用：

- 创建 / 复制 / 重命名；
- 归档；

- World schema / migration 检查。

#### Scene Manager

未来负责：

- Map Registry；
- MapPackage 导入；
- 多地图 / Scene 列表；
- Scene 排序 / 切换；
- Scene reset / clone。

#### Backup Center

未来负责：

- 一键 World Snapshot；

- 恢复；

这些只是结构预留，当前不会制造“看起来能点但功能不完整”的假入口。

`docs/FUTURE-ROADMAP.md` 也进入发布包，便于从成品直接查看未来计划。

### 九、自动化验证

新增真实 Server + LauncherAdminClient 测试：

1. Launcher GM Session 连接；
2. GM 初始化含 Actor 的 World；
3. Launcher 预创建 User；
4. 默认 Actor + OWNER；
5. 修改 User；
6. 重发 Player Key；
7. 删除 User；
8. Player 首次进入 pending；
9. Launcher 批准 Player。

CI 额外检查：

- `deployment/launcher/**/*.js / .mjs` syntax；
- 使用 MinGW 编译 `RPGmap Launcher.exe`；
- 验证 EXE 为 Windows x64 PE32+；
- 最终 ZIP 根目录 BAT 数量必须为 0；
- 根目录 EXE 数量必须为 1；
- 必须存在 `launcher/` 与 `server/`；
- `VERSION.json.launcherMode = native-exe-web-admin-console`；
- 必须包含 `docs/FUTURE-ROADMAP.md`。

## 1.4.2 Candidate — 2026-08-22

V1.4.2 将发布包和持久数据边界确立为：

```text
app/     程序前端
world/   当前 World / Campaign 运行状态
maps/    真正 Map / Scene 资源库
```

World 数据：

```text
world/state.json
world/users.json
world/uploads/
world/backups/
```

`maps/` 留给地图 manifest、背景、建筑 / 墙体、可破坏对象、Collision / Navigation、环境特效和 Damage / Destroyed Variant。

并兼容迁移：

```text
map/world.json  -> world/state.json
map/users.json  -> world/users.json

data/worlds/default/world.json  -> world/state.json
data/worlds/default/access.json -> world/users.json
```

该结构全部被 V1.4.3 继承。
