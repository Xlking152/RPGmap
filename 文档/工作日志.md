# RPGmap 工作日志

本文件记录应用版本级别的重要开发过程。精炼摘要见根目录 `CHANGELOG.md`；具体提交历史通过 Git 查看。

当前开发版本：**1.4.3 Candidate**  
当前稳定 `main`：**1.4.0**

## 版本规则

RPGmap 使用 `MAJOR.MINOR.PATCH`：

- `PATCH`：Bug 修复、权限增强、Launcher、兼容性和小型架构整理，例如 `1.4.3`。
- `MINOR`：新增完整功能或子系统，例如未来真正的 Multi-Map / SceneSystem。
- `MAJOR`：明显不兼容的存档、服务器协议、World 数据或核心架构变化。

## 1.4.3 Candidate — 2026-08-22

V1.4.3 的核心目标是把 V1.4.2 已整理好的 `app / world / maps` 结构继续向“真正可用的软件入口”推进：GM 不再面对多个 BAT、多个连接窗口和分散的 User 管理，而是只通过一个启动入口进入统一 Web Launcher / GM Control Center。

### 一、最终启动方案：单 BAT + Web Launcher

最终决定：Windows 发布包根目录只保留：

```text
启动 RPGmap.bat
```

BAT 不承担 Server / User / Tunnel 业务逻辑，只负责：

1. 找到 RPGmap 根目录；
2. 查找 Node.js；
3. 启动 `launcher/launcher.mjs`；
4. 将 runtime 输出写入 `launcher-startup.log`；
5. 由 Web Launcher 自动打开浏览器控制中心。

Node 查找顺序：

```text
tools/node/node.exe
    ↓
根目录 node.exe
    ↓
系统 PATH node.exe
```

当前 Node.js 要求：

```text
^20.19.0 || >=22.12.0
```

### 二、Native EXE 尝试与撤回

开发过程中曾新增轻量 Windows C 启动壳并由 MinGW 编译成：

```text
RPGmap Launcher.exe
```

该方案曾实现：

- Node 查找；
- 启动 `launcher.mjs`；
- Windows MessageBox 错误提示；
- startup log；
- GitHub Actions Windows Smoke Test。

自动化环境可以正常启动，但真实 Windows 实机出现过：

- EXE 双击后没有界面；
- 后台 Node 立即退出但反馈不直观；
- 端口冲突时出现 `exit code 0`；
- 用户需要额外区分 EXE 壳与实际 Web Launcher。

因此最终决定：**撤回 Native EXE，不进入 V1.4.3 发布包。**

原因不是 EXE 技术上无法实现，而是当前阶段增加了不必要的启动层和诊断成本。RPGmap 当前更重视稳定、透明、可维护。

原生 `windows-launcher.c` 与 MinGW 打包步骤已经移除。

### 三、Launcher 动态本机端口

早期固定：

```text
127.0.0.1:29999
```

实机发现端口可能被其他程序占用。

不采用“按端口强制 taskkill 未知进程”的方式，因为占用端口的程序可能不是 RPGmap。

最终策略：

```text
29999
  ↓ occupied
29998
  ↓
29997
  ↓
29996
  ↓
29995
  ↓
Windows 自动分配空闲 loopback 端口
```

Launcher 会读取最终端口并自动打开浏览器，用户不需要知道或手动修改端口。

Game Server 仍默认：

```text
0.0.0.0:30000
```

### 四、Launcher 统一联机信息

网页 Launcher 集中显示：

- Server 状态；
- Local URL；
- LAN URL；
- Cloudflare Public URL；
- Join Code；
- GM Secret；
- Player Invite；
- World / Maps 路径；
- Server / Tunnel 日志。

玩家邀请只包含：

```text
地址 + 房间号
```

GM Secret 单独放在安全区，默认隐藏。

### 五、本机 / LAN / Internet 生命周期统一

Launcher 负责：

```text
Local / LAN
Launcher -> Generate Credentials -> Server

Internet
Launcher -> cloudflared -> Public URL -> Server
```

Internet 模式继续使用 Cloudflare HTTP/2 over TCP。

Windows 缺少 cloudflared 时，由 Launcher 自动下载官方 Windows amd64 可执行文件到：

```text
tools/cloudflared.exe
```

### 六、Launcher Admin Console

Launcher 增加 Users / Actor Ownership 管理：

- pending Player；
- approve；
- 预创建 User；
- Default Actor；
- NONE / OBSERVER / OWNER；
- Player Key rotation；
- delete User；
- online status；
- Actor catalog。

关键设计：**Launcher 不直接写 `world/users.json`。**

数据流：

```text
Launcher Admin
      ↓
Hidden GM WebSocket Session
      ↓
Multiplayer Server
      ↓
Access / Ownership Logic
      ↓
world/users.json
```

因此 Launcher 和游戏内 Users 面板不会形成两套权限状态。

### 七、Launcher 安全边界

Launcher 仅绑定：

```text
127.0.0.1:<dynamic>
```

Cloudflare Quick Tunnel 仅转发：

```text
127.0.0.1:30000
```

因此远程 Player 不会经过 Launcher 管理端口。

Launcher 本机 API 另有随机 Browser Token。

### 八、未来管理中心预留

Launcher 首页已预留三个禁用模块：

#### World Manager

未来负责 World 选择、创建、复制、重命名、归档、删除、启动和 schema / migration。

#### Scene Manager

未来负责 Map Registry、MapPackage、Scene 列表、排序、切换、reset / clone。

#### Backup Center

未来负责 Snapshot、自动备份、恢复、World import/export 和升级前备份。

### 九、发布包结构

最终 V1.4.3 Candidate：

```text
RPGmap-v1.4.3/
├─ 启动 RPGmap.bat
├─ 操作说明.md
├─ app/
├─ launcher/
├─ server/
├─ world/
├─ maps/
├─ tools/
├─ docs/
└─ VERSION.json
```

打包约束：

- 根目录 BAT 数量 = 1；
- 根目录 EXE 数量 = 0；
- 不存在旧 `public/` / `data/` / `map/`；
- 不把项目 `README.md` 放进发布 ZIP；
- 包内根文档为 `操作说明.md`；
- `VERSION.json.launcherMode = single-bat-web-admin-console`；
- `VERSION.json.launcherPortMode = dynamic-loopback`。

### 十、自动化验证

保留：

- npm tests；
- JavaScript syntax；
- Vite production build；
- LauncherAdminClient + 真实 Server 联调；
- ZIP 解压后二次结构检查。

Windows Smoke Test 改为直接测试最终：

```text
启动 RPGmap.bat
```

并且 CI 会故意占用 `29999`，要求 Launcher 自动切换到 `29998` 并成功提供网页控制中心。
