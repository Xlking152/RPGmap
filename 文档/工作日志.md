# RPGmap 工作日志

当前开发版本：**1.4.3 Candidate**  
当前稳定 `main`：**1.4.0**

## 1.4.3 Candidate — 2026-08-22

### 最终启动架构

经过 Native EXE 和多层隐藏进程方案实机测试后，V1.4.3 最终收口为：

```text
RPGmap.bat
    ↓
PowerShell Runtime
    ↓
Node.js launcher/launcher.mjs
    ↓
Web Launcher / GM Control Center
```

根目录唯一入口为 `RPGmap.bat`，EXE 数量固定为 0。

### PowerShell Runtime

新增：

```text
deployment/launcher/rpgmap-runtime.ps1
```

职责只包括：

- 查找 Node.js；
- 作为 Launcher Node 进程宿主；
- 保持一个稳定、可最小化的信息窗口；
- 将根 `maps/` 作为 Runtime Map Library 挂载到 `app/maps`；
- 显示 Launcher / Server / Tunnel stdout；
- Server READY 后显示 Local / LAN / Public URL、Join Code、GM Secret、World / Maps、Build；
- 显示后续 Server / Tunnel 日志。

PowerShell 不承担 User / Ownership 等业务逻辑，真正的 GM 操作仍全部位于 Web Launcher。

Node 查找顺序：

```text
tools/node/node.exe
→ 根目录 node.exe
→ 系统 PATH node.exe
```

### 为什么撤回 EXE

曾实现 `RPGmap Launcher.exe` 和 `windows-launcher.c`，并通过自动化 Windows Smoke Test。但真实设备出现双击无界面、后台错误反馈不直观、端口冲突诊断复杂等问题。

因此：

- Native EXE 方案撤回；
- `windows-launcher.c` 删除；
- MinGW 构建删除；
- 当前优先 BAT + PowerShell + Web Launcher。

### 动态 Launcher 端口

Launcher 只绑定 loopback：

```text
29999 → 29998 → 29997 → 29996 → 29995 → Windows 自动空闲端口
```

不根据端口强杀未知进程。浏览器自动打开最终地址。

### External Runtime MapPackage 修正

实机检查 V1.4.3 Candidate 包时发现：虽然发布结构已经有根 `maps/`，但默认兰州地图仍由：

```text
src/maps/lanzhou.js
src/assets/generated/*.webp
```

在 Vite build 时直接打进 `app/`，因此包内 `maps/` 实际只有 README。这与已经确定的 `app / maps / world` 语义不一致。

本轮改为：

```text
maps/
├─ index.json
└─ northern-song-lanzhou-1104/
   ├─ map.json
   ├─ README.txt
   └─ assets/*.webp
```

具体实现：

- 新增 `scripts/export-maps.mjs`；
- 构建时把源码地图导出为纯 JSON Runtime MapPackage；
- 地图 WebP 从 `src/assets/generated/` 复制到对应 MapPackage `assets/`；
- 新增 `src/maps/loader.js`；
- Production Client 从 `/maps/index.json` / `map.json` 读取地图；
- Loader 在内存中为纯 JSON MapPackage 补 `createSvg()` compatibility adapter，Engine 接口无需大改；
- Vite dev 模式在外部地图不存在时回退到源码 MapPackage；
- `src/main.js` 删除所有地图 WebP 和 `lanzhou.js` 静态 import；
- Windows Runtime 创建 `app/maps -> ../maps` Junction；
- Game Server 继续走原有静态服务，但实际数据只保存在根 `maps/` 一份；
- CI 检查 `maps/index.json`、默认 `map.json` 和地图 assets；
- CI 检查兰州特定 SVG markup 不再存在于 production `app/` bundle；
- Windows Smoke Test 验证 Junction 后实际访问 `/maps/index.json`。

这一步把 V1.4.2 仅完成的“目录边界”真正落成了 Runtime Map Library，为 Scene Manager / 多地图切换提供了真实基础。

### World 空目录说明

`world/` 与 `maps/` 的空目录语义不同：

- `maps/` 是程序运行所需地图资源，新包必须包含真实 MapPackage；
- `world/` 是某场 Campaign 的可变状态，新包不应该预置一份假的 `state.json/users.json`。

因此新的干净包中 `world/` 初始只有 README、`uploads/`、`backups/` 是正常的；实际 `state.json/users.json` 在首次持久化或旧数据迁移后出现。

### Future Manager Slots

已预留：

- World Manager；
- Scene Manager；
- Backup Center。

其中 `maps/index.json` 已经成为 Scene Manager 未来 Map Registry 的基础，不再需要从零建立外置地图机制。
